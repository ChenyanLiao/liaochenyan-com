MolloM ユーザーガイド

デスクトップでのプロジェクト準備から、スマートフォンでの進捗・結果の確認まで。MolloM の操作を章ごとに解説します。

初回はリガンドを一つだけ使います。公開サンプルを開いて保存し、ポケットの画面で受容体、参照リガンド、探索ボックスを探してください。Vina で試走し、得点とポーズを開けたら、自分の分子ライブラリに切り替えます。すでに軌跡がある場合は軌跡解析から始められます。

デスクトップの手順は開発版 0.301.0 で確認しました。図は以前の版のものです。設定で使用中の版を確認し、ダウンロードページと照合してください。ご自身の AI クライアントを使う場合は接続手順を読み、エージェント向けガイド（Markdown）を渡してください。

1. はじめに

1.1 最初の計算を選ぶ

馴染みのある受容体と、いくつかのリガンドを使用してください。大規模なライブラリを実行する前に、import処理や準備作業、検索ボックスの操作、小規模な試行回数、結果の確認などをしっかり行ってください。

もし、すでにGROMACSシステムがある場合は、第10章から始めましょう。もし波動関数のファイルがある場合は、第12章から始めます。モバイルモニタリングや計画に関する内容については、第13章から始めます。ドッキングや分子動力学に関する内容は、別々のエントリポイントから始めます。どちらも、互いに前提条件ではありません。

1.2 操作する端末と計算先を選ぶ

デスクトップアプリケーションを使って、構造を準備し、プログラムを設定し、計算のスケジュールを立て、結果を確認します。実行ホストとしては、ローカルコンピュータやSSHサーバーを選択します。プログラムのパス、入力パス、およびそのホスト用のリソースを指定します。リモートパスはサーバー上で読み取りされ、ローカルパスはコンピュータ上で読み取りされます。

電話をモニタリングサービスに接続すると、ペアリングされたデバイスからの実行結果やログを確認できます。また、権限が有効な限り、保留中の計画を編集することもできます。デスクトップを離れる前に、コンピューティングホストが稼働状態を維持し、モニタリングサービスが継続して実行されているかを確認してください。

1.3 プロジェクトと設定を開く

「プロジェクトとテンプレート」の下で、新しいプロジェクトを作成するか、プロジェクト用のJSONファイルを開く、または公開されている例を読み込みます。設定で、使用するインターフェース言語を選択します。

例を実行する前に、入力ファイルを確認し、環境設定や検索範囲を確認してください。まずは小さなテストを実行してみてください。テンプレート内の値を出発点として、それらを自分の構造や研究問題に合わせて調整してください。

AI クライアントで最初のジョブを読む。 MolloM を起動しているパソコンで、MCP の stdio 接続に対応したクライアントを使います。クライアントから Node.js 18 以降を実行できることを確認してください。設定の「AI Agent · MCP」で読み取り専用を選び、権限を適用します。サービスの起動後に接続 JSON をコピーし、クライアントの既存の MCP 設定に追加します。生成されたパスを使い、接続ファイルの中身はチャットに貼り付けないでください。MolloM を開いたまま再接続し、ガイドを渡して「登録済みのドッキングを最大5件表示し、私が選んだ1件の状態を読んで」と頼みます。登録済みジョブがなければ空の一覧も正常です。書き込みが必要になったらジョブ制御を明示的に許可し、適用して再接続します。

2. 計算環境を整える

2.1 ローカルで実行する

  1. オープンコンピュータ環境およびソフトウェアセンターを選択し、ローカルで実行することを指定します。
  2. 再び環境を検出し、そこで見つかったプログラムを調査します。
  3. もし、ドッキングエンジンがすでにインストールされている場合は、実際に実行可能なファイルを選択します。例えば、Vinaバイナリのようなものです。
  4. 作業ディレクトリに書き込めることと、空き容量が十分にあることを確認します。

パスを確認した後、実際に小さな実験を行ってみましょう。ここでは、不足しているライブラリやモデルファイル、デバイスドライバーなどが最も多く見つかります。

2.2 SSH で接続する

  1. サーバーを追加する際は、そのサーバーのホスト名やSSH設定用のアラインダを使用します。
  2. ユーザー名とポートを入力し、システムの認証か鍵ファイルを選びます。通常のテキスト欄に秘密鍵を貼り付けないでください。
  3. サーバーの作業ディレクトリと、リモート実行可能ファイルのパスを指定してください。Python用のパスが必要な場合は、サーバー上のパスを使用してください。
  4. サーバーを保存した後、接続をテストし、環境を確認してください。

初回接続時はホストのフィンガープリントを確認します。不明なホストや認証エラーが出たら、まずシステムの SSH クライアントで接続を確認し、次に MolloM で再試行します。実行ファイルが起動しないときは、検出結果、権限、依存関係、実行環境を確認してください。

クラスターでは、そのタスクで選択できるスケジューラーを使い、パーティションまたはキュー、アカウント、制限時間と資源を指定します。

未知のホスト鍵の指紋は管理者に確認します。認証エラーならユーザー名と鍵を、SSH 接続後の環境エラーならリモートの Python を確認してください。Slurm の PENDING / Priority は順番待ち、QOSMinGRES はパーティションの最低資源要件を確認する合図です。

2.3 ソフトウェアをインストール・登録する

ソフトウェアセンターで、ローカルコンピュータまたはターゲットサーバーを選択し、そのソフトウェアのリストを更新します。バージョンをインストールする場合は、まずインストールおよび検証の計画を確認してください。これには、インストール先、ライセンス、依存関係などが含まれます。

既存のインストール環境がある場合は、そのバージョンを使用する前に、再度確認を行ってください。いくつかの項目には、オスプラングのインストール手順が記載されており、また、別途インストールしたプログラムを登録するための機能もあります。続ける前に、失敗した確認結果を必ず確認してください。ディレクトリが存在しているからといって、そのプログラムが正常に動作しているという証拠にはなりません。

3. プロジェクトを作成して構造を読み込む

3.1 後から見つけやすい名前を付ける

「プロジェクト」と「テンプレート」の下に、そのプロジェクトを作成してください。そのプロジェクト名は、そのプロジェクトの目的や内容を明確に表すものにしましょう。1つのプロジェクト内に複数の実行やスクリーニングラウンドが含まれていても問題ありません。小さな調整を行う際には、すべてのファイルをコピーする必要はありません。

重要な設定を変更した後で保存してください。プロジェクト設定に関する情報は、JSON形式でエクスポートしてください。また、第9章で紹介されているポータブルパッケージを使用して、入力データや結果もエクスポートできます。

3.2 受容体とリガンドを追加する

  1. 「Receptors」と「Ligands」の下で、PDBまたはPDBQTファイルから得られた受容体を追加してください。
  2. リガンドファイルを選択するか、あるフォルダを選ぶこともできます。また、サーバ上のファイルをブラウズすることもできます。
  3. 実際に使用する入力形式を選択してください：PDBQT、SDF/SD、MOL2、MOL、またはSMILESです。
  4. 入力値を再確認し、記録の数や、エンジンが対応可能な入力値、およびパーサーの問題点についても確認してください。

1つのSDFファイルには、複数の分子記録が含まれている可能性があるため、ファイルの数や記録の数は異なるかもしれません。問題のある記録を確認し、それらを修正するか、除外するか、または再び準備するかを決定してください。

3.3 データの由来を残す

元のファイルや追跡可能な分子識別子を保持しておきます。準備された作業状態は、共通の親元に接続されている必要があります。あるプロジェクトにおいて、構造や構像を比較する際には、受容体の名前を明確に記述する必要があります。

手動で編集したエンジン設定情報によって、元のファイルが破損することがないようにしてください。準備段階では、作業用のコピーを作成しておき、それを別途確認することができます。

4. 受容体とリガンドを準備する

4.1 受容体に残す成分を決める

構造の準備段階では、鎖を指定するか、またはその欄を空にして、すべての鎖を保持するようにします。通常の水分を除去するか、HETATMの補因子や金属を保持するかを決めます。機能性水分や金属イオン、補因子をポケットから除去する前に、構造や文献の情報を確認する必要があります。

不足しているか、不標準的な残基やプロトン化の処理について確認する必要があります。現在のワークフローでは、サポートしていない構造が報告されています。また、ターゲットpHでのループの欠如やプロトン化の処理は、別途行う必要があります。

4.2 リガンドの状態を準備する

最も大きな親構造を保持するかどうを選択し、 tautomericな状態を列挙し、各ソースレコードにおける状態の数を制限します。定義されていない立体化学は、デフォルトでは除外されます。その特定の入力がどのように処理されるかを知っている場合にのみ、この機能を有効にすることができます。

、3D座標がない入力データについては、まず3D座標を生成します。その後、電荷や立体化学、結合の状態を確認した上で、ドッキングを行います。

4.3 準備前後の変化を確認する

入力データを準備し、確認する。また、完了したものや問題のある記録を確認する。その後、準備用のディレクトリを開いて、そこにあるファイルを確認する。前後比較の際には、重原子数、形式電荷、断片、座標などをチェックする。

原因に応じて、正しくエラーを修正します。元のファイルを保持しつつ、新しい作業用のコピーを生成することで、変更点を追跡することができます。

5. 探索範囲を設定する

5.1 結合ポケットを見つける

3Dポケットビューでは、受容体を選択します。タンパク質、リガンド、表面の表示を切り替えることができます。回転させるにはドラッグする、ズームインするにはスクロールすることができます。必要に応じてビューの設定をリセットすることもできます。

もし、参照配体が利用可能であれば、その配体を使って、そのポケットの位置を特定します。その配体は、現在の受容体の座標系と一致している必要があります。もし座標が別の構造から得られた場合は、まず構造を合わせてください。

5.2 探索ボックスを確認する

中心座標と各辺の長さを XYZ で指定します。単位は Å（オングストローム）です。目的の領域とリガンドが入ること、無関係な空間を含みすぎないことを確認します。

各受容体がチェックされているかを個別に確認してください。プロジェクトを保存した後、試験結果を確認して、表示される内容が予定通りであるかを確認してください。

6. ドッキングエンジンと計算資源を設定する

6.1 エンジンを選んで確認する

プログラムの名前やカテゴリで検索し、そのドキュメントを参照して、このラウンドで使用するものを選び出します。その実行可能ファイルをターゲットホストに配置し、そのパスを確認してください。

構成された内蔵型の統合機能の方が好ましいです。カスタムなネイティブ統合機能を使用する場合は、小さなジョブでテストコマンドや入出力のパーサーを確認してみてください。

6.2 Vina のパラメーターと独立したシードを設定する

Vinaを選択し、その後、エクスイージビリティ、最大出力、エネルギー範囲、スコアリング関数などを設定します。エクスイージビリティが高いほど、より多くの計算コストがかかります。すべてを最大化するのではなく、試行錯誤を通じて最適な値を決めましょう。

独立なシードのリストを入力してください。1つのシードごとに1回ずつ検索を行います。入力された記録、有効な受容体、そしてシードの数が、実際に処理される作業の数を決定します。提出する前に、ラウンドの名前や数を確認してください。そうすることで、不要な受容体や重複したシードがないかを確認できます。

6.3 GNINA を使う

CNNをどのように利用するかを選択します。例えば、再評価や精緻化といった処理を行うか、またはモデルを選択するか、あるいはエンジンのデフォルト値をそのまま使用するかを決めます。GPUを使用しない場合は、CPUのみでの実行を選択します。

GPU を使う場合は、ソフトウェア、ドライバー、割り当てた資源を確認し、試行ログで実際の実行モードを確かめます。エネルギー、CNNscore、CNNaffinity は異なる指標で、並べ替えの向きも別です。絞り込み条件はそれぞれ設定してください。

6.4 同時実行数と CPU・GPU を割り当てる

タスクあたりの CPU 数は 1 件に使う資源、同時実行数は並行して走る件数です。その積を割り当てられた CPU 数に収め、OS と入出力の余裕を残します。

クラスター内でのキュー、時間、メモリ、GPUの要求状況を確認します。スケールアップ前の試験的なスループットやメモリの使用状況も確認します。より多くの同時処理が可能になると、ストレージやGPUメモリ、またはCPUの利用に制約が生じることがあります。

7. 少数で試し、バッチ計算を投入する

7.1 少数の入力で試す

試行およびタイミングのビューでは、リガンドのサンプルサイズを設定し、実際の試行を開始して、そのタスクを開きます。これにより、選択されたプログラムが実行され、選択されたホスト上でリソースが消費されます。

レビュー結果、結果の解析、およびログの確認が行われます。この推定値は、キューイング、準備、転送、またはエクスポートに関する情報ではありません。エンジン、モデル、エクスクルシブ性、またはホストを変更した後で、再度試行してみてください。

成功した一件のポーズを開き、失敗があれば一件の元ログを読みます。小さいリガンド一つでは大きい分子を多く含むライブラリの所要時間を見積もりにくいため、サンプル数と並列数を控え、キュー待ち、転送、書き出しの時間は別に見込んでください。

7.2 バッチを投入する

「タスクと進捗」ページで、準備した入力値、受容体、シード、リソースを確認しました。その後、新しいドッキング実行を実行してください。保存されたパラメータを開いて、実際の設定内容を確認してください。

実行が完了したり、失敗したり、処理中の作業がある場合もあります。問題を診断するために、実行状況や生のログ、または実行ファイルを開きます。新しいラウンドの設定を変更する際には、異なる条件での結果を別々に保持するように、新しい実行を開始してください。

7.3 一時停止・中止・復旧する

一時停止すると、新しいタスクを取り込まなくなります。すでに実行中のタスクは続きます。準備ができたら再開してください。残りを中止しても、書き込み済みの結果は残ります。

再試行が必要な失敗タスクだけを選び、成功した結果と試行履歴を残します。接続が切れたり状態が不明になったりしたら、再接続して元のジョブを更新し、二重投入はしないでください。独立した実行プロセスは画面を閉じても続けられますが、ホストのスリープ・停止やスケジューラーによる終了は別に対処します。

8. 結果を絞り込んで次のラウンドを作る

8.1 確認する候補を選ぶ

「Results」と「Screening」のセクションで、適切なものを選びます。名前のフィルターや、主要な基準値、または複数のメトリクスに基づくフィルターも適用します。最初のスコアだけを見て判断するのではなく、各項目の詳細や出典、メトリクスを確認することが重要です。

すべての条件は、同じポーズに適用されるべきです。関連性のない評価方法を平均化してはいけません。ドッキングの優先順位は、構造を調査するために決定されます。結合や活動に関する情報は、独立した証拠が必要です。

8.2 多様性を保ちながら重複を減らす

親子ごとに1人の代表者を置くか、RDKitのスカーフォールごとに代表者を限定することが適切です。もし、作業中の状態間の違いが比較の対象となっている場合は、早急にマージを行わないようにしてください。

フィルタリングされた件数を確認し、前倒しで処理するべき記録を選び出します。特に高いスコアや、矛盾したり不自然な記録がある場合は、入力内容や準備の歴史を最初に確認してください。

8.3 新しいラウンドを作る

オープンなセッションでは、完成した実行例を選び、条件を設定し、候補者を数えます。次のラウンドには名前を付け、そのラウンド用のエンジンを選びます。元の準備された入力をそのまま使用するか、このラウンドで最も適切なポーズを使用します。

出力ディレクトリを選択し、新しいラウンドを作成します。試行したり、提出する前に、その入力ファイルや設定内容を確認してください。ラウンドを作成したからといって、計算が始まるわけではありません。

練習では Vina affinity を ≤ −7.0 kcal/mol に設定し、まず通過件数を見ます。次のラウンドで GNINA に切り替える場合、利用するスコアと向きを選び直します。CNNscore は大きい方を優先します。投入前に受容体、リガンド数、エンジンを確認してください。

9. 結果の書き出しとプロジェクトの移行

9.1 共同作業者に渡す結果を書き出す

「Structures and Results Export」で、フィルタリングされた結果や、チェックされたレコードのみを選択します。必要なCSV、構造、受容体、設定、レポートをエクスポートします。複数のポーズを含めるために、該当するすべてのポーズを選択します。

報告書の中で、成功と失敗を確認してください。SDF形式への変換は、信頼性の高い原子マッピングがない場合に失敗する可能性があります。そのため、保持されているPDBQTファイルも確認してください。欠落した構造は、実際に提供された構造としてカウントしないでください。大規模なエクスポートでは、一時停止やチェックポイントの回復機能がサポートされています。

書き出しの途中で終了した場合は元のプロジェクトを開き、同じ書き出し記録と出力先を確認して再開します。競合があれば既存ファイルを先に調べてください。複数ポーズを含めた場合、行数、リガンド数、ファイル数は一致しないことがあります。

9.2 移行用のプロジェクトパッケージを作る

バンドルをプレビューしてください。必要に応じて、リモート入力や完成したタスクの結果も含めることができます。その後、ディレクトリを選択してエクスポートしてください。

別のコンピュータ上で、そのバンドル内のProject.htvs.jsonを選択し、エクスポートする前にプレビューを確認してください。その後、そのホスト用のソフトウェアや認証情報、パスなどを再設定してください。比較するために、過去の結果を保存しておきましょう。エクスポートされたプロジェクトから新しい実行例を作成してください。

9.3 ストレージを管理する

プロジェクトやストレージ内のディスクスペース、参照情報をスキャンしてください。キャッシュをクリアする前に、どのファイルが何の目的で使われているかを確認してください。予見機で表示される安全なキャッシュエントリのみをクリアしてください。

元の入力データや最終的な結果、準備に関する記録については、バックアッププランに従って処理してください。実際に必要となる入力データや設定内容が移動する必要がある場合は、プロジェクトをバンドルとして扱ってください。

10. 分子動力学の系を準備する

10.1 出発点を選ぶ

オープン分子動力学・GROMACS。標準のPDBファイルから構築するか、既存の座標、トポロジー、またはTPRを使用して構築します。

ドッキング結果を得るために、handoff SDFを生成し、原子の同一性と座標を確認した後、リガンドのパラメータ設定に進みます。まず、力場の種類、プロトン化、リガンドの電荷、そしてリガンドの組成を決定します。

10.2 リガンドを準備して複合体を組み立てる

「リガンドパラメータ」の項目で、GAFFまたはGAFF2を使用して設定されているACPYPE/AmberToolsを選択します。また、整数形式で表される電荷値と電荷の付与方法も指定してください。入力値や環境設定を確認した後、独立したタスクを準備し、レビューが完了した後にそのタスクを実行します。また、トポロジーの処理結果も確認してください。

現在、複合体は、乾燥状態のAMBERタンパク質と、1つのGAFF/GAFF2リガンドを含んでいます。GRO/TOPというタンパク質、ITPというリガンド、そして結合したGROを選択してください。その後、座標系や原子の順序、および力場の互換性を確認してください。単独の複合体を構築する前に、原子の対応関係や入力値を確認し、その後、システム設定に送り、溶媒やイオン、および検証処理を行ってください。

10.3 溶媒とイオンを追加する

  1. 標準的なプロテインのPDBデータ、または、トポロジーが定義されている乾燥システム、あるいは、既に完全な構造が与えられているシステムを選びましょう。
  2. 実行ホスト、システムディレクトリ、入力値を設定した後、構造やインストールされている力場の有無を確認してください。
  3. 適切な導入型力場と、それに合致する水モデルを選択してください。ボックスの形状、溶質と境界との距離、塩濃度、イオン、中和処理の設定も行ってください。
  4. レビュー端末とプロトネーション設定を確認し、ビルドプランを保存し、プレビューコマンドを実行します。
  5. 確認が取れ次第、ビルドを提出してください。マルチステージのワークフローに移行する前に、出力結果を確認してください。また、MDインポートを行う前にも、必ず出力結果を確認してください。

MD 系のボックス距離は nm、ドッキングの探索ボックスは Å です。膜タンパク質、非標準残基、複雑な補因子を含む場合は、適切な専門手法で準備してから系を取り込みます。構築後はエネルギー最小化と平衡化が必要です。

10.4 既存の系を取り込む

「ImportまたはConnect System」の下で、既存のTPRや座標、トポロジー、MDPを選択します。ターゲットホスト上でのディレクトリや相対的なファイルパスを設定します。必要に応じて、インデックス、位置制約に関する座標、チェックポイントも追加します。

GROMACSを確認し、その後、システムも確認してください。そして、それを提出可能なジョブとしてインポートしてください。提出する前に、入力データと前処理の結果を確認してください。外部の実行を参照している場合は、監視機能のみを使用することをお勧めします。

11. 多段階のシミュレーションを設定・実行する

11.1 ワークフローと独立したレプリカを作る

ワークフローを作成し、必要に応じて、独立した繰り返し実験の回数や、開始時のサンプル数を指定してください。EM、NVT、NPT、および生産段階における、各ステップでの入力データ、MDP、リソースについても確認してください。

内蔵されている短いワークフローを確認し、そのワークフローが正常に実行されているかを確認してください。これらの設定を、自分の使用目的やプロダクトに合わせて変更しないでください。保存したワークフローを、提出しないようにしてください。

11.2 MDP を編集して前処理を確認する

GROMACSのパラメータ設定ウィンドウでは、ネイティブなパラメータ名で検索し、積分器、dt、nsteps、出力周波数、結合定数、制約条件などを確認します。時間ステップとステップ数によって、全体の処理時間が決まります。

MDP ファイルの取り込み時は、キーの重複を確認し、有用なコメントを残します。前処理で出た警告を読み、原因を解消してください。未解決の問題を maxwarn の引き上げで通さないでください。

11.3 段階を開始して計算資源を割り当てる

現在または次の段階を始める前に、ホスト、スケジューラーの資源、mdrun 設定を確認します。スレッド、PME、GPU とキューの資源要求を合わせ、短い試行のログを長時間ジョブの設定に生かします。

別のステージを開始する前に、出力結果やシステムの状態を確認してください。必要なステップをスキップするのではなく、失敗したり停止したステージを解決してください。

11.4 停止・再開し、ログを確認する

正常に止めるには、チェックポイントを保存して停止します。元のジョブのチェックポイントから再開し、ログで再開地点を確認してください。上限は最終ステップ番号です。追加するステップ数ではありません。

ログを読み直し、異常な値や不合理な構造がないか確認してください。制約が発生している場合や、エネルギーが異常である場合は、システムや設定をチェックし、必要であれば、準備段階または平衡状態に戻ります。各段階間の移行や、同じ段階での再開には、異なるワークフローが必要です。

12. 軌跡と波動関数を調べる

12.1 軌跡解析を設定する

トラジェクティブがもはや記録されていない場合は、それを読み取り専用の分析ソースとして追加します。TPRとXTC/TRRを選択してください。必要に応じてEDRやログも追加します。トラジェクティブ、原子群、エネルギー項目を確認してください。

時間帯間、フレーム間隔、PBCの処理方法、参照値、フィットンググループ、測定グループを選択します。RMSD、RMSF、回転半径、SASA、水素結合、接触距離、エネルギーなどから始めます。研究の目的や利用可能なツールに応じて、PCA、クラスタリング、または密度を選択します。

カスタムの原子選択をプレビューします。タンパク質をフィットした後のリガンドのRMSD、リガンドをフィットした後のRMSDは、異なる値になります。どちらの値を使用したかを記録してください。

0～20 ns を 10 ps ごとに保存すると両端を含めて 2,001 フレームです。解析で 100 ps ごとに取ればグラフは 201 点になります。FAILED と表示されたときは、シミュレーションの最終ステップ、軌跡の最終時刻、起動スクリプトのエラーを照合してから再開を判断してください。

12.2 解析結果を確認・比較・書き出す

プロットやトラジェクティブのプレビューを確認する前に、そのメソッドや出所を確認しておきましょう。曲線の形状だけで判断するのではなく、実際にそのフレームを確認してみてください。

まず、MDジョブとその分析結果を入力します。その後、比較用の2〜8つのレコードを追加します。曲線や方法を比較する前に、時間帯やアラインデーション、選択肢を一致させます。必要に応じて、比較結果をJSON形式でエクスポートできます。また、独立した実験結果間の違いも保持します。

12.3 Multiwfn の入力を確認する

MultiWfn入力チェックでは、ローカルホストまたはSSHホスト上の波関数ファイルを選択します。この入力チェック機能では、FCH/FCHK、シングルフレームのMWFN、そして非磁性体であるGTO WFN/WFXもサポートされています。

原子、電子、基底状態、軌道、密度データなどを確認し、一致しない、または不適合な項目をまず修正する必要があります。ターゲットホスト上でMultiwfnをインストールまたは確認してください。ドッキングポーズやMDフレームワークは、別の量子化学計算のための幾何学的データを提供することができます。その波動関数を生成した後で、それをインポートすることができます。

12.4 解析を設定して三次元密度を確認する

MultiWfnのパス、メソッド、CPUスレッド、タイムアウトを入力し、タスクをプレビューしてください。電子状態、メソッド、ライセンスを確認した後、実行せずに保存してください。準備ができたら、別途提出してください。

密度については、グリッドの原点、間隔、およびポイントの数をボーア単位で設定します。カバー範囲や合計のポイント数を確認した後、結果を読み込み、等値面の閾値を設定・更新します。

入力チェックで使用可能な手法を選びます。Mulliken 電荷や Löwdin 電荷の計算には基底関数の情報が必要です。拡張子を変えても情報は補えません。

12.5 解析を書き出して保存する

キューファイル、ログ、メソッドの出力結果、設定内容などをエクスポートできます。タスクアーカイブをプレビューし、送り先を選択します。大容量のコピーは一時停止してから再開することができます。

オフラインでのレビュー用に、タスクアーカイブをインポートします。エントリーに別名を付与したり、それらを非表示にしたり、誤って削除されたエントリーを復元することもできます。リストの管理は、元の計算とは別に行われます。ファイルを削除する前に、必ず確認してください。

13. スマートフォンを PC やサーバーにつなぐ

進捗を監視したり、メモを取ったり、保留中の計画を編集したりする前に、まずデバイスをペアリングする必要があります。

13.1 サービスに接続してサインインする

コンピューター上で監視サービスを起動し、その電話がそれに接続できるかを確認してください。サーバーのSSHアドレスではなく、自分のデプロイメントや管理者が提供するアドレスを使用してください。

  1. プロフィールタブや「設定」から、アカウントやデバイスを開きます。
  2. 設定したサービスアドレスを入力し、接続してください。
  3. メールアドレスとパスワードを入力し、サインインしてください。
  4. アカウントを登録できる場合は、表示名、メールアドレス、パスワードを入力して登録します。必要に応じてメールを確認してから、サインイン画面に戻ります。

確認: 登録フォームが閉じられ、現在のアカウントや監視デバイスが表示されます。もし、どのデバイスもペアリングされていない場合は、ペアリングを続けてください。

うまくいかないとき: まず、アドレスや運用中のサービスが正常かを確認してください。セッションが終了した後で、再びログインしてください。もしアプリが再送信することを提案していれば、メールボックスやスパムフォルダを確認してください。再送信によって、設定が未完了のメールサービスは解決されません。ローカルな読み取り専用の接続は、現在のデバイスのローカルサービス用であり、リモートコンピュータとは異なります。

13.2 ワンタイムコードでペアリングする

  1. コンピュータの監視エージェント内で、新しいペアリングコードを生成します。両方のデバイスが同じサービスアドレスを使用していることを確認してください。
  2. 電話のアカウントやデバイス画面で、コードを入力し、ペアリングを要求してください。
  3. コンピューター上で、要求しているアカウントを確認し、ペアリングが正常に行われているかを確認してください。
  4. 携帯電話のリフレッシュ装置を使って、機能を更新してください。

確認: コンピュータは、監視装置の下にあります。電話でのペアリングだけでは不十分です。コンピュータが確認する必要があります。

うまくいかないとき: もし、古いコードが有効でなく、使用されていたり、期限が切れていた場合は、新しいコードを生成します。確認が待ち受けている場合は、各デバイス上で、要求するアカウントとサービスアドレスを確認します。

13.3 監視する端末を選ぶ

  1. コンピューターを探して、その名前や最後の接続日時、ステータスレポートのタイムスタンプなどを確認してください。
  2. そのデバイスを開けて、再び「Progress」に戻りましょう。
  3. デバイスを切り替えるには、アカウントの画面を開き、別のコンピュータを選択します。

確認: 選択されたデバイスにはマークが付けられており、ホームビューでは、その接続に関する実行状況が表示されます。計算は、そのコンピュータ上、または接続されているサーバー上で行われます。実行状況については、ローカルまたはリモートでの実行かどうかを確認してください。

うまくいかないとき: まず、デバイスリストを更新してください。もし接続が切れていれば、スリープ状態やモニタリングエージェント、ネットワーク状況を確認してください。接続が切れていても、それが計算に失敗したという意味ではありません。一つのデバイスの接続に問題があるからといって、すべてのデバイスがオフラインであるという意味ではありません。

13.4 権限の確認とペアリングの解除

  1. リフレッシュ機能を使用し、関連するカードの権限や有効期限を確認してください。
  2. ジョブの閲覧には読み取り権限を使います。計画を編集したり計算を投入したりするときは、PC で対応する期限付き権限を付与し、スマートフォンで権限を更新します。詳しくは第 18 章を参照してください。
  3. 再パーティングを行う前に、保存する必要がある研究記録をエクスポートしてください。その後、「再パーティング」を選択し、確認プロセスを確認してください。

確認: 更新された権限情報は、デスクトップ上の権限情報と一致します。解除連携後、デバイスはアカウントへの監視データの送信を停止します。既存の計算結果は、元のホスト上で引き続き保持されます。

うまくいかないとき: コンピュータ上の有効期限が切れた権限を更新する代わりに、無効になった編集ボタンを再試行するのではなく、リフレッシュするようにします。ペアリングを解除する前に、ログアウトするか、接続を変更する前に、必要なローカルデータを保持しておきます。ローカルデータは、アプリが説明するようにクリアされます。

14. 計算ジョブを探して進捗を確認する

14.1 進捗画面でジョブを探す

  1. オープン・プログレス
  2. オーバーレイの数値は、アクティブなものや、注意が必要な実行すべてに適用され、それに応じたリストが表示されます。
  3. 最近の実行例を選び、その詳細を確認するか、または全ての実行例とプロジェクトリストを開いてみてください。
  4. コンピュータ側での更新時間と、電話端末での最後に成功した読み取りの時間を比較してください。これらは、異なるイベントを測定するものです。

確認: 実行内容、プロジェクト名、種類、実行場所を確認してください。最新の進捗状況や不明な状態は、実際の進捗状況を反映していない可能性があります。

うまくいかないとき: もし、何かが欠けていれば、デバイスを確認し、「Research」セクションで検索してください。もし、読み取りが中断したり、接続が切れたりした場合は、再接続して、タスクを更新してください。再度提出しないでください。

14.2 プロジェクト・種類・状態で絞り込む

  1. 名前やプロジェクト名、識別子で検索することができます。
  2. プロジェクトと、DockingやMDなどのコンピューティングタイプを選択します。
  3. 州別で絞り込みし、さらに必要に応じて、エンジンやローカル/リモート実行の観点からも絞り込むことができます。
  4. 結果をページめくったり、フィルターをクリアして、もう一度始めましょう。

確認: 表示される範囲は、リストの上に示されています。ディレクトリ検索では、そのページ全体が検索対象となります。アカウント接続では、選択されたデバイスに関連する記録が検索されます。つまり、表示されているページだけでなく、関連する記録も含めて検索されます。

うまくいかないとき: フィルタリングをクリアし、選択したプロジェクトとタイプを確認してください。もし同期が部分的な場合は、コンピューター上の以前の履歴を確認してください。オフライン検索では、保存されているローカルコピーのみが対象となります。

14.3 更新間隔を設定し、取得をやり直す

  1. このガイドに合わせて、設定で「日本語」をアプリ言語として選択してください。
  2. 5秒、10秒、15秒、30秒ごと、1分、2分、5分ごとに、または手動で更新することができます。
  3. ホーム画面でタスクの更新を押すと、すぐにデータを取得します。結果やログを取得できなければ、詳細画面で再試行します。

確認: 最後の成功した読み取りのタイムアップ更新です。手動モードでは、予定されている読み取り処理が停止します。間隔を変更したり、画面を閉じたり、電話をロックしたりしても、リモートジョブの実行は停止しません。

うまくいかないとき: もし、タイムスタンプが変わっていない場合は、接続メッセージを確認します。再試行する前に、デバイスを更新し、確認する必要があります。以前に保存されていたページは、参照用のコピーとして残ります。

14.4 通知を絞り込み、対応するジョブを開く

  1. ログインしてペアリングが完了した後、「メッセージ」を開き、リストを更新してください。
  2. 読了状態や、エラーや完了、接続の変更などのイベントタイプに基づいてフィルタリングすることができます。古いメッセージについては、前のページに戻ります。
  3. メッセージを「読んだ」か「未読」かを個別に判別します。エラーログや、メッセージを送信したデバイスも表示されます。アプリは、該当するデバイスを選択し、メッセージが送信された後に、そのメッセージが「読んだ」と判定されます。
  4. 障害通知が表示された場合、その時刻や試行回数を確認してください。もし、古い試行回数が関連している場合、表示されるログは現在の試行回数に関するものです。コンピュータ上で古いログを確認してください。

確認: 未読件数やフィルタリングされたリストは、メッセージの状態を反映しています。読んだということは、メッセージが解決されたという意味ではありません。現在の状態を把握するには、「開いた」という状態や、メッセージが読まれた時刻を参照してください。

うまくいかないとき: プロンプトが表示されたらログインしてください。接続が確立された後、通知メッセージを再送信します。メッセージに一致するものがない場合は、両方のフィルターをリセットしてください。ペアリングされていないデバイスに関する通知は過去のものであり、目的地を開くことはできません。アクセスに失敗した場合は、アカウントやデバイスを確認し、デスクトップの記録も確認してください。古い試行について説明するために、現在のログを使用しないでください。

15. 結果とログを確認する

15.1 ドッキング結果を確認する

  1. 「Research」タブで「Docking run」を選択し、その結果の概要を開きます。
  2. 各結果のリガンド、受容体、シード、および試行回数を確認してください。
  3. ポーズのスコアの名前、値、ランキングの方向、および利用可能なQCを確認してください。
  4. ページを切り替えて結果を確認します。比較したいポーズがあれば、その候補レコードを開きます。詳しくは第 16 章を参照してください。

確認: この要約には、読了時間が表示されています。結果は、各タスクごとにページングされており、1つのタスクあたり最大5つのポーズが表示されます。スコアやQCが記載されていない場合は、ゼロや合格と見なされません。

うまくいかないとき: 結果が表示されない場合は、その実行がキューに入っているか、アクティブかどうを確認し、その後ログを参照してください。失敗した読み取りを再試行してください。スコアは、エンジン間で平均化することはできず、また、バインドや活動性を示すこともできません。

15.2 MD の進捗、チェックポイント、解析を確認する

  1. フィルタリングされた研究をMDに転送し、実行を開始します。
  2. 要約すると、経過したシミュレーションの時間を、目標値、パフォーマンス、ステップ数、およびチェックポイントの状態と比較します。
  3. この試行がチェックポイントから再開されたかどうかを確認し、どのソースからこの試行が始まったかを特定してください。
  4. 要約の中で、既存の分析結果を確認してください。デスクトップアプリを使って、さらなる分析を実行することができます。

確認: 利用できないデータは、依然として表示されない状態です。チェックポイントを見つけたからといって、電話が再び正常に機能するという意味ではありません。

うまくいかないとき: 分析が行われていない場合は、コンピュータ上で出力が正しく表示されているかを確認してください。実行が再開可能であれば、デスクトップ上で実行を続行してください。目標の時間に到達したり、実行が完了したとしても、それが収束やメカニズムが実現された証拠とは言えません。

15.3 目的のログを選ぶ

  1. 実行中のエラーやログを開くことができます。
  2. 実行の出力を得るためにワーカーを選び、またはジョブのスケジュールを行うためにスケーラーを選びます。
  3. ドッキングの結果から、その具体的な結果を確認するために、タスクログを開きます。
  4. 以前のログページに戻る、または、最新の出力結果に戻る。

確認: このログには、読み取り時刻、バイト数、そして総サイズが表示されます。エラーを解決する前に、元の内容を確認してください。

うまくいかないとき: まだ表示されていないログも、後で表示される可能性があります。最も新しいページから再試行してください。過去のメッセージから開いたログの場合は、その試行回数が現在のものと異なるかどうを確認してください。

15.4 ログを検索・追跡・コピーする

  1. 現在のページを検索し、前のページや次のページへの移動を利用してください。
  2. エラーを発生させるキーワードだけをフィルタリングし、完全なコンテキストが必要な場合は、そのフィルターをオフにします。
  3. ライブ接続と自動的な間隔を設定しておくと、フォロー・ラストエッジ機能が有効になります。検索したり、上方向にスクロールしたり、古いページを読んだ後でも、フォロー・ラストエッジ機能が再び有効になります。使用を終えたら、再びこの機能を無効にすることができます。
  4. 「コピーする」を使って、そのページをコピーできます。

確認: 件数と追尾表示で現在の状態が分かります。検索と絞り込みは現在のページ（最大 16 KiB）のみが対象です。行番号もページ内の番号です。ページをコピーしてもログ全体はダウンロードされません。

うまくいかないとき: 必要がある場合は、より古いページを検索してください。以下の内容はオフライン状態では利用できないか、または手動モードでは利用できません。最新のページを手動で開いてください。コピーに失敗した場合は、長押ししてテキストを選択してください。キーワードのマッチングは、エクスイートコードや文脈を考慮して行われます。

16. メモ、お気に入り、候補の比較

16.1 メモを保存し、ジョブをお気に入りに加える

  1. 「実行詳細」を開き、「実行ノート」を選択してください。
  2. お気に入りのコースは、頻繁に再訪したくなるものです。
  3. 研究のレビューステータスを設定し、観察点や質問、または次のステップについて記述してください。
  4. 保存します。研究記録に戻り、「Run Notes」を開いて、その内容を編集します。

確認: お気に入りの項目、レビューの状態、メモ、編集時間などがリストに表示されます。メモを「レビュー済み」にマークしても、計算が完了したという意味ではありません。記録はまずローカルに保存されます。

うまくいかないとき: 保存に失敗した場合は、エディター内で保存状態を確認してください。記録が不足している場合は、アカウントやデバイスを確認してください。保存されていない変更を破棄するように求められた場合は、元に戻って保存してください。

16.2 ポーズを候補リストに保存する

  1. Dockingサマリーから、特定のポーズに関する候補者情報を開きます。
  2. その出典やスコアを確認し、レビューのステータスを設定し、メモを追加します。
  3. 保存し、候補者リスト内の「研究記録」の項目を見つけてください。
  4. ソースを開いて、追加のフィールドの完全な起源を表示します。

確認: 候補者は、元のポーズ、スコア、再生時間を保持します。元の記録を編集して、そのメモを更新してください。

うまくいかないとき: 安定した識別子がないポーズでは、保存することはできません。デスクトップ上の結果を確認してください。もしソースが利用できない場合でも、保存されたデータは、再接続するまで読み取ることができます。研究記録を削除しても、計算結果は削除されません。同期処理が行われる際には、必ず確認を読んでください。

16.3 2〜4 件の記録を比較する

  1. 「Run Notes」または「Research Records」にある候補者リストを選択してください。
  2. 比較やエクスポートのために、2つから4つのエントリをマークしてください。
  3. 選択したエントリの比較を開きます。
  4. 水平スクロールして、ソース、エンジン、メトリクス、パラメータ、読み取り回数、および注釈などを確認できます。ハイライトされたフィールドは、通常のフィールドとは異なります。

確認: 欠損値は、ハッチマークで示されます。適切な文脈があれば、それはヒントにはなりますが、科学的な条件を確認するための手段ではありません。

うまくいかないとき: 2つ未満の場合や4つ以上の場合では、選択肢を調整してください。異なる受信機、走行経路、得点などのデータを並べて表示できますが、互いに矛盾するスコアは並べ替えたり、統合したりしないでください。古くなったデータは、元のデータ源から更新してください。

16.4 概要を書き出し、保存先を確認する

  1. 研究記録の中から、選択した記録や現在のリストをエクスポートすることができます。また、比較結果の要約もエクスポートできます。
  2. Markdown形式のファイル（.md）またはJSON形式のファイル（.json）を選択し、プレビューを確認してください。
  3. AndroidやiOSで保存するか、共有するかを選択できます。また、ブラウザから直接ダウンロードすることもできます。その後、システムダイアログで保存先を選択してください。
  4. もしファイルが不要な場合は、その内容をコピーしないでください。共有する前に、そのファイルの情報や出典を確認してください。公開したくない情報は、必ず削除してください。

確認: 保存されたファイルを開くか、目的地のアプリで受信を確認してください。サマリーには、記録やメモ、出典などの情報が記録されています。ただし、完全な分子ライブラリやトラジェクト、計算ファイルは含まれていません。

うまくいかないとき: 保存や共有をキャンセルしても、元のレコードは削除されません。エクスポートに失敗した場合は、再試行するか、テキストをコピーしてください。共有シートを開くだけでは、配布が完了したとは言えません。

17. オフラインで読むページを保存する

17.1 ジョブの概要と必要なページを保存する

  1. 接続中にオープンランに関する詳細を確認し、正常な読み取りが行われることを待ちます。
  2. 実行の概要を保存します。結果やログページを保持したい場合は、そのページを開いて、現在読み込まれているページをそのまま保持してください。
  3. 各追加ページを、別々にロードし、保持してください。
  4. 保存された結果やログページ、その範囲、読み取り時刻、保存時刻を確認してください。

確認: このページには、保存が成功したと報告されています。要約では、全てのデータがダウンロードされるわけではありません。新たにオンラインで入手できるデータが、保存されたデータに代わることができるので、これは不変のバックアップではありません。

うまくいかないとき: 保持機能が無効になっている場合は、ページの読み込みが完了するまで待ちます。ストレージが満たされている場合は、17.3項に説明されているように、もう不要な素材をアプリケーションから削除してください。アプリケーションが確認した場合に限り、表示されているページは保存されたコピーとみなされます。

17.2 オフラインで開き、未保存のページを確認する

  1. 元のアカウントと接続で、そのアプリを再開してください。オフラインコピーのラベルや、元の読み取り時間を見てみてください。
  2. 「オフライン記録」の項目にある「設定」で、明示的に保存されたデータを開きます。
  3. 保存された結果のページを拡大し、必要なページを選択してください。
  4. 再接続後、タスクを更新し、更新が必要なページを再読み込みしてください。

確認: オフラインコピーでは、元の読み取り時間が表示されます。通常、読み取りは最近のコンテンツをキャッシュしますが、特定のページやサマリーを保持する場合は、そのまま保持されます。

うまくいかないとき: もし既存の保存済みのページがない場合は、別のページを選択するか、再接続して取得してください。オフラインでの実行が欠けている場合は、アカウントやデバイスを確認してください。ログアウトしたり、ペアレッチを解除すると、ローカルに保存されているデータが消去されます。再接続しても、エクスポートしたデータの代わりにはなりません。

17.3 保存領域を管理し、保持指定を解除する

  1. 「設定」→「オフライン記録」を開くと、接続、アプリ、および保持されているコンテンツによる使用状況を確認できます。
  2. 保存されているページリストから、特定の行やページを保持することをやめましょう。
  3. 実行時に保持されているすべてのページを解放するために、その詳細な操作を使用し、使用状況を確認・再確認してください。
  4. 現在の接続のオフライン記録は、不要であることを確認した後にのみ削除してください。

確認: 上限はアプリ全体で 40 ジョブ、ジョブごとに結果またはログ 12 ページ、合計 20 MiB です。保持指定したコピーも上限に含みますが、自動では削除されません。保持を解除すると通常のキャッシュ削除の対象になります。端末内のコピーを消してもサーバーの結果は残ります。

うまくいかないとき: 保持されているコピーをリリースしても、すぐに使用量が減少するわけではありません。なぜなら、そのコピーはキャッシュ内に残っている可能性があるからです。保存や削除がうまくいかない場合は、デバイスのストレージを確認してください。ストレージの管理を代行するためにログアウトするのはやめてください。

18. 未投入の計画を編集して実行する

18.1 デスクトップのプロジェクトや保存済み計画を開く

  1. デスクトッププロジェクトを保存してください。そうでない場合、電話では保存されていないデスクトップの変更内容を読み取ることができません。
  2. PC の「設定」でモバイルのプロジェクトとタスクの権限を開き、ペアリング済みの監視エージェントの Device.json を選び、有効期間を設定します。既定では計画の編集だけが可能です。実際の計算を投入するには、PC でモバイル投入の権限を別途有効にします。権限を付与しただけでは実行されず、スマートフォンでの確認が必要です。
  3. 電話で、正しいデバイスを選択し、権限を更新してください。研究セクションから、またはログインしたアカウントからアプリを開きます。
  4. デスクトッププロジェクトを開いて、新しい計画を設定するか、保存された計画を確認します。
  5. 編集する前に、プロジェクトの内容、ホストの種類、エンジンの種類、そしてタスクの数を確認してください。

確認: デスクトッププロジェクトでは、ソースコードを変更することなく、独立した計画案を作成することができます。ただし、実行が開始されていない計画案のみが、サポートされている場所で編集可能です。

うまくいかないとき: プロジェクトをコンピューターに保存し、情報が不足している場合は、計画を更新してください。許可に関するエラーがある場合は、デスクトップ上でペアリングされたエージェント、実施期間、提出の承認状況を確認し、電話機も再び更新してください。デスクトップ上で、サポートされていないプロジェクトの構成を確認してください。実際に実行されているプロジェクトを編集可能として扱わないでください。

18.2 パラメーターを編集し、端末内の下書きを復元する

  1. ドッキング計画には、各リガンドに対するCPUスレッド数、並列リガンド、エクスポージャビリティ、最大可能なポーズ数、スコアリング関数、シード値などが含まれます。エネルギー範囲（kcal/mol）は、その形式が示されている場合にのみ設定してください。単一のボックスについては、中心位置とサイズXYZをÅ単位で指定してください。
  2. GNINA は CPU のみで実行するか、対応環境で GPU の使用を許可できます。表示される CNN スコアリングモードは現在の設定で、この画面では変更できません。受容体ごとの探索ボックスは PC で編集します。
  3. MDリソースの設定には、ランクごとのスレッド数、MPIランク、GPUの数、メモリ（GiB単位）、キューイング時間、パーティション、アカウント、QoS、最大実行時間（時間単位）、および実行モードなどが含まれます。これらの設定は、既存のTPRにおける科学的な設定には影響しません。
  4. エディット内容がローカルに保存されていることを確認してください。必要であれば、ローカルの草案を再開し、その値を確認し、オンライン上のソースを更新した後に、プレビューを行ってください。

確認: 表示されている単位や範囲に従ってください。ローカルなドラフトは、電話での入力に限ります。これはデスクトップでの計画ではなく、何の計算も行われていません。コンマで区切られたセクション、およびフォームのキュー時間の形式を使用してください。

うまくいかないとき: ハイライトされた値を正しく修正してください。デスクトップのソースが変更された場合は、古いドラフトを破棄する前に、最新のソースに沿って変更を反映させてください。古いドラフトで変更されたプロジェクトを上書きしないでください。ローカル保存に失敗した場合は、ページを開いたままにして、ストレージを確認してください。

18.3 変更内容を確認して未投入の計画を保存する

  1. 編集を終えたら、変更内容をプレビューします。
  2. 変更前後を比べます。デスクトップのプロジェクトから新しい計画を作った場合は、計算資源の概要も確認します。
  3. 確認し、未投入の計画として保存します。
  4. 保存結果と保存済み計画の一覧を確認します。PC からの確認済みの受付記録が表示された場合は、それも確認します。

確認: このアプリでは、提出されていない計算内容がある待ち受けプランが表示されているか、または、独立したプランが確認されているが、ソースプロジェクトは変更されていないことが確認されます。保存すると、ジョブが実行されません。

うまくいかないとき: 既存の計画は、プレビューを行う前に変更が必要です。新しい計画では、元の設定をそのまま使用できます。もしソースやプレビューの内容が変わった場合は、再びリフレッシュしてプレビューしてください。保存結果が不明な場合は、新しい計画を作成するのではなく、同じ保存操作を再実行してください。

18.4 資源を確認して投入し、結果が不明なときは復旧する

  1. PC で期限付きの投入権限を付与し、スマートフォンで権限を更新します。端末内の編集を先に PC に保存するか、不要な下書きを明示的に破棄します。
  2. 保存されている未処理の計画を開き、提出内容を確認してください。
  3. ホスト、エンジン、タスク数、CPU の同時実行数を確認します。MD の場合は、スレッド数、ランク数、GPU、メモリ、キューの実行時間上限を確認します。
  4. 計画を確認してから確認欄にチェックを入れ、計算を開始します。この操作で実際のジョブが計算ホストに送信されます。
  5. リフレッシュプランの状態を確認します。関連する実行が表示されたら、進捗状況、結果、ワーカーのログ、またはスケーラーに関するログを開きます。

確認: 提出された内容は、実際に完了する前に記録されます。提出やキューインが完了したという意味ではありません。関連する実行状況を確認してください。

うまくいかないとき: 開始ボタンが使えないときは、確認欄、投入権限、未保存の編集を確認します。接続が切れたら、同じ投入を復旧するか計画の状態を更新し、新しい計画で投入し直さないでください。元のアカウント、サービス、ホストに戻り、保存された受付記録を処理します。受付記録を保存できなければ、端末内のストレージを復旧して元の操作を保持します。データ消去で復旧を回避しないでください。
