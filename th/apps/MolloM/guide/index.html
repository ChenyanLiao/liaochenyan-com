MolloM · 2026.11.19

คู่มือการใช้งาน MolloM

ตั้งแต่การเตรียมโปรเจกต์บนคอมพิวเตอร์ไปจนถึงการดูงานและผลลัพธ์บนโทรศัพท์ คู่มือ MolloM แบ่งตามขั้นตอนการใช้งาน

ครั้งแรกใช้ลิแกนด์เพียงหนึ่งตัว เปิดตัวอย่างสาธารณะ บันทึกโครงการ แล้วหาตัวรับ ลิแกนด์อ้างอิง และกล่องค้นหาในภาพสามมิติ ทดลองรัน Vina แล้วเปิดดูคะแนนและท่าจับก่อนเปลี่ยนไปใช้คลังของตัวเอง หากมีวิถีการจำลองอยู่แล้ว ให้เริ่มที่การวิเคราะห์วิถี

ขั้นตอนบนเดสก์ท็อปตรวจสอบกับรุ่นพัฒนา 0.301.0 ภาพประกอบมาจากรุ่นก่อนหน้า ดูหมายเลขรุ่นในการตั้งค่าและเทียบกับหน้าดาวน์โหลด หากใช้ไคลเอนต์ AI ของตนเอง ให้ทำตามขั้นตอนเชื่อมต่อ แล้วส่งคู่มือสำหรับเอเจนต์ (Markdown) ให้ไคลเอนต์

1. เริ่มต้นใช้งาน

1.1 เลือกงานคำนวณแรก

ใช้ตัวรับรู้ที่คุ้นเคย และสารตั้งต้นเพียงไม่กี่ชนิดในการดำเนินการต่างๆ เช่น การนำเข้าข้อมูล การเตรียมข้อมูล ช่องสำหรับการค้นหา การทดลองเล็กๆน้อยๆ และการทบทวนผลลัพธ์ต่างๆ ก่อนที่จะดำเนินการกับไลบราร้าขนาดใหญ่.

หากคุณมีระบบ GROMACS อยู่แล้ว ให้เริ่มต้นอ่านเนื้อหาในบทที่ 10 ก่อน หากคุณมีไฟล์ที่เกี่ยวข้องกับฟังก์ชันคลื่น ให้เริ่มต้นอ่านเนื้อหาในบทที่ 12 ก่อน หากคุณต้องการอ่านเนื้อหาเกี่ยวกับการตรวจสอบการเคลื่อนที่ของอนุภาค ให้เริ่มต้นอ่านเนื้อหาในบทที่ 13 ก่อน การจัดการการเชื่อมต่อระหว่างอนุภาคและการคำนวณความเป็นระนองนั้นมีจุดเริ่มต้นที่แตกต่างกัน ทั้งสองอย่างนี้ไม่จำเป็นต้องเริ่มต้นจากจุดเดียวกันเลย

1.2 เลือกอุปกรณ์ที่ใช้และเครื่องที่รันการคำนวณ

ใช้แอปพลิเคชันบนเดสก์เพื่อเตรียมโครงสร้างต่างๆ กำหนดการทำงานของโปรแกรม กำหนดเวลาสำหรับการคำนวณ และตรวจสอบผลลัพธ์ต่างๆ โปรดเลือกคอมพิวเตอร์ในเครือข่ายหรือเซิร์ฟเวอร์ SSH เป็นโฮสต์สำหรับการประมวลผล กรุณากรอกเส้นทางการเข้าถึงโปรแกรม รวมถึงเส้นทางการเข้าถึงทรัพยากรต่างๆ สำหรับโฮสต์นี้: เส้นทางการเข้าถึงจากเซิร์ฟเวอร์จะถูกอ่านจากเซิร์ฟเวอร์ ส่วนเส้นทางการเข้าถึงจากคอมพิวเตอร์จะถูกอ่านจากคอมพิวเตอร์ของคุณเอง.

หลังจากที่เชื่อมต่อโทรศัพท์เข้ากับบริการการตรวจสอบแล้ว คุณสามารถตรวจสอบข้อมูลต่างๆ เช่น ข้อมูลการทำงาน ผลลัพธ์ และบันทึกต่างๆ ของอุปกรณ์ที่เชื่อมต่อได้ และยังสามารถแก้ไขแผนการทำงานที่ยังไม่เสร็จสิ้นได้ ขณะที่ยังมีสิทธิ์ในการเข้าถึงข้อมูลเหล่านั้นอยู่ ก่อนที่จะออกจากหน้าต่างทำงาน ควรตรวจสอบให้แน่ใจว่าอุปกรณ์ที่ใช้ในการประมวลผลยังคงทำงานอยู่ และบริการการตรวจสอบก็ยังคงทำงานอยู่ต่อไป.

1.3 เปิดโปรเจกต์และการตั้งค่า

ภายใต้หัวข้อ “โปรเจกต์และแม่แบบ” ให้สร้างโปรเจกต์ขึ้นมา จากนั้นเปิดไฟล์ JSON ของโปรเจกต์นั้น หรือนำไฟล์ตัวอย่างที่มีอยู่มาใช้ได้เลย จากนั้นเลือกภาษาการออกแบบอินเทอร์เฟซของคุณในส่วน “Settings”

ก่อนที่จะรันตัวอย่างนี้ ควรตรวจสอบไฟล์ข้อมูลที่จะนำมาใช้ รวมถึงสภาพแวดล้อมและพื้นที่ที่จะใช้ในการทดลองก่อน ควรทำการทดลองเบาๆก่อน ให้ใช้ค่าที่กำหนดไว้เป็นจุดเริ่มต้น แล้วปรับเปลี่ยนค่านั้นให้เหมาะสมกับโครงสร้างและคำถามทางวิจัยของคุณเอง.

อ่านงานแรกผ่านเอเจนต์ เปิดไคลเอนต์ที่รองรับ MCP ผ่าน stdio บนคอมพิวเตอร์ที่เปิด MolloM ไคลเอนต์ต้องเรียก Node.js 18 ขึ้นไปได้ ในการตั้งค่า MolloM เลือก AI Agent · MCP เลือกสิทธิ์อ่านอย่างเดียวแล้วยืนยัน เมื่อบริการทำงานแล้ว ให้คัดลอก JSON ไปเพิ่มในรายการเซิร์ฟเวอร์ MCP เดิมของไคลเอนต์ ใช้พาธที่สร้างให้และอย่านำเนื้อหาไฟล์เชื่อมต่อไปวางในแชต เปิด MolloM ค้างไว้ เชื่อมต่อใหม่ ส่งคู่มือเอเจนต์ แล้วสั่งว่า “แสดงงาน docking ที่ลงทะเบียนไว้ไม่เกินห้างาน รอให้ฉันเลือกก่อนอ่านสถานะ” ถ้ายังไม่มีงาน รายการว่างก็เป็นผลตอบกลับที่ถูกต้อง เมื่อต้องเขียนข้อมูลจึงค่อยเปิดสิทธิ์ควบคุมงาน ยืนยัน แล้วเชื่อมต่อใหม่

2. ตั้งค่าสภาพแวดล้อมการคำนวณ

2.1 รันบนเครื่องของคุณ

  1. ศูนย์ปฏิบัติการและซอฟต์แวร์ด้านการจัดการสภาพแวดล้อม และเลือกการปฏิบัติการในระบบท้องถิ่น
  2. ตรวจสอบสภาพแวดล้อมอีกครั้ง และตรวจสอบโปรแกรมต่างๆ ที่พบได้
  3. หากมีเครื่องมือสำหรับการเชื่อมต่อเครื่องอยู่แล้ว ให้เลือกไฟล์ที่สามารถนำไปใช้ได้จริง เช่น ไฟล์ Vina binary นั่นเอง.
  4. ตรวจสอบว่าเขียนลงในไดเรกทอรีทำงานได้และมีพื้นที่ดิสก์เพียงพอ

หลังจากตรวจสอบเส้นทางการทำงานแล้ว ให้ทำการทดลองใช้งานจริงดู ตรงนี้คือจุดที่มีโอกาสสูงที่จะพบกับปัญหาเกี่ยวกับไลบรารีที่หายไป ไฟล์โมเดล หรือไดรฟ์ของอุปกรณ์ต่างๆ

2.2 เชื่อมต่อผ่าน SSH

  1. เพิ่มเซิร์ฟเวอร์เข้ามา โดยใช้ชื่อไมโครโปรโตคอลของเซิร์ฟเวอร์ หรือใช้แอพลิเคชัน SSH Config เพื่อกำหนดการเชื่อมต่อกับเซิร์ฟเวอร์นั้น.
  2. กรอกชื่อผู้ใช้และพอร์ต แล้วเลือกการยืนยันตัวตนของระบบหรือไฟล์กุญแจ อย่าวางกุญแจส่วนตัวลงในช่องข้อความทั่วไป
  3. กรุณากรอกไดเรกท์ของเซิร์ฟเวอร์ และเส้นทางสำหรับการเรียกใช้โปรแกรมจากระยะไกลด้วยนะคะ หากจำเป็นต้องใช้เส้นทางของ Python ก็ให้ใช้เส้นทางที่อยู่บนเซิร์ฟเวอร์นั้นแทนค่ะ.
  4. Save ไคลเอนต์ไว้ก่อน จากนั้นจึงทดสอบการเชื่อมต่อ และตรวจสอบสภาพแวดล้อมที่ใช้ในการทำงาน.

ตรวจสอบลายนิ้วมือของโฮสต์เมื่อเชื่อมต่อครั้งแรก หากไม่รู้จักโฮสต์หรือยืนยันตัวตนไม่สำเร็จ ให้ทดสอบในไคลเอนต์ SSH ของระบบก่อนลองอีกครั้งใน MolloM หากโปรแกรมเปิดไม่ได้ ให้ดูผลการตรวจสอบ สิทธิ์ ไลบรารีที่ต้องใช้ และสภาพแวดล้อม

บนคลัสเตอร์ให้เลือกระบบจัดคิวที่หน้างานนั้นรองรับ แล้วระบุพาร์ทิชันหรือคิว บัญชี เวลาสูงสุด และทรัพยากรที่ขอ

หากไม่รู้จักลายนิ้วมือของโฮสต์ ให้ตรวจสอบกับผู้ดูแลระบบ หากยืนยันตัวตนไม่ผ่าน ให้ตรวจชื่อผู้ใช้และกุญแจ แต่ถ้า SSH เชื่อมต่อแล้วและตรวจสภาพแวดล้อมไม่ผ่าน ให้ตรวจ Python บนเซิร์ฟเวอร์ ใน Slurm ข้อความ PENDING / Priority หมายถึงรอคิว ส่วน QOSMinGRES ต้องตรวจทรัพยากรขั้นต่ำของพาร์ทิชัน

2.3 ติดตั้งหรือลงทะเบียนซอฟต์แวร์

ในส่วนของ Software Center ให้เลือกคอมพิวเตอร์ท้องถิ่นหรือเซิร์ฟเวอร์ที่ต้องการ จากนั้น refresh รายการซอฟต์แวร์ของเซิร์ฟเวอร์นั้นๆ หากต้องการติดตั้งเวอร์ชันใดก็ให้อ่านแผนการติดตั้งและการตรวจสอบข้อมูลก่อน โดยรวมถึงข้อมูลเกี่ยวกับตำแหน่งที่ต้องการติดตั้ง ใบอนุญิย์ และข้อกำหนดต่างๆที่ต้องปฏิบัติตามด้วย.

สำหรับการติดตั้งที่มีอยู่แล้ว ควรตรวจสอบความถูกต้องของการติดตั้งก่อนที่จะเลือกใช้เวอร์ชันนั้นๆ บางช่องทางอาจมีคำแนะนำเกี่ยวกับวิธีการติดตั้งจากแหล่งข้อมูลอ้างอิง หรืออาจให้คุณสามารถลงทะเบียนโปรแกรมที่คุณติดตั้งไว้ได้ ควรอ่านผลลัพธ์จากการตรวจสอบที่ล้มเหลวก่อนที่จะดำเนินการต่อไป การที่มีไดเรกท์นั้นอยู่ในระบบไม่ได้หมายความว่าโปรแกรมนั้นสามารถทำงานได้จริงๆ

3. สร้างโปรเจกต์และนำเข้าโครงสร้าง

3.1 ตั้งชื่อโปรเจกต์ให้ค้นหาได้ง่าย

สร้างโปรเจกต์ขึ้นมาในหมวด “Projects and Templates” ให้ตั้งชื่อที่เหมาะสมเพื่อบ่งบอกถึงหัวข้อและวัตถุประสงค์ของโปรเจกต์นั้นๆ โปรเจกต์หนึ่งๆ สามารถมีหลายรุ่นหรือขั้นตอนการปรับเปลี่ยนได้ แต่การปรับเปลี่ยนเล็กน้อยไม่จำเป็นต้องคัดลอกไฟล์ทั้งหมดไปยังโปรเจกต์ใหม่

บันทึกข้อมูลไว้หลังจากที่ได้เปลี่ยนการตั้งค่าที่สำคัญแล้ว นำข้อมูลในรูปแบบ JSON ออกมาเพื่อใช้กับการตั้งค่าของโปรเจกต์โดยเฉพาะ ใช้แพ็กเกจที่มีอยู่ในบทที่ 9 เพื่อนำข้อมูลต่างๆ ไปใช้งานได้.

3.2 เพิ่มตัวรับและลิแกนด์

  1. ในส่วนของ “Receptors and Ligands” ให้เพิ่มตัวรับที่มาจากไฟล์ PDB หรือ PDBQT เข้ามา.
  2. เลือกไฟล์ที่เป็นลิแกนด์ หรือโฟลเดอร์ที่ต้องการ หรือสามารถค้นหาไฟล์ต่างๆ บนเซิร์ฟเวอร์ได้เช่นกัน.
  3. กรุณาเลือกรูปแบบการป้อนข้อมูลที่ต้องการ: PDBQT, SDF/SD, MOL2, MOL หรือ SMILES.
  4. ตรวจสอบข้อมูลที่ป้อนเข้ามาอีกครั้ง และตรวจสอบจำนวนข้อมูลที่มีอยู่ รวมถึงปัญหาเกี่ยวกับการประมวลผลข้อมูลด้วย.

ไฟล์ SDF หนึ่งๆ อาจมีข้อมูลโมเลกุลหลายชุดอยู่ในนั้น ดังนั้น จำนวนไฟล์และจำนวนข้อมูลในไฟล์อาจแตกต่างกันได้ ควรตรวจสอบข้อมูลที่มีปัญหาเหล่านั้น และตัดสินใจว่าจะต้องแก้ไข ยกเลิก หรือเตรียมข้อมูลเหล่านั้นอีกครั้งหรือไม่ ก่อนที่จะดำเนินการขยายข้อมูลในไฟล์ SDF นั้นต่อไป.

3.3 เก็บข้อมูลที่มาของโครงสร้าง

ควรเก็บไฟล์ต้นฉบับไว้ และยังควรเก็บข้อมูลระบุตัวตนของโมเลกุลต่างๆไว้ด้วย สถานะของโมเลกุลที่ได้จากการปรับแต่งควรจะสามารถเชื่อมโยงกับโมเลกุลต้นได้อย่างชัดเจน เมื่อต้องเปรียบเทียบโครงสร้างหรือสถานะของโมเลกุลต่างๆในโครงการเดียวกัน.

อย่าไปลบไฟล์ต้นฉบับออกไป เพราะข้อมูลที่คุณปรับเปลี่ยนเองนั้นจะถูกเก็บไว้ในไฟล์สำรองที่คุณสามารถตรวจสอบได้แยกต่างหาก.

4. เตรียมตัวรับและลิแกนด์

4.1 เลือกองค์ประกอบที่จะเก็บไว้ในตัวรับ

ในการเตรียมโครงสร้าง ให้ระบุว่าจะต้องเก็บโครงสร้างต่างๆไว้หรือไม่ หรือให้ว่างไว้เพื่อไม่ให้มีการกำหนดโครงสร้างใดๆ ขึ้นมา ควรพิจารณาว่าจะต้องกำจัดน้ำธรรมดาออกไปหรือไม่ และควรเก็บเอนไซม์หรือโลหะต่างๆไว้หรือไม่ ควรตรวจสอบข้อมูลทางโครงสร้างและเอกสารต่างๆก่อนที่จะกำจัดน้ำที่มีประโยชน์ ไอออนโลหะ หรือเอนไซม์ต่างๆออกไป

ควรตรวจสอบส่วนที่ขาดหายไปหรือไม่เป็นมาตรฐาน รวมถึงการกระบวนการเปลี่ยนโปรตอนด้วย โครงสร้างที่รายงานในขณะนี้ไม่เป็นมาตรฐาน ดังนั้นส่วนที่ขาดหายไปและการกระบวนการเปลี่ยนโปรตอนควรได้รับการจัดการแยกต่างหาก

4.2 เตรียมสถานะของลิแกนด์

คุณสามารถเลือกได้ว่าจะเก็บข้อมูลของ “พ่อแม่ของสาร” ไว้หรือไม่ รวมถึงจำนวนสถานะที่สามารถเกิดขึ้นได้ในแต่ละข้อมูลของแหล่งข้อมูลควรจะถูกจำกัดไว้อย่างไรด้วย ส่วนเรื่องของการกำหนดโครงสร้างของสารนั้น จะถูกกำหนดไว้โดยค่าเริ่มต้น แต่คุณสามารถเปิดใช้งานฟังก์ชันนี้ได้ก็ต่อเมื่อคุณรู้ว่าจะจัดการกับข้อมูลเหล่านั้นอย่างไร

สร้างพิกัด 3D สำหรับข้อมูลที่ยังไม่มีพิกัดอยู่ จากนั้นตรวจสอบข้อมูลเกี่ยวกับค่าความหนักของสาร, รูปแบบของโครงสร้างสาร และพันธะต่างๆ ก่อนที่จะดำเนินการเชื่อมต่อข้อมูลเหล่านั้นเข้าด้วยกัน.

4.3 ตรวจสอบการเปลี่ยนแปลงหลังเตรียมโครงสร้าง

เตรียมและตรวจสอบข้อมูลที่ส่งเข้ามา ตรวจสอบข้อมูลที่เสร็จสิ้นการประมวลผลแล้ว รวมถึงข้อมูลที่มีปัญหา จากนั้นเปิดไดเรกท์สำหรับการเตรียมข้อมูล เพื่อตรวจสอบไฟล์ต่างๆ ในการเปรียบเทียบก่อนและหลังการประมวลผล ควรตรวจสอบข้อมูลเกี่ยวกับจำนวนอะตอมที่มีน้ำหนักมาก ความสัมพันธ์ทางพันธุกรรม ชิ้นส่วนต่างๆ และพิกัดต่างๆด้วย.

แก้ไขข้อผิดพลาดให้ถูกต้องตามสาเหตุที่เกิดขึ้น ควรเก็บไฟล์ต้นฉบับไว้ และสร้างไฟล์สำเนาที่ใช้งานได้จริง เพื่อที่จะสามารถติดตามการเปลี่ยนแปลงของไฟล์ได้

5. กำหนดบริเวณค้นหา

5.1 หาตำแหน่งโพรงจับ

ในมุมมอง 3D นี้ ให้เลือกตัวรับสัญญาณที่ต้องการ คุณสามารถเปลี่ยนการแสดงผลของโปรตีน ลิแกนด์ และพื้นผิวต่างๆได้ โดยการลากเพื่อหมุน หรือเลื่อนดูข้อมูลเพื่อปรับขนาดภาพ หากจำเป็นก็สามารถย้อนกลับไปยังมุมมองเดิมได้เช่นกัน.

ใช้リガンドเพื่อระบุตำแหน่งของช่องว่างนั้น หากมีอยู่จริงก็ควรจะมีการปรับเปลี่ยนพิกัดของโครงสร้างให้สอดคล้องกับระบบพิกัดของตัวรับที่มีอยู่ในปัจจุบันก่อน หากพิกัดต่างๆ มาจากโครงสร้างที่แตกต่างกัน ก็ควรจะปรับเปลี่ยนโครงสร้างเหล่านั้นก่อนด้วย.

5.2 ตรวจสอบกล่องค้นหา

กรอกพิกัดศูนย์กลาง XYZ และขนาด XYZ เป็นอังสตรอม (Å) ตรวจว่ากล่องครอบคลุมบริเวณเป้าหมายและมีที่พอสำหรับลิแกนด์ โดยไม่กินพื้นที่ที่ไม่เกี่ยวข้องมากเกินไป

กรุณาตรวจสอบช่องที่เกี่ยวข้องกับตัวรับแต่ละตัวแยกกัน จากนั้นบันทึกโปรเจกต์นั้นไว้ แล้วตรวจสอบผลลัพธ์ในการทดลองว่าสิ่งที่คาดหวังไว้มีปรากฏจริงหรือไม่.

6. ตั้งค่าโปรแกรมด็อกกิงและทรัพยากร

6.1 เลือกและตรวจสอบโปรแกรม

เลือกโปรแกรมตามชื่อหรือหมวดหมู่ของมัน จากนั้นดูข้อมูลในเอกสารประกอบของโปรแกรม แล้วเลือกโปรแกรมนั้นสำหรับการใช้งานในรอบนี้ กำหนดเส้นทางการเรียกใช้โปรแกรมให้ถูกต้อง แล้วตรวจสอบเส้นทางการเรียกใช้โปรแกรมอีกครั้ง.

แนะนำให้ใช้การประกอบเข้ากับโปรแกรมที่มีอยู่ในตัวจะดีกว่า สำหรับการประกอบเข้ากับโปรแกรมแบบกำหนดเองนั้น ควรทดสอบคำสั่งต่างๆ รวมถึงการประมวลผลข้อมูลอินพุตและเอาต์พุตก่อน โดยใช้ขนาดงานที่เล็กๆ ก่อน

6.2 ตั้งค่าพารามิเตอร์ Vina และค่า seed อิสระ

เลือก “Vina” มาใช้งาน จากนั้นกำหนดค่าที่เกี่ยวข้องกับความซ้ำซากของข้อมูล ค่าที่สูงสุดของผลลัพธ์ที่ได้ ช่วงพลังงานที่สามารถใช้ได้ และฟังก์ชันสำหรับการให้คะแนน หากต้องการความแม่นยำสูง ก็จะต้องใช้ทรัพยากรที่มากขึ้น ควรใช้การทดลองเพื่อตัดสินใจ มากกว่าที่จะพยายามเพิ่มค่าทั้งหมดให้สูงสุด

กรุณากรอกรายชื่อของเมล็ดพันธุ์ที่ต้องการค้นหาไว้ทีละเมล็ดพันธุ์ ระบบจะประมวลผลข้อมูลต่างๆ รวมถึงตัวรับที่ถูกเปิดใช้งานไว้ เพื่อหาจำนวนเมล็ดพันธุ์ที่ต้องการค้นหา กรุณาตรวจสอบชื่อของเมล็ดพันธุ์และจำนวนเมล็ดพันธุ์ที่ต้องการค้นหาก่อนที่จะส่งข้อมูลไป เพื่อป้องกันไม่ให้มีตัวรับหรือเมล็ดพันธุ์ที่ไม่ต้องการเข้ามาเกี่ยวข้องกับกระบวนการค้นหานี้

6.3 ใช้งาน GNINA

เลือกวิธีการใช้งานของ CNN ได้ เช่น การปรับปรุงคุณภาพของข้อมูล หรือการเลือกใช้โมเดลต่างๆ ส่วนหากไม่ต้องการใช้ GPU ก็สามารถเลือกให้ทำงานบน CPU เท่านั้นได้

เมื่อใช้ GPU ให้ตรวจซอฟต์แวร์ ไดรเวอร์ และทรัพยากรที่จัดสรร แล้วดูบันทึกการทดลองว่าใช้โหมดใดจริง ค่าพลังงาน CNNscore และ CNNaffinity วัดคนละอย่างและมีทิศทางการจัดอันดับของตนเอง ให้ตั้งตัวกรองแยกกัน

6.4 กำหนดงานพร้อมกันและจัดสรร CPU กับ GPU

จำนวน CPU ต่องานคือทรัพยากรของแต่ละงาน ส่วนจำนวนงานพร้อมกันคือจำนวนงานที่รันในเวลาเดียวกัน ผลคูณต้องไม่เกิน CPU ที่จัดสรร และควรเผื่อไว้ให้ระบบกับการอ่านเขียนข้อมูล

ตรวจสอบสถานะของคิว เวลา หน่วยความจำ และคำขอที่เกี่ยวข้องกับ GPU ในคลัสเตอร์ต่างๆ ก่อนที่จะมีการปรับขนาดระบบ ประสิทธิภาพการประมวลผลและการใช้หน่วยความจำอาจลดลงเมื่อมีการรองรับการประมวลผลหลายๆงานพร้อมกัน โดยเฉพาะเมื่อมีการแข่งขันกันในด้านการจัดเก็บข้อมูล หน่วยความจำของ GPU หรือ CPU

7. ทดลองชุดเล็กก่อนส่งงานทั้งชุด

7.1 ทดลองกับตัวอย่างขนาดเล็ก

ในส่วนของการทดลองและการกำหนดเวลา ให้ตั้งค่าขนาดของตัวอย่างที่จะนำมาทดลอง จากนั้นเริ่มการทดลองจริง และเปิดโปรแกรมที่เลือกไว้ ด้วยวิธีนี้ เราจะสามารถรันโปรแกรมที่เลือกไว้ได้ และยังสามารถใช้ทรัพยากรของฮอสต์ที่เลือกไว้ได้อีกด้วย.

การทบทวนผลลัพธ์ การวิเคราะห์ผลลัพธ์ และบันทึกต่างๆ ผลการประเมินนั้นสะท้อนถึงตัวอย่างและการตั้งค่าที่กำหนดไว้เท่านั้น ไม่ได้สะท้อนถึงการจัดเรียงข้อมูล การเตรียมข้อมูล การโอนข้อมูล หรือการส่งออกข้อมูลแต่อย่างใด ควรทำการทดลองอีกครั้งหลังจากที่ปรับเปลี่ยนเครื่องมือ โมเดล หรือตัวเลือกต่างๆแล้ว.

เปิดท่าจับของลิแกนด์ที่สำเร็จหนึ่งตัว และอ่านบันทึกต้นฉบับของตัวที่ล้มเหลว ลิแกนด์ขนาดเล็กเพียงตัวเดียวอาจใช้ประมาณเวลาของคลังที่มีโมเลกุลใหญ่จำนวนมากได้ไม่ดี จดจำนวนตัวอย่างและจำนวนงานที่รันพร้อมกัน เผื่อเวลารอคิว ถ่ายโอน และส่งออกแยกต่างหาก

7.2 ส่งงานทั้งชุด

ในส่วนของ “Tasks and Progress” ให้ตรวจสอบข้อมูลต่างๆ เช่น ข้อมูลที่เตรียมไว้ไว้ล่วงหน้า ตัวรับข้อมูล ต้นทุน และทรัพยากรต่างๆ จากนั้นจึงส่งคำขอใหม่ไป จากนั้นเปิดข้อมูลการตั้งค่าที่เก็บไว้ เพื่อตรวจสอบการตั้งค่าจริงๆ

ดูข้อมูลเกี่ยวกับงานที่เสร็จสิ้นแล้ว งานที่ล้มเหลว และงานที่ยังค้างอยู่ เปิดไฟล์บันทึกการทำงาน ไฟล์บันทึกข้อมูลต่างๆ เพื่อหาสาเหตุของปัญหา เริ่มต้นการทำงานใหม่เมื่อมีการเปลี่ยนแปลงการตั้งค่าต่างๆ เพื่อให้ผลลัพธ์จากสถานการณ์ที่แตกต่างกันยังคงแยกกันอยู่

7.3 พัก ยกเลิก หรือกู้งานคำนวณ

เมื่อพักงาน ตัวรันจะไม่รับงานใหม่ แต่งานที่กำลังทำอยู่จะดำเนินต่อ ให้เริ่มต่อเมื่อพร้อม การยกเลิกงานที่เหลือจะไม่ลบผลที่เขียนไว้แล้ว

ลองใหม่เฉพาะงานที่ล้มเหลวและจำเป็นต้องรันซ้ำ โดยเก็บผลที่สำเร็จและประวัติไว้ หากเครือข่ายขาดหรือไม่ทราบสถานะ ให้เชื่อมต่อใหม่และรีเฟรชงานเดิมแทนการส่งซ้ำ ตัวรันอิสระทำงานต่อได้หลังปิดหน้าต่าง ส่วนการพักเครื่อง ปิดเครื่อง หรือถูกระบบคิวหยุดต้องจัดการแยกกัน

8. คัดกรองผลและสร้างรอบถัดไป

8.1 เลือกรายการที่จะตรวจสอบ

เลือกการแข่งขันที่คุณสนใจ จากนั้นใช้ตัวกรองเพื่อเลือกผลการแข่งขันที่คุณต้องการ ไม่ควรเพียงแค่ดูคะแนนในตอนแรกเท่านั้น แต่ควรดูข้อมูลเกี่ยวกับรูปแบบการแข่งขัน ต้นกำเนิดของผลการแข่งขัน และตัวชี้วัดต่างๆด้วย

เงื่อนไขทั้งหมดควรมีผลบังคับกับท่าที่เหมือนกันทั้งหมด ไม่ควรนำวิธีการประเมินผลที่ไม่เกี่ยวข้องกันมารวมกัน การจัดลำดับความสำคัญของโครงสร้างต่างๆนั้นจำเป็นต้องมีการศึกษาโดยเฉพาะ ส่วนเรื่องการผูกพันและกิจกรรมต่างๆนั้น จำเป็นต้องมีหลักฐานที่ชัดเจนด้วย

8.2 ลดรายการซ้ำโดยรักษาความหลากหลาย

ควรกำหนดให้มีตัวแทนเพียงหนึ่งคนต่อพ่อแม่ หรือจำกัดจำนวนตัวแทนที่สามารถมีได้ ตามความเหมาะสม เมื่อมีความแตกต่างระหว่างสถานะการทำงานของโค้ดต่างๆ ควรหลีกเลี่ยงการรวมโค้ดเหล่านั้นเข้าด้วยกันตั้งแต่เนิ่นๆ

ตรวจสอบจำนวนข้อมูลที่ผ่านการกรองแล้ว และเลือกข้อมูลที่จะนำไปใช้ต่อไป สำหรับคะแนนที่สูงผิดปกติ หรือข้อมูลที่ไม่สมเหตุผล ควรตรวจสอบประวัติการป้อนข้อมูลและข้อมูลการเตรียมข้อมูลก่อนการนำข้อมูลเหล่านั้นมาใช้

8.3 สร้างรอบใหม่

ในการประชุมครั้งนี้ ให้เลือกข้อมูลที่เสร็จสมบูรณ์แล้ว กำหนดเงื่อนไขต่างๆ และนับจำนวนผู้สมัครรอบต่อไป ให้ตั้งชื่อสำหรับรอบถัดไป และเลือกเครื่องมือที่เหมาะสมสำหรับการประมวลผลข้อมูลในรอบนั้นด้วย ให้เก็บข้อมูลที่เตรียมไว้ในรอบแรกไว้ หรือเลือกโค้ดที่ดีที่สุดจากรอบนี้มาใช้แทน.

กรุณาเลือกไดเรกท์สำหรับการสร้างรอบใหม่นี้ไว้ก่อน จากนั้นตรวจสอบข้อมูลที่ใช้ในการสร้างรอบนี้ก่อนที่จะนำไปใช้งานหรือส่งเข้าสู่ระบบ การสร้างรอบใหม่ไม่ได้ทำให้การคำนวณเริ่มต้นขึ้นเลย

ลองตั้ง Vina affinity ≤ −7.0 kcal/mol แล้วดูจำนวนที่ผ่านก่อนสร้างรอบใหม่ หากเปลี่ยนเป็น GNINA ให้เลือกช่องคะแนนและทิศทางใหม่ เช่น CNNscore ยิ่งสูงยิ่งดี ก่อนส่งงานให้ตรวจตัวรับ จำนวนลิแกนด์ และโปรแกรมของรอบนั้น

9. ส่งออกผลและย้ายโปรเจกต์

9.1 ส่งออกผลสำหรับผู้ร่วมงาน

ในส่วน “Structures and Results Export” ให้เลือกผลลัพธ์ที่ต้องการส่งออกมาในรูปแบบ CSV หรือเฉพาะข้อมูลที่ตรวจสอบแล้วเท่านั้น ให้เลือกข้อมูลที่จำเป็นต้องส่งออกมา เช่น โครงสร้าง ข้อมูลเกี่ยวกับตัวรับ และรายงานต่างๆ ให้เลือกข้อมูลที่มีความจำเป็นต้องส่งออกมา โดยเลือกทั้งหมดข้อมูลที่เกี่ยวข้อง.

ตรวจสอบความสำเร็จและความล้มเหลวในรายงานดังกล่าวด้วยนะครับ การแปลงข้อมูล SDF อาจไม่ประสบความสำเร็จได้ หากไม่มีข้อมูลการจัดเรียงอะตอมที่เชื่อถือได้ ดังนั้นควรตรวจสอบข้อมูล PDBQT ที่ยังคงอยู่ในรายงานด้วยนะครับ อย่าให้ข้อมูลที่หายไปถูกนับเป็นข้อมูลที่ได้รับการส่งมอบไปเลยครับ การส่งออกข้อมูลขนาดใหญ่สามารถใช้ฟังก์ชันการหยุดการทำงานและการกู้คืนข้อมูลได้ด้วยครับ.

หากปิดโปรแกรมระหว่างส่งออก ให้เปิดโครงการเดิม เลือกรายการส่งออกรายการเดิมและตรวจโฟลเดอร์ปลายทางก่อนทำต่อ หากพบไฟล์ขัดแย้ง ให้เปิดดูไฟล์เดิมก่อนแก้ไข ลิแกนด์หนึ่งตัวอาจมีหลายท่าจับ จำนวนแถว จำนวนลิแกนด์ และจำนวนไฟล์จึงอาจต่างกัน

9.2 สร้างแพ็กเกจโปรเจกต์สำหรับย้ายเครื่อง

ลองดูเนื้อหาในแพ็กเกจก่อนใช้เสมอ โดยรวมถึงข้อมูลจากการป้อนข้อมูลและผลลัพธ์จากการทำงานต่างๆ หากจำเป็น จากนั้นเลือกไดเรกท์ที่ต้องการ แล้วออกแบบแฟ้กต์ข้อมูลนั้นออกมา.

บนคอมพิวเตอร์อีกเครื่องหนึ่ง ให้เลือกไฟล์ Project.htvs.json ของแพ็กเกจนั้น จากนั้นดูผลการทดลองก่อนนำไฟล์นั้นมาใช้เป็นโปรเจกต์แยกต่างหาก ให้ปรับแต่งซอฟต์แวร์ การยืนยันตัวตน และเส้นทางการทำงานของโปรเจกต์นั้นอีกครั้ง เก็บผลการทดลองที่ผ่านมาไว้เพื่อเปรียบเทียบกัน และสร้างโปรเจกต์ใหม่จากโปรเจกต์ที่นำมาใช้

9.3 จัดการพื้นที่จัดเก็บ

ตรวจสอบพื้นที่ของไฟล์ต่างๆ และข้อมูลที่เกี่ยวข้องกับไฟล์เหล่านั้นในส่วนของ “Projects” และ “Storage”。 ตรวจสอบว่าไฟล์เหล่านั้นมีไว้เพื่ออะไร และมีการใช้งานอย่างไรก่อนที่จะลบข้อมูลที่เกี่ยวข้องออกไป。 ควรลบเฉพาะข้อมูลที่ปรากฏในส่วนของ “Preview” เท่านั้น.

ให้ปฏิบัติตามแผนสำรองสำหรับข้อมูลการนำเข้าไฟล์ต่างๆ และบันทึกเกี่ยวกับผลลัพธ์และข้อมูลการเตรียมการต่างๆ โดยสามารถจัดเรียงโครงการต่างๆเป็นชุดๆได้ เมื่อจำเป็นต้องนำข้อมูลต่างๆไปใช้จริงๆ.

10. เตรียมระบบสำหรับพลวัตโมเลกุล

10.1 เลือกจุดเริ่มต้น

Open Molecular Dynamics · GROMACS. สามารถสร้างโมเดลจากโมเลกุลที่มีอยู่ในรูปแบบ PDB ได้ หรือจะเลือกใช้ข้อมูลพิกัด ทอพอไลติก หรือ TPR ที่มีอยู่แล้วก็ได้.

สำหรับผลลัพธ์การเชื่อมต่อนี้ ให้สร้างข้อมูล SDF ของโมเลกุลที่จะเชื่อมต่อกัน จากนั้นตรวจสอบตัวตนและพิกัดของอะตอมต่างๆ จากนั้นจึงดำเนินการปรับแต่งพารามิเตอร์ของลิแกนด์ต่อไป คือ การกำหนดฟิลด์แรง การชาร์จของลิแกนด์ และองค์ประกอบของลิแกนด์ก่อนอื่น

10.2 เตรียมลิแกนด์และประกอบคอมเพล็กซ์

ในส่วนของพารามิเตอร์ของ Ligand ให้เลือก ACPYPE/AmberTools ที่ถูกกำหนดไว้แล้ว ร่วมกับ GAFF หรือ GAFF2 นอกจากนี้ ยังต้องป้อนค่าที่เป็นจำนวนเต็มสำหรับค่าความชื้นของสาร และวิธีการกำหนดค่าความชื้นด้วย จากนั้นตรวจสอบข้อมูลที่ป้อนเข้ามา และเตรียมงานเพื่อการทดลอง โดยส่งงานไปพิจารณาหลังจากการตรวจสอบเรียบร้อยแล้ว จากนั้นก็ตรวจสอบผลลัพธ์ที่ได้จากการทดลองด้วย.

ปัจจุบัน การสร้างโครงสร้างของสารประกอบนั้นมีความซับซ้อน โดยมีโปรตีน AMBER และไลแกนด์ GAFF/GAFF2 อยู่ในโครงสร้างนี้ด้วย ให้เลือกโปรตีน GRO/TOP และไลแกนด์ ITP มาทำการตรวจสอบระบบพิกัด ลำดับอะตอม และความเข้ากันของฟอร์ซฟิลด์ ก่อนที่จะสร้างโครงสร้างของสารประกอบนั้นขึ้นมา จากนั้นจึงส่งข้อมูลนั้นไปยังระบบเพื่อการกำหนดค่าเกี่ยวกับสารละลาย และการตรวจสอบความถูกต้องของข้อมูลต่างๆ

10.3 เติมตัวทำละลายและไอออน

  1. เลือกโปรตีนมาตรฐานที่มี PDB กำหนดไว้ หรือเลือกโปรตีนที่มีโครงสร้างที่ชัดเจน หรือโปรตีนที่มีโครงสร้างครบถ้วนอยู่แล้ว.
  2. กรุณากำหนดเครื่องที่จะใช้ในการประมวลผล, ไดเรกท์ของระบบ และข้อมูลที่จะนำมาใช้ จากนั้นตรวจสอบโครงสร้างต่างๆ รวมถึงฟิลด์ต่างๆ ที่ถูกติดตั้งไว้ด้วย.
  3. เลือกฟิล드เดอร์ที่มีอยู่แล้ว และโมเดลของน้ำที่เข้ากันได้กับฟิลด์เดอร์นั้นๆ กำหนดรูปร่างของกล่องที่ใช้ในการทดลอง ระยะห่างระหว่างสารละลายกับขอบของกล่อง ความเข้มข้นของเกลือ ไอออนต่างๆ และการทำงานของปัจจัยอื่นๆ ที่เกี่ยวข้องด้วย.
  4. ตรวจสอบการตั้งค่าทั้งหมดเกี่ยวกับปลายทางการประมวลผลข้อมูล และการปรับแต่งค่าต่างๆ จากนั้นบันทึกแผนการสร้างโปรแกรมไว้ก่อน แล้วดูผลลัพธ์จากการปรับแต่งดูก่อน.
  5. กรุณาส่งไฟล์ที่สร้างขึ้นมาเพื่อตรวจสอบก่อน จากนั้นจึงนำผลลัพธ์ที่ได้ไปใช้ในกระบวนการทำงานแบบหลายขั้นตอน หรือการนำไฟล์ MD มาใช้.

ระยะในกล่องระบบ MD ใช้หน่วย nm ส่วนกล่องค้นหาสำหรับด็อกกิงใช้ Å สำหรับโปรตีนเยื่อหุ้ม กรดอะมิโนนอกมาตรฐาน หรือโคแฟกเตอร์ที่ซับซ้อน ให้เตรียมด้วยวิธีเฉพาะที่เหมาะสมแล้วนำเข้าระบบ ระบบที่สร้างแล้วยังต้องลดพลังงานและปรับสมดุล

10.4 นำเข้าระบบที่มีอยู่

ในส่วนของ “Import or Connect System” ให้เลือก TPR หรือพิกัดที่มีอยู่แล้ว รวมถึงโทลโลจีและ MDP ด้วย จากนั้นกำหนดตำแหน่งของไดเรกท์และเส้นทางการเข้าถึงไฟล์ต่างๆ บนฮอสต์เป้าหมาย หากจำเป็น ก็สามารถเพิ่มพิกัดสำหรับการสร้างดัชนี ตำแหน่งที่จำเป็นสำหรับการควบคุม และจุดตรวจสอบได้ด้วย.

ตรวจสอบ GROMACS ก่อน จากนั้นก็ตรวจสอบระบบของเครื่องคอมพิวเตอร์ และนำไฟล์ GROMACS มาใช้เป็นงานที่สามารถส่งเข้าระบบได้ ควรอ่านข้อมูลที่ได้จากการอ่านข้อมูลเข้ามา และผลลัพธ์จากการประมวลผลก่อนที่จะส่งไฟล์ไปยังระบบ ควรเลือกการตรวจสอบเฉพาะในกรณีที่คุณกำลังทำการทดลองภายใต้การควบคุมของบุคคลภายนอกเท่านั้น.

11. ตั้งค่าและรันการจำลองหลายขั้นตอน

11.1 สร้างเวิร์กโฟลว์และชุดจำลองอิสระ

สร้างเวิร์กโฟลว์และระบุจำนวนรอบจำลองอิสระกับค่า seed เริ่มต้นตามต้องการ ตรวจข้อมูลนำเข้า ไฟล์ MDP และทรัพยากรของแต่ละขั้นตอน ได้แก่ EM, NVT, NPT และการจำลองช่วงเก็บข้อมูล (production)

มีการตรวจสอบขั้นตอนการทำงานโดยอัตโนมัติ เพื่อให้แน่ใจว่าขั้นตอนการทำงานนั้นดำเนินไปอย่างราบรื่น ไม่ควรนำขั้นตอนการทำงานเหล่านี้มาใช้ในกระบวนการปรับแต่งหรือการผลิตของคุณเอง ควรตรวจสอบระยะเวลาการทำงาน อุณหภูมิ และความดันที่ใช้ในการทำงาน รวมถึงข้อจำกัดต่างๆที่มีอยู่ จากนั้นจึงเก็บขั้นตอนการทำงานเหล่านี้ไว้ก่อนที่จะส่งออกไปใช้จริง

11.2 แก้ไข MDP และตรวจสอบการเตรียมก่อนรัน

ในแปลงพารามิเตอร์ของ GROMACS ให้ค้นหาข้อมูลตามชื่อพารามิเตอร์โดยตรง แล้วตรวจสอบค่าต่างๆ เช่น integrator, dt, nsteps, ความถี่ของการแสดงผล, การควบคุมข้อมูล และข้อจำกัดต่างๆ ค่าของ time step และจำนวนขั้นตอนจะกำหนดถึงความยาวของการประมวลผลโดยรวม.

เมื่อนำเข้าไฟล์ MDP ให้ตรวจคีย์ซ้ำและเก็บหมายเหตุที่มีประโยชน์ อ่านคำเตือนจากการเตรียมก่อนรันแล้วแก้ที่ต้นเหตุ อย่าเพิ่ม maxwarn เพื่อข้ามปัญหาที่ยังไม่ได้แก้

11.3 เริ่มขั้นตอนและจัดสรรทรัพยากร

ก่อนเริ่มขั้นตอนปัจจุบันหรือถัดไป ให้ตรวจโฮสต์ ทรัพยากรของระบบคิว และการตั้งค่า mdrun ให้จำนวนเธรด PME GPU และทรัพยากรที่ขอสอดคล้องกัน ใช้บันทึกจากการทดสอบสั้น ๆ เพื่อเลือกทรัพยากรสำหรับงานยาว

โปรดตรวจสอบผลลัพธ์และสถานะของระบบก่อนที่จะเริ่มขั้นตอนต่อไป โปรดแก้ไขขั้นตอนที่ล้มเหลวหรือหยุดชะงักไว้ แทนที่จะข้ามขั้นตอนที่จำเป็นไป

11.4 หยุด รันต่อ และตรวจสอบบันทึก

บันทึกจุดตรวจสอบก่อนหยุดอย่างเป็นระเบียบ จากนั้นรันต่อจากจุดตรวจสอบของงานเดิมและดูในบันทึกว่าเริ่มต่อที่ขั้นใด ค่าขีดจำกัดคือหมายเลขขั้นสุดท้าย ไม่ใช่จำนวนขั้นที่จะเพิ่ม

อ่านและตรวจสอบบันทึกต่างๆ หากมีข้อบกพริดเกิดขึ้น หรือพลังงานไม่เป็นปกติ หรือโครงสร้างต่างๆดูไม่สมเหตุผล ให้ตรวจสอบระบบและการตั้งค่าต่างๆ และหากจำเป็นก็ให้กลับไปยังขั้นตอนการเตรียมหรือการปรับสมดุลของระบบอีกครั้ง การเปลี่ยนจากขั้นตอนหนึ่งไปยังอีกขั้นตอนหนึ่งนั้นมีขั้นตอนการทำงานที่แตกต่างกันไปด้วย.

12. ตรวจสอบวิถีและฟังก์ชันคลื่น

12.1 ตั้งค่าการวิเคราะห์วิถี

เมื่อเส้นทางการเคลื่อนที่ไม่สามารถเขียนได้อีกต่อไป ให้เพิ่มข้อมูลนั้นไว้เป็นแหล่งข้อมูลสำหรับการวิเคราะห์แบบอ่านได้เท่านั้น เลือกตัวเลือก TPR และ XTC/TRR; หากจำเป็น ก็เพิ่มข้อมูล EDR และบันทึกต่างๆ เข้ามาด้วย ตรวจสอบข้อมูลเกี่ยวกับเส้นทางการเคลื่อนที่ กลุ่มอะตอม และคำศัพท์ที่เกี่ยวข้องกับพลังงานอีกครั้ง.

เลือกช่วงเวลาที่จะใช้ในการวิเคราะห์ รวมถึงช่วงเวลาที่ใช้ในการประกอบข้อมูลเข้ากับโครงสร้างข้อมูลด้วย จากนั้นเลือกตัวเลือกต่างๆ เช่น RMSD, RMSF, รัศมีการเคลื่อนที่, SASA, พันธะน้ำ, ระยะห่างในการสัมผัส หรือพลังงานต่างๆ จากนั้นเลือกตัวเลือกต่างๆ เช่น PCA, การจัดกลุ่มข้อมูล หรือความหนาแน่น ตามคำถามวิจัยและเครื่องมือที่มีอยู่

ดูตัวเลือกของอะตอมที่คุณกำหนดเองก่อนนะครับ. ค่าที่ใช้ในการคำนวณ RMSD ของligand หลังจากการปรับแต่งโปรตีน และ RMSD ของligand หลังจากการปรับแต่งligand ก็แตกต่างกันไปเช่นกัน; จงบันทึกค่าที่ใช้ในการคำนวณนั้นไว้ด้วยครับ.

วิถีตั้งแต่ 0 ถึง 20 ns ที่บันทึกทุก 10 ps จะมี 2,001 เฟรมเมื่อนับจุดเริ่มและจุดจบ หากวิเคราะห์ทุก 100 ps จะได้กราฟ 201 จุด เมื่อพบ FAILED ให้เทียบขั้นสุดท้ายในบันทึกการจำลอง เวลาของเฟรมสุดท้าย และข้อผิดพลาดของสคริปต์ก่อนตัดสินใจรันต่อ

12.2 ดู เปรียบเทียบ และส่งออกผลวิเคราะห์

ควรอ่านข้อมูลเกี่ยวกับวิธีการทำงานและแหล่งที่มาของข้อมูลก่อนที่จะพิจารณาข้อมูลในรูปแบบกราฟหรือข้อมูลที่เกี่ยวข้องกับเส้นทางการเคลื่อนที่ของข้อมูลนั้นๆ ควรตรวจสอบข้อมูลจริงที่อยู่ด้านหลังจุดที่ไม่ธรรมดานั้นด้วย ไม่ควรตัดสินจากรูปแบบของเส้นโค้งเพียงอย่างเดียว.

ให้ทำการบันทึกข้อมูลต่างๆที่เกี่ยวข้องกับงาน MD รวมถึงผลการวิเคราะห์ต่างๆ จากนั้นเพิ่มข้อมูลอีกสองถึงแปดรายการเพื่อใช้ในการเปรียบเทียบข้อมูลต่างๆ ให้ตรวจสอบเวลาที่ใช้ในการดำเนินการ การจัดเรียงข้อมูล และตัวเลือกต่างๆก่อนที่จะเปรียบเทียบข้อมูลต่างๆ นอกจากนี้ ควรส่งออกข้อมูลที่เกี่ยวข้องในรูปแบบ JSON หากจำเป็น และควรเก็บข้อมูลที่แตกต่างกันในแต่ละชุดข้อมูลไว้ด้วย.

12.3 ตรวจสอบข้อมูลนำเข้าของ Multiwfn

ในหน้าตรวจข้อมูลนำเข้าของ Multiwfn ให้เลือกไฟล์ฟังก์ชันคลื่นบนเครื่องนี้หรือโฮสต์ SSH การตรวจรองรับ FCH/FCHK, MWFN แบบเฟรมเดียว และไฟล์ GTO WFN/WFX แบบไม่เป็นแม่เหล็กที่โปรแกรมรองรับ

โปรดทบทวนข้อมูลเกี่ยวกับอะตอม อิเล็กตรอน โครงสร้างออร์บิทัล และความหนาแน่นของสารต่างๆก่อน จากนั้นจึงจัดการกับข้อมูลที่ขาดหายหรือไม่สอดคล้องกัน ควรติดตั้งหรือตรวจสอบการใช้งานของ Multiwfn บนโฮสต์ที่ต้องการด้วย นอกจากนี้ การกำหนดตำแหน่งของโมเลกุลหรือกรอบการแสดงผลของ MD ก็สามารถช่วยให้ได้ข้อมูลทางกายภาพที่จำเป็นสำหรับการคำนวณเคมีควอนตัมได้ โดยสามารถสร้างฟลักซ์คลื่นขึ้นมาได้ก่อนที่จะนำข้อมูลนั้นมาใช้ในการคำนวณต่อไป.

12.4 ตั้งค่าการวิเคราะห์และดูความหนาแน่นสามมิติ

กรุณากรอกเส้นทางของ Multiwfn วิธีการดำเนินการ จำนวนเธรดของ CPU และเวลาที่กำหนดไว้ เพื่อประเมินผลการดำเนินการก่อนการป้อนข้อมูลจริง ตรวจสอบสถานะของระบบ วิธีการดำเนินการ และใบอนุญิยาตของโปรแกรม จากนั้นจึงบันทึกไฟล์ไว้ก่อนที่จะรันโปรแกรมจริง กรุณาส่งไฟล์เหล่านี้แยกกันเมื่อพร้อมที่จะดำเนินการ.

สำหรับค่าความหนาแน่น ให้กำหนดตำแหน่งเริ่มต้นของระเบียบรูป ระยะห่างระหว่างจุดต่างๆ และจำนวนจุดต่างๆ ในหน่วยโบลต์ ตรวจสอบว่าการครอบคลุมของพื้นที่นั้นเพียงพอหรือไม่ และจำนวนจุดทั้งหมดเท่าไหร่ จากนั้นนำผลลัพธ์มาใช้ และกำหนดค่าขีดจำกัดของ isosurface ให้เหมาะสม.

เลือกวิธีที่ใช้ได้หลังตรวจไฟล์ การคำนวณประจุแบบ Mulliken และ Löwdin ต้องมีข้อมูลชุดฐาน การเปลี่ยนนามสกุลไฟล์ไม่ได้เพิ่มข้อมูลนี้

12.5 ส่งออกและเก็บถาวรผลวิเคราะห์

สามารถส่งออกไฟล์คิวบ์ ไฟล์บันทึกข้อมูลต่างๆ ผลลัพธ์จากการประมวลผล และข้อมูลเกี่ยวกับการตั้งค่าต่างๆ ไปยังตำแหน่งที่ต้องการได้ นอกจากนี้ ยังสามารถหยุดการทำงานของไฟล์เหล่านี้ชั่วคราวได้ และสามารถเริ่มการทำงานอีกครั้งได้ในภายหลังอีกด้วย.

จำเป็นต้องนำไฟล์ที่เก็บข้อมูลมาเพื่อการตรวจสอบข้อมูลในสภาพการใช้งานแบบออฟไลน์ ควรตั้งชื่อแยกสำหรับไฟล์ต่างๆ หรือสามารถซ่อนหรือลบไฟล์เหล่านั้นได้ ควรยังคงสามารถนำไฟล์เหล่านั้นกลับมาใช้งานได้อีกครั้ง การจัดการไฟล์เหล่านี้ควรแยกออกจากกระบวนการคำนวณต้นฉบับ ควรตรวจสอบให้ดีก่อนที่จะลบไฟล์เหล่านั้นออก

13. เชื่อมต่อโทรศัพท์กับคอมพิวเตอร์หรือเซิร์ฟเวอร์

จงเชื่อมต่ออุปกรณ์ต่างๆเข้ากับโปรแกรมนี้ก่อนที่จะตรวจสอบความคืบหน้า การจดบันทึก หรือการแก้ไขแผนการต่างๆที่ยังค้างอยู่ในโทรศัพท์.

13.1 เชื่อมต่อบริการและเข้าสู่ระบบ

เปิดบริการการตรวจสอบบนคอมพิวเตอร์ และตรวจสอบให้แน่ใจว่าทีวีสามารถเชื่อมต่อเข้าถึงได้ ให้ใช้ที่อยู่ที่ได้มาจากผู้ดูแลระบบหรือผู้จัดการ ไม่ใช่ที่อยู่ SSH ของเซิร์ฟเวอร์.

  1. เปิดบัญชีและอุปกรณ์ของคุณได้จากแท็บ “Profil” หรือ “Settings”
  2. กรุณากรอกที่อยู่ของบริการที่กำหนดไว้ และเชื่อมต่อไปเลย.
  3. กรุณากรอกอีเมลและรหัสผ่าน จากนั้นจึงลงชื่อเข้าสู่ระบบ.
  4. หากเปิดให้ลงทะเบียน ให้สร้างบัญชีด้วยชื่อที่แสดง อีเมล และรหัสผ่าน ยืนยันอีเมลหากระบบขอ แล้วกลับไปยังหน้าเข้าสู่ระบบ

ตรวจสอบ: ฟอร์มการลงทะเบียนปิดลง และบัญชีปัจจุบันรวมถึงอุปกรณ์สำหรับการตรวจสอบต่างๆ จะปรากฏขึ้นมา หากไม่มีอุปกรณ์ใดที่สามารถเชื่อมต่อเข้ากับบัญชีได้ ให้ดำเนินการเชื่อมต่ออุปกรณ์เหล่านั้นต่อไป.

เมื่อพบปัญหา: ตรวจสอบที่อยู่และการทำงานของบริการก่อนด่วน. เมื่อช่วงการใช้งานสิ้นสุดลง ให้ลองเข้าสู่ระบบอีกครั้ง. หากแอปพลิเคชันเสนอให้ส่งอีเมลเพื่อยืนยันการเข้าสู่ระบบอีกครั้ง ให้ตรวจสอบกล่องจดหมายและโฟลเดอร์ขยะของคุณด้วยการส่งอีเมลนั้นไม่สามารถแก้ไขปัญหาเกี่ยวกับบริการอีเมลที่ไม่ได้ตั้งค่าไว้ได้. การเชื่อมต่อแบบ read-only นั้นใช้สำหรับการเข้าถึงข้อมูลในเครื่องคอมพิวเตอร์ของเครื่องนั้นเท่านั้น ไม่ใช่สำหรับการเชื่อมต่อกับคอมพิวเตอร์ที่อยู่ไกลออกไป.

13.2 จับคู่ด้วยรหัสใช้ครั้งเดียว

  1. สร้างรหัสการจับคู่ใหม่ในตัวควบคุมการทำงานของคอมพิวเตอร์ ตรวจสอบให้แน่ใจว่าทั้งสองอุปกรณ์ใช้ที่อยู่บริการเดียวกัน
  2. ในหน้าผู้ใช้และอุปกรณ์ของโทรศัพท์ ให้คุณป้อนรหัสและทำการเชื่อมต่ออุปกรณ์เข้ากับโทรศัพท์ของคุณ.
  3. บนคอมพิวเตอร์ ให้ตรวจสอบบัญชียอดที่ต้องการใช้งาน และยืนยันการเชื่อมต่อดังกล่าว.
  4. รีฟันท์อุปกรณ์ต่างๆบนโทรศัพท์ของคุณด้วย.

ตรวจสอบ: คอมพิวเตอร์นั้นอยู่ภายใต้การควบคุมของอุปกรณ์ตรวจสอบต่างๆ การร้องขอการเชื่อมต่อเพียงแค่ผ่านโทรศัพท์นั้นยังไม่เพียงพอ คอมพิวเตอร์จำเป็นต้องยืนยันการเชื่อมต่อด้วยตัวเอง

เมื่อพบปัญหา: หากโค้ดเดิมไม่ถูกต้อง ใช้ไม่ได้ หรือหมดอายุแล้ว ให้สร้างโค้ดใหม่แทน หากการยืนยันยังไม่เสร็จ ให้ตรวจสอบบัญชีที่ขอใช้งาน และที่อยู่ของบริการบนแต่ละอุปกรณ์อีกครั้ง.

13.3 เลือกอุปกรณ์ที่จะติดตาม

  1. ลองหาโปรแกรมคอมพิวเตอร์นั้นมา แล้วตรวจสอบชื่อของโปรแกรม นอกจากนั้นยังต้องตรวจสอบเวลาที่มีการติดต่อกับโปรแกรมนั้น และเวลาที่มีการรายงานสถานะของโปรแกรมด้วย.
  2. เปิดอุปกรณ์นั้นออกมา แล้วกลับไปที่ Progress อีกครั้ง.
  3. เพื่อเปลี่ยนไปใช้เครื่องคอมพิวเตอร์อื่น ให้เปิดหน้าผลการดำเนินการของบัญชี แล้วเลือกเครื่องคอมพิวเตอร์อื่นมาแทน.

ตรวจสอบ: อุปกรณ์ที่เลือกไว้ได้รับการระบุไว้อย่างชัดเจน และหน้าผลการประมวลผลจะแสดงข้อมูลเกี่ยวกับการประมวลผลที่เกิดขึ้นบนอุปกรณ์นั้น รวมถึงข้อมูลเกี่ยวกับการประมวลผลบนเซิร์ฟเวอร์ที่เชื่อมต่อกับอุปกรณ์นั้นด้วย ให้ตรวจสอบข้อมูลเกี่ยวกับการประมวลผลที่เกิดขึ้นบนอุปกรณ์หรือเซิร์ฟเวอร์นั้นๆ.

เมื่อพบปัญหา: โปรดรีเฟอร์รายการของอุปกรณ์ก่อนดูก่อนนะครับ หากอุปกรณ์ใดไม่เชื่อมต่ออยู่ ให้ตรวจสอบเรื่องการหลับตลอดของอุปกรณ์นั้น รวมถึงตัวแทนที่คอยตรวจสอบการทำงานของอุปกรณ์ต่างๆ และสภาพของเครือข่ายด้วย การที่อุปกรณ์ใดไม่เชื่อมต่อไม่ได้หมายความว่าการประมวลผลของอุปกรณ์นั้นล้มเหลวหรอกนะครับ ปัญหาในการเชื่อมต่อของอุปกรณ์หนึ่งไม่ได้หมายความว่าอุปกรณ์ทั้งหมดจะไม่สามารถทำงานได้เลยครับ.

13.4 ตรวจสอบสิทธิ์และเลิกจับคู่

  1. ตรวจสอบอุปกรณ์ต่างๆให้ดี รวมถึงตรวจสอบข้อมูลเกี่ยวกับสิทธิ์การใช้งานและวันหมดอายุของบัตรที่เกี่ยวข้องด้วย.
  2. โปรแกรมนี้สามารถใช้งานได้โดยมีสิทธิ์ในการอ่านข้อมูลต่างๆ หากต้องการแก้ไขแผนการหรือส่งข้อมูลการคำนวณ ให้ขออนุญิติที่จำกัดเวลาไว้สำหรับคอมพิวเตอร์ของคุณ จากนั้นให้อัปเดตโทรศัพท์ของคุณด้วย ดูข้อมูลเพิ่มเติมในบทที่ 18.
  3. ก่อนที่จะยกเลิกการเชื่อมต่อ กรุณาย้อนส่งข้อมูลการวิจัยที่คุณต้องการเก็บไว้ก่อน จากนั้นเลือกตัวเลือก “ยกเลิกการเชื่อมต่อ” และตรวจสอบข้อมูลการยืนยันอีกครั้ง.

ตรวจสอบ: สิทธิ์การใช้งานที่อัปเดตแล้วจะสอดคล้องกับสิทธิ์ที่กำหนดไว้ในโปรแกรมคอมพิวเตอร์ หลังจากที่การเชื่อมต่อถูกยกเลิก อุปกรณ์จะหยุดส่งข้อมูลการตรวจสอบไปยังบัญชีของผู้ใช้ ตัวคำนวณที่มีอยู่จะยังคงอยู่ที่ตำแหน่งเดิมต่อไป

เมื่อพบปัญหา: ให้รีเฟอร์การอนุญาตที่หมดอายุลงบนคอมพิวเตอร์แทนการพยายามใช้ปุ่มแก้ไขที่ถูกปิดใช้งานอีกครั้ง ก่อนที่จะยกเลิกการเชื่อมต่อหรือเปลี่ยนการเชื่อมต่อ ให้เก็บข้อมูลที่จำเป็นไว้ก่อน ข้อมูลที่เก็บไว้ในระบบจะถูกลบออกตามที่แอปพลิเคชันกำหนดไว้

14. ค้นหางานและดูความคืบหน้า

14.1 ค้นหางานจากหน้าความคืบหน้า

  1. เปิดโปรแกรม/เริ่มต้นการทำงาน
  2. ใช้ตัวนับยอดการใช้งานทั้งหมด เพื่อดูรายการที่เกี่ยวข้องกับการใช้งานที่กำลังดำเนินอยู่หรือสิ่งที่จำเป็นต้องให้ความสนใจ.
  3. เลือกช่วงเวลาที่เกิดเหตุการณ์ต่างๆขึ้นมา หรือเปิดรายละเอียดของช่วงเวลานั้นขึ้นมาได้เลย. หรืออาจจะเปิดรายการทั้งหมดของช่วงเวลานั้นก็ได้.
  4. ลองเปรียบเทียบเวลาที่ใช้ในการอัปเดตด้านการประมวลผลกับเวลาที่ใช้ในการอ่านข้อมูลครั้งล่าสุดในโทรศัพท์ดูสิ. เวลาเหล่านี้เป็นตัวบ่งบอกถึงเหตุการณ์ต่างๆที่เกิดขึ้น.

ตรวจสอบ: กรุณา確認ข้อมูลเกี่ยวกับลูป โปรเจกต์ ประเภท และตำแหน่งการดำเนินการต่างๆ ข้อมูลเกี่ยวกับความคืบหน้าในปัจจุบัน หรือสถานะที่ไม่ทราบแน่ชัดนั้น หมายถึงข้อมูลล่าสุดที่มีอยู่เท่านั้น ไม่ใช่ข้อมูลเกี่ยวกับความคืบหน้าในขณะนั้นจริงๆ

เมื่อพบปัญหา: หากมีการขาดหายไปของข้อมูล ให้ตรวจสอบอุปกรณ์และค้นหาข้อมูลในส่วนของการวิจัยด้วย หากการอ่านข้อมูลเกิดข้อผิดพลาด หรือการเชื่อมต่อเกิดการหยุดชะงัก ให้รีบเชื่อมต่ออุปกรณ์อีกครั้งและอัปเดตข้อมูลใหม่ อย่าเพิ่มข้อมูลเข้ามาอีกเด็ดขาด.

14.2 กรองตามโปรเจกต์ ประเภท และสถานะ

  1. การค้นหาและวิจัยข้อมูลโดยใช้ชื่อ ชื่อโครงการ หรือรหัสประจำตัว
  2. เลือกโปรเจกต์และประเภทการประมวลผลที่ต้องการ เช่น Docking หรือ MD.
  3. สามารถกรองผลลัพธ์ตามรัฐต่างๆ ได้ และยังสามารถปรับแต่งผลลัพธ์ตามเครื่องที่ใช้ในการประมวลผล หรือการประมวลผลแบบ local/remote ได้หากจำเป็น.
  4. ลองพิมพ์ผลการค้นหาอีกครั้ง หรือลบตัวเลือกที่ไม่ต้องการออกเพื่อเริ่มต้นใหม่.

ตรวจสอบ: ขอบเขตของข้อมูลที่แสดงออกมานั้นอยู่เหนือรายการต่างๆ หากต้องการค้นหาข้อมูลในไดเรกท์ ก็จะสามารถค้นหาข้อมูลทั้งหมดในหน้าเหล่านั้นได้ ทั้งนี้ การค้นหาข้อมูลจะค้นหาข้อมูลทั้งหมดที่เกี่ยวข้องกับอุปกรณ์ที่เลือกไว้ ไม่ใช่เพียงแค่ข้อมูลที่แสดงอยู่บนหน้าเท่านั้น.

เมื่อพบปัญหา: กรุณาเลือกโปรเจกต์และประเภทที่ต้องการ หากการซิงค์ยังไม่เสร็จสมบูรณ์ ให้ตรวจสอบข้อมูลในระบบของคอมพิวเตอร์ก่อน หากการค้นหาในโหมดออฟไลน์จะครอบคลุมเฉพาะไฟล์ที่บันทึกไว้ในระบบเท่านั้น.

14.3 ตั้งช่วงเวลารีเฟรชและลองอ่านข้อมูลใหม่

  1. เลือก “ภาษาไทย” เป็นภาษาของแอปในส่วนของ “การตั้งค่า” เพื่อให้สอดคล้องกับคำแนะนำนี้.
  2. สามารถเลือกการอัปเดตได้ทุกๆ 5 วินาที, 10 วินาที, 15 วินาที หรือ 30 วินาที; หรือสามารถอัปเดตได้ทุกๆ 1 นาที, 2 นาที หรือ 5 นาที; หรือสามารถอัปเดตได้ด้วยตนเองก็ได้.
  3. รีเฟรชงานบนหน้าหลักเพื่ออ่านข้อมูลทันที หากผลหรือบันทึกไม่โหลด ให้ลองอ่านใหม่ในหน้ารายละเอียด

ตรวจสอบ: เป็นการอัปเดตเวลาการอ่านข้อมูลครั้งล่าสุดที่ประสบความสำเร็จแล้ว ในโหมด manuel จะหยุดการอ่านข้อมูลที่กำหนดไว้โดยอัตโนมัติ การเปลี่ยนแปลงช่วงเวลาการอ่าน การปิดหน้าจอ หรือการล็อกโทรศัพท์ ไม่มีผลต่อการหยุดการทำงานของการอ่านข้อมูลจากระยะไกล

เมื่อพบปัญหา: หากเวลาที่บันทึกไว้ยังคงเหมือนเดิม ให้พยายามหาข้อความที่เกี่ยวข้องกับการเชื่อมต่อนั้นๆ จากนั้นยืนยันข้อมูลของอุปกรณ์ก่อนที่จะพยายามอีกครั้ง หน้าที่ถูกบันทึกไว้ก่อนหน้านี้จะยังคงอยู่ในรูปแบบของข้อมูลอ้างอิงเท่านั้น.

14.4 กรองการแจ้งเตือนและเปิดงานที่เกี่ยวข้อง

  1. หลังจากที่ลงชื่อเข้าใช้และทำการเชื่อมต่อแล้ว ให้เปิดหน้า “Message” แล้วรีเฟอร์รายการสถานะของข้อความต่างๆ.
  2. สามารถกรองข้อมูลตามสถานะของข้อความหรือประเภทของเหตุการณ์ต่างๆ เช่น ความล้มเหลว การเสร็จสมบูรณ์ หรือการเปลี่ยนแปลงของการเชื่อมต่อได้ นอกจากนี้ ยังสามารถกลับไปยังหน้าเดิมเพื่อดูข้อความเก่าด้วย.
  3. แสดงข้อความที่อ่านหรือยังไม่ได้อ่านไว้อย่างชัดเจน โปรแกรมจะเปิดบันทึกข้อความที่เกิดข้อผิดพลาด รวมถึงอุปกรณ์ที่ใช้ในการส่งข้อความนั้นๆ โปรแกรมจะเลือกอุปกรณ์ที่เกี่ยวข้อง และแสดงข้อความที่อ่านแล้วไว้อย่างชัดเจนเมื่อเปิดข้อความนั้นขึ้นมา.
  4. สำหรับการแจ้งเตือนเกี่ยวกับความล้มเหลวนั้น ให้ตรวจสอบเวลาและครั้งที่ใช้ในการทดลองนั้นด้วย หากระบุว่ามีการทดลองในครั้งก่อน ก็ให้ดูบันทึกของการทดลองในครั้งนั้นแทน ตรวจสอบบันทึกของการทดลองในครั้งก่อนบนคอมพิวเตอร์ด้วย.

ตรวจสอบ: จำนวนข้อความที่ยังไม่ได้อ่าน และรายการข้อความที่ถูกกรองออกมา จะบ่งบอกถึงสถานะของข้อความนั้นๆ ว่าเป็นอย่างไร ความหมายของ “อ่านแล้ว” ไม่ได้หมายถึงข้อความนั้นได้รับการแก้ไขหรือไม่ ให้ใช้เวลาที่ข้อความนั้นถูกอ่านเพื่อทราบสถานะปัจจุบันของข้อความนั้นๆ

เมื่อพบปัญหา: กรอกข้อมูลเมื่อมีคำขอให้ทำเช่นนั้น; ให้รีบูตข้อความหลังจากตรวจสอบความเชื่อมต่อแล้ว หากไม่มีข้อความที่ตรงกับเงื่อนไข ให้รีเซ็ตตัวกรองทั้งสองข้อได้ การแจ้งเตือนสำหรับอุปกรณ์ที่ไม่ได้เชื่อมต่อกันนั้นเป็นเพียงข้อมูลทางประวัติเท่านั้น และไม่สามารถใช้ข้อมูลนี้เพื่อเปิดตำแหน่งที่กำหนดได้ หากการเข้าถึงล้มเหลว ให้ตรวจสอบบัญชีและอุปกรณ์ต่างๆ รวมถึงตรวจสอบบันทึกบนเดสก์ อย่าใช้บันทึกปัจจุบันเพื่ออธิบายถึงความพยายามในอดีต

15. ตรวจสอบผลและบันทึก

15.1 ตรวจผลด็อกกิง

  1. เลือกโครงการ “Docking” ที่มีอยู่ในส่วนของ “Research” แล้วเปิดผลการวิเคราะห์ของโครงการนั้นขึ้นมา.
  2. กรุณายืนยันข้อมูลต่างๆ เช่น ลิแกนด์ ตัวรับสัญญาณ และขั้นตอนการทดลองของผลลัพธ์แต่ละข้อด้วย.
  3. โปรดอ่านชื่อของคะแนนของท่าที่เลือก ค่าของคะแนนนั้น ทิศทางของคะแนน และคุณสมบัติที่สามารถใช้ได้.
  4. ลองตรวจสอบผลลัพธ์ที่ได้ดูนะคะ ให้เปิดบันทึกของผู้สมัครที่คุณต้องการเปรียบเทียบกันได้เลยค่ะ; ดูรายละเอียดเพิ่มเติมได้ในบทที่ 16.

ตรวจสอบ: สรุปผลการอ่านแสดงเวลาที่ใช้ในการอ่านไว้ด้วย โดยผลลัพธ์จะถูกจัดเรียงตามหมวดหมู่ของงานต่างๆ และมีโอกาสที่จะมีการแสดงผลของการทำงานหลายครั้งในหนึ่งหมวดหมู่ หากมีคะแนนที่ขาดหายไป หรือมีข้อบกพร่องใดๆ ก็ไม่ควรนับคะแนนเหล่านั้นเป็นศูนย์หรือผลการผ่านการทดสอบ

เมื่อพบปัญหา: หากไม่มีผลลัพธ์ใดๆ ให้ตรวจสอบว่าการดำเนินการนั้นอยู่ในโหมด “Queue” หรือโหมด “Active” หรือไม่ จากนั้นจึงดูข้อมูลในบันทึกการทำงานของระบบ หากการอ่านข้อมูลล้มเหลว ให้พยายามทำการอ่านอีกครั้งค่ะ คะแนนต่างๆ ไม่สามารถนำมาบวกกันได้ และไม่สามารถใช้คะแนนเหล่านั้นเพื่อกำหนดหรือประเมินกิจกรรมต่างๆ ได้เช่นกัน.

15.2 ดูความคืบหน้า MD จุดตรวจสอบ และผลวิเคราะห์

  1. กรองข้อมูลการวิจัยเพื่อนำไปใช้ใน MD และเปิดโปรแกรมเพื่อใช้งาน.
  2. ในการสรุปผล ควรตรวจสอบเวลาที่ใช้ในการจำลองสถานการณ์ ความสามารถของระบบ จำนวนขั้นตอนที่เกิดขึ้น และสถานะของจุดตรวจสอบต่างๆด้วย.
  3. ตรวจสอบว่าครั้งนี้เป็นการทดลองที่เริ่มต้นขึ้นจากจุดสำคัญของแฟล็กก์หรือไม่ และระบุตำแหน่งของจุดเริ่มต้นของการทดลองนั้นด้วย.
  4. ตรวจสอบผลการวิเคราะห์ที่มีอยู่ในบทสรุปนี้ ใช้แอปพลิเคชันบนเดสก์เพื่อกำหนดหรือดำเนินการวิเคราะห์เพิ่มเติมได้

ตรวจสอบ: ข้อมูลที่ไม่สามารถระบุได้ ก็ยังคงไม่มีอยู่ การค้นหาจุดตรวจสอบนั้น ไม่ได้หมายความว่าทีวีสามารถทำงานต่อได้อีกครั้ง.

เมื่อพบปัญหา: หากไม่มีการวิเคราะห์ใดๆ ให้ตรวจสอบว่ามีผลลัพธ์ที่สามารถอ่านได้บนคอมพิวเตอร์หรือไม่ หากสามารถดำเนินการต่อได้อีกครั้ง ให้ตรวจสอบและดำเนินการต่อไปบนเดสก์ท็อป การบรรลุเวลาที่กำหนดไว้หรือการเสร็จสมบูรณ์ของการดำเนินการไม่ใช่หลักฐานว่าการดำเนินการนั้นเป็นไปอย่างราบรื่นหรือมีประสิทธิภาพจริงๆ

15.3 เลือกบันทึกที่ต้องการ

  1. เปิดข้อมูลเกี่ยวกับข้อผิดพลาดและบันทึกต่างๆ ที่เกิดขึ้นระหว่างการรันโปรแกรม หรือในบัตรที่เกี่ยวข้องกับการรันโปรแกรม.
  2. เลือก “Worker” สำหรับการผลิตผลลัพธ์ข้อมูล หรือ “Scheduler” สำหรับการกำหนดลำดับการดำเนินการของงานต่างๆ.
  3. จากผลลัพธ์ของการดาวน์โหลด ขอเปิดบันทึกงานเพื่อตรวจสอบผลลัพธ์ที่เฉพาะนั้นๆ.
  4. ลองเลือกดูหน้าที่มีบันทึกไว้ในช่วงเวลาที่ก่อนหน้านี้ได้เลย หรือจะเลือกดูผลลัพธ์ที่มีอยู่ในตอนนี้ก็ได้เช่นกัน.

ตรวจสอบ: ข้อมูลในไฟล์จะแสดงเวลาที่มีการอ่านข้อมูล, ช่วงขนาดของข้อมูลในไฟล์ และขนาดรวมของไฟล์ด้วย. โปรดตรวจสอบตำแหน่งของข้อมูลในไฟล์ก่อนที่จะพยายามอ่านข้อมูลนั้น.

เมื่อพบปัญหา: บันทึกที่ยังไม่ได้ปรากฏในรายการ อาจจะปรากฏขึ้นในภายหลัง กรุณา試圖เข้าถึงหน้าเว็บที่เกี่ยวข้องอีกครั้ง สำหรับบันทึกที่ได้มาจากข้อความในอดีต ควรตรวจสอบว่าการทดลองครั้งนั้นแตกต่างจากการทดลองครั้งปัจจุบันหรือไม่.

15.4 ค้นหา ติดตาม และคัดลอกบันทึก

  1. ลองค้นหาในหน้า current page ดูนะค่ะ โดยใช้ตัวควบคุมการค้นหาแบบ Previous และ Next.
  2. กรองคำสำคัญที่เกี่ยวข้องกับข้อผิดพลาดออกไปก่อน จากนั้นจึงปิดการกรองนั้นเมื่อคุณต้องการข้อมูลที่ครบถ้วน.
  3. ด้วยการเชื่อมต่อแบบเรียลไทม์ และการปรับแต่งช่วงเวลาการแสดงผลอัตโนมัติ คุณสามารถเปิดฟังก์ชันการติดตามข้อมูลได้ ขณะที่กำลังค้นหาหรือเลื่อนดูหน้าเก่า ฟังก์ชันการติดตามข้อมูลก็จะหยุดการทำงานไปชั่วคราว คุณสามารถเปิดฟังก์ชันนี้ขึ้นมาใหม่อีกครั้งเมื่อเสร็จสิ้นการดำเนินการต่างๆ
  4. ใช้คำสั่ง “Copy Current Page” เพื่อคัดลอกหน้าใดหนาหนึ่งมาใช้.

ตรวจสอบ: ตัวนับและตัวบอกการติดตามแสดงสถานะปัจจุบัน การค้นหาและกรองทำได้เฉพาะหน้าที่เปิดอยู่ สูงสุด 16 KiB หมายเลขบรรทัดอ้างอิงเฉพาะหน้านั้น การคัดลอกหน้าไม่ได้ดาวน์โหลดบันทึกทั้งไฟล์

เมื่อพบปัญหา: เมื่อจำเป็น ให้ค้นหาในหน้าเก่าแทน หากหน้าใดไม่สามารถใช้งานได้ในโหมดออฟไลน์ หรือในโหมดการค้นหาแบบอัตโนมัติ ให้เปิดหน้าใหม่ด้วยวิธีการด่วน หากการคัดลอกข้อความไม่สำเร็จ ให้กดปุ่มเพื่อเลือกข้อความที่ต้องการ ให้ตีความผลการค้นหาโดยใช้รหัสและบริบทของข้อความนั้นๆ

16. จดบันทึก เก็บรายการโปรด และเปรียบเทียบผู้สมัคร

16.1 บันทึกโน้ตและเพิ่มงานในรายการโปรด

  1. เปิดข้อมูลเกี่ยวกับการรันโปรแกรม และเลือก “Run Notes”
  2. รันที่คุณชอบนั้น คุณสามารถกลับไปใช้บ่อยๆ ได้เลย.
  3. กรุณาตั้งค่าสถานะของการทบทวนผลการวิจัยไว้ และเขียนข้อสังเกต คำถาม หรือขั้นตอนต่อไปไว้ด้วย.
  4. บันทึกไว้ก่อนนะครับ. กลับไปที่บันทึกการวิจัย และเปิดโปรแกรม “Run Notes” เพื่อค้นหาหรือแก้ไขข้อมูลนั้น.

ตรวจสอบ: รายชื่อของสิ่งที่ชอบ ระดับการประเมินผล หมายเหตุต่างๆ และเวลาที่ใช้ในการแก้ไขข้อมูล จะปรากฏอยู่ในรายการนี้ การทำเครื่องหมายบนหมายเหตุที่ได้รับการประเมินนั้น ไม่ได้หมายความว่าการคำนวณนั้นเสร็จสิ้นแล้ว ข้อมูลจะถูกเก็บไว้ในระบบก่อนเสมอ.

เมื่อพบปัญหา: หากเกิดความล้มเหลวในการบันทึกข้อมูล ให้ยังคงอยู่ในโปรแกรมแก้ไขข้อมูลต่อไป และตรวจสอบว่ามีบันทึกข้อมูลอยู่หรือไม่ หากข้อมูลหายไป ให้ตรวจสอบบัญชียและอุปกรณ์ที่เกี่ยวข้องด้วย หากมีคำขอให้ลบข้อมูลที่ยังไม่ได้บันทึกไว้ ให้กลับไปบันทึกข้อมูลเหล่านั้นไว้ก่อน.

16.2 บันทึกท่าจับลงในรายการคัดเลือก

  1. เปิดบันทึกของผู้สมัครสำหรับท่าที่เลือกไว้ในรายงานการจัดวางโครงสร้าง.
  2. ตรวจสอบที่มาของบทวิจารณ์ และกำหนดสถานะของบทวิจารณ์นั้นไว้ด้วย จากนั้นก็เพิ่มหมายเหตุหรือข้อความเพิ่มเติมเข้าไปด้วย.
  3. บันทึกข้อมูลนั้นไว้ และค้นหาข้อมูลนั้นในรายชื่อผู้สมัคร ภายในหมวด “ข้อมูลการวิจัย”
  4. เปิดไฟล์ซอร์สโค้ด หรือขยายข้อมูลเกี่ยวกับแหล่งที่มาของข้อมูล เพื่อให้สามารถดูข้อมูลเพิ่มเติมได้.

ตรวจสอบ: ผู้สมัครยังคงมีข้อมูลเกี่ยวกับตำแหน่งงาน ดัชนี และเวลาที่ใช้ในการอ่านข้อมูลไว้เหมือนเดิม กรุณาแก้ไขข้อมูลต้นฉบับเพื่ออัปเดตข้อมูลต่างๆ.

เมื่อพบปัญหา: การปรับแต่งภาพที่ไม่มีรหัสกำหนดไว้นั้นไม่สามารถบันทึกไว้ได้ กรุณาตรวจสอบผลลัพธ์ที่บันทึกไว้บนเดสก์ท็อปด้วย หากแหล่งข้อมูลไม่สามารถใช้งานได้ ข้อมูลที่บันทึกไว้ก็ยังสามารถอ่านได้จนกว่าคุณจะเชื่อมต่ออีกครั้ง การลบข้อมูลการวิจัยนั้นไม่ได้ลบผลลัพธ์ที่ได้จากการคำนวณไปด้วย กรุณาอ่านข้อความยืนยันก่อนที่จะทำการซิงค์ข้อมูล

16.3 เปรียบเทียบสองถึงสี่รายการ

  1. เลือก “Run Notes” หรือ “รายชื่อผู้สมัคร” ในหมวด “Research Records”.
  2. จงทำเครื่องหมายไว้ที่ข้อมูลทั้งสองจุดนี้ เพื่อใช้ในการเปรียบเทียบหรือการส่งออกข้อมูล.
  3. เปิดการเปรียบเทียบข้อมูลของข้อความที่เลือกไว้.
  4. ลองเลื่อนดูข้อมูลในแนวระนาบ เพื่อดูแหล่งที่มาของข้อมูล เครื่องมือที่ใช้ในการวิเคราะห์ ตัวชี้วัดต่างๆ จำนวนครั้งที่มีการอ่านข้อมูล และหมายเหตุต่างๆ ฟิลด์ที่มีสัญลักษณ์แดงนั้นมีความแตกต่างกันออกไป.

ตรวจสอบ: ข้อมูลที่หายไปจะถูกแสดงในรูปแบบของเครื่องหมายเท่านั้น การมีข้อมูลที่สอดคล้องกันนั้นเป็นเพียงเบาะแสเท่านั้น ไม่ใช่หลักฐานที่สามารถใช้แทนการตรวจสอบเงื่อนไขทางวิทยาศาสตร์ได้

เมื่อพบปัญหา: ปรับการเลือกข้อมูลให้เหมาะสม หากมีจำนวนข้อมูลน้อยกว่า 2 หรือมากกว่า 4 ข้อมูล คุณสามารถอ่านข้อมูลจากแหล่งข้อมูลต่างๆ ร่วมกันได้ แต่ไม่ควรจัดลำดับหรือรวมคะแนนที่ไม่เกี่ยวข้องเข้าด้วยกัน ควรอัปเดตข้อมูลที่ไม่ถูกต้องให้เป็นข้อมูลที่ถูกต้อง

16.4 ส่งออกสรุปและตรวจสอบว่าปลายทางได้รับ

  1. สามารถส่งออกข้อมูลที่เลือก หรือรายการที่อยู่ในรายการปัจจุบันจากส่วน “Research Records” ได้เช่นกัน หรือสามารถส่งออกข้อมูลสรุปจากการเปรียบเทียบต่างๆ ได้เช่นกัน.
  2. กรุณาเลือกรูปแบบไฟล์ในรูปแบบ Markdown (.md) หรือ JSON (.json) แล้วไปตรวจสอบภาพลูป preview ของไฟล์นั้นดู.
  3. สามารถบันทึกหรือแบ่งปันข้อมูลบนแอปพลิเคชัน Android หรือ iOS ได้ หรือจะดาวน์โหลดข้อมูลจากเบราว์เซอร์ก็ได้ จากนั้นเลือกตำแหน่งที่ต้องการเก็บข้อมูลในกล่องโต้ตอบของระบบ.
  4. หากไม่จำเป็นต้องมีไฟล์สำเนา ก็ให้ลบไฟล์นั้นไปเลย ควรตรวจสอบข้อมูลและแหล่งที่มาของข้อมูลก่อนที่จะแบ่งปันข้อมูลนั้นๆ ควรลบทุกสิ่งที่ไม่จำเป็นต้องเปิดเผยออกไปด้วย.

ตรวจสอบ: เปิดไฟล์ที่บันทึกไว้ หรือยืนยันการรับข้อมูลในแอปพลิเคชันของปลายทาง ไฟล์ที่บันทึกไว้นั้นประกอบด้วยข้อมูลสรุป หมายเหตุ และข้อมูลอื่นๆ ที่เกี่ยวข้อง ไม่ใช่ไฟล์ที่เกี่ยวกับโมเลกุล ทิศทาง หรือไฟล์การคำนวณทั้งหมด

เมื่อพบปัญหา: การยกเลิกการบันทึกหรือการแบ่งปันข้อมูล ไม่ได้ทำให้ข้อมูลต้นฉบับหายไป ควรลองทำการส่งออกอีกครั้ง หรือคัดลอกข้อมูลไว้อีกครั้ง หากการส่งออกไม่ประสบความสำเร็จ การเปิดแผ่นแสดงข้อมูลเพื่อแบ่งปันข้อมูล ไม่ถือเป็นการส่งมอบข้อมูลไปยังผู้อื่น

17. เก็บหน้าไว้อ่านแบบออฟไลน์

17.1 เก็บสรุปงานและหน้าที่เลือก

  1. ให้เปิดรายละเอียดของการรันข้อมูลขณะที่ยังเชื่อมต่ออยู่ และรอให้เกิดการอ่านข้อมูลที่สำเร็จ.
  2. Save the summary of the run. เพื่อเก็บผลลัพธ์หรือหน้าที่บันทึกไว้ ให้เปิดหน้านั้นไว้ก่อน แล้วเก็บข้อมูลที่บันทึกไว้ในหน้านั้นไว้ด้วย.
  3. โหลดและเก็บแต่ละหน้าอย่างแยกกัน.
  4. ตรวจสอบผลลัพธ์ที่บันทึกไว้ รวมถึงหน้าที่แสดงข้อมูลต่างๆ เช่นช่วงเวลาที่มีการอ่านข้อมูล และช่วงเวลาที่มีการบันทึกข้อมูลไว้ด้วย.

ตรวจสอบ: หน้านี้รายงานว่าการเก็บข้อมูลนั้นประสบความสำเร็จ อย่างไรก็ตาม ข้อมูลที่เก็บไว้ไม่ได้ถูกดาวน์โหลดมาในรูปแบบทั้งหมด แต่ข้อมูลใหม่ที่อัปเดตบนเว็บสามารถแทนที่ข้อมูลที่เก็บไว้ได้ ดังนั้น การเก็บข้อมูลนี้จึงไม่ใช่การสำรองข้อมูลที่ไม่สามารถเปลี่ยนแปลงได้

เมื่อพบปัญหา: หากการเก็บข้อมูลถูกปิดไป ให้รอจนกว่าข้อมูลจะถูกโหลดเสร็จสิ้น หากพื้นที่เก็บข้อมูลเต็ม ให้ลบข้อมูลที่ไม่จำเป็นออกไป ตามที่อธิบายไว้ในข้อ 17.3 ข้อมูลที่ปรากฏบนหน้าไม่ถือเป็นสำเนาที่บันทึกไว้ หากไม่มีการยืนยันจากแอปพลิเคชันนั้น

17.2 เปิดแบบออฟไลน์และตรวจสอบหน้าที่ขาด

  1. เปิดแอปพลิเคชันด้วยบัญชีและการเชื่อมต่อที่เหมือนเดิมก่อนหน้านี้ จากนั้นค้นหาตัวเลือก “Offline Copy” และเวลาที่แสดงไว้ในแอปพลิเคชัน.
  2. ในส่วน “Settings” ภายใต้หัวข้อ “Offline Records” ให้เปิดไฟล์ที่เก็บข้อมูลจากการดำเนินการที่ถูกเก็บไว้อย่างชัดเจน.
  3. ขยายผลลัพธ์ที่บันทึกไว้ และเลือกหน้าที่คุณต้องการ.
  4. หลังจากที่สามารถเชื่อมต่ออีกครั้ง ให้รีเฟอร์ข้อมูลของงานต่างๆ และอ่านอีกครั้งสำหรับหน้าที่จำเป็นต้องมีการอัปเดต.

ตรวจสอบ: สำเนาที่ไม่ได้เชื่อมต่อกับเว็บไซต์จะแสดงเวลาที่ผู้ใช้อ่านเนื้อหาในตอนแรก ส่วนเนื้อหาที่อ่านมาแล้วจะถูกเก็บไว้ในหน่วยความจำของอุปกรณ์ อย่างไรก็ตาม ข้อมูลที่เลือกไว้จะถูกเก็บไว้ในรูปแบบของบทสรุปหรือหน้าแสดงเนื้อหา

เมื่อพบปัญหา: หากไม่มีหน้าเว็บที่บันทึกไว้ ให้เลือกหน้าเว็บที่มีอยู่แล้ว หรือเชื่อมต่อกับเซิร์ฟเวอร์อีกครั้งเพื่อดึงข้อมูลมาใช้ หากมีหน้าเว็บที่หายไปจากระบบ ให้ตรวจสอบบัญชีและอุปกรณ์ที่ใช้ในการทำงาน การออกจากระบบหรือการยกเลิกการเชื่อมต่อกับอุปกรณ์สามารถลบข้อมูลที่บันทึกไว้ได้ แต่การเชื่อมต่อกับเซิร์ฟเวอร์อีกครั้งไม่สามารถทดแทนการบันทึกข้อมูลได้

17.3 จัดการพื้นที่และยกเลิกการเก็บหน้าที่ตรึงไว้

  1. เลือก “Settings” → “Offline Records” เพื่อดูข้อมูลเกี่ยวกับการใช้งานโดยผู้ใช้, แอปพลิเคชันต่างๆ และเนื้อหาที่ถูกเก็บไว้.
  2. หยุดการเก็บข้อมูลของบทความทั้งหมดหรือหน้าใดหน้าหนึ่งไว้ในรายการหน้าเก็บข้อมูลของคุณได้แล้ว.
  3. เพื่อให้สามารถปล่อยเนื้อหาทั้งหมดที่ยังค้างอยู่ไปได้ ให้ใช้ตัวเลือก “ปล่อยเนื้อหา” เพื่อยืนยันและตรวจสอบการใช้งานอีกครั้ง.
  4. ควรลบข้อมูลการเชื่อมต่อที่ไม่จำเป็นออกไป หลังจากที่คุณยืนยันว่าไม่จำเป็นต้องเก็บข้อมูลเหล่านั้นอีกต่อไป.

ตรวจสอบ: ทั้งแอปเก็บได้สูงสุด 40 งาน ผลหรือบันทึก 12 หน้าต่องาน และรวม 20 MiB สำเนาที่ตรึงไว้นับในโควตาแต่จะไม่ถูกลบอัตโนมัติ เมื่อยกเลิกการตรึง สำเนาจะกลับเข้าสู่การล้างแคชตามปกติ การลบสำเนาบนเครื่องไม่ลบผลบนเซิร์ฟเวอร์

เมื่อพบปัญหา: การปล่อยให้ไฟล์ที่ถูกเก็บไว้ยังคงอยู่ในหน่วยความจำนั้น ไม่จำเป็นต้องทำให้การใช้งานของไฟล์นั้นลดลงทันที เพราะไฟล์เหล่านั้นอาจยังคงอยู่ในหน่วยความจำต่อไป ลองตรวจสอบพื้นที่เก็บข้อมูลของอุปกรณ์ดู หากการบันทึกหรือการลบไฟล์นั้นไม่ประสบความสำเร็จ อย่าใช้วิธีการออกจากระบบเพื่อแก้ไขปัญหานี้แต่อย่างใด.

18. แก้ไขและส่งแผนที่รอดำเนินการ

18.1 เปิดโปรเจกต์เดสก์ท็อปหรือแผนที่บันทึกไว้

  1. Save projectบนเดสก์ท็อปไว้ก่อนนะครับ โทรศัพท์ไม่สามารถอ่านข้อมูลที่ไม่ได้ถูกบันทึกไว้ในเดสก์ท็อปได้.
  2. บนคอมพิวเตอร์ ให้เปิดการตั้งค่าสิทธิ์โปรเจกต์และงานผ่านมือถือ เลือก Device.json ของเอเจนต์ที่จับคู่ไว้แล้วกำหนดระยะเวลา ค่าเริ่มต้นให้แก้แผนได้เท่านั้น หากต้องการส่งงานจริง ให้เปิดสิทธิ์ส่งงานแยกบนคอมพิวเตอร์ การเปิดสิทธิ์ไม่ทำให้งานเริ่มจนกว่าจะยืนยันบนโทรศัพท์
  3. บนโทรศัพท์ ให้เลือกอุปกรณ์ที่เหมาะสม และอัปเดตสิทธิ์การใช้งานของอุปกรณ์นั้นด้วย จากนั้นเปิดแผนผังที่เกี่ยวข้องกับการวิจัย หรือจากหน้าผู้ใช้ที่ลงชื่อเข้าสู่ระบบแล้ว.
  4. เปิดโปรเจกต์บนเดสก์ท็อปเพื่อกำหนดแผนการดำเนินงานใหม่ๆ หรือเพื่อดูแผนการดำเนินงานที่ได้เก็บไว้แล้ว.
  5. โปรดตรวจสอบโครงการนี้ก่อนที่จะทำการแก้ไขข้อมูลต่างๆ เช่น ข้อมูลเกี่ยวกับฮอสต์ เครื่องที่ใช้ในการประมวลผล และจำนวนงานที่มีอยู่.

ตรวจสอบ: โครงการบนเดสก์สามารถสร้างแผนการดำเนินงานที่แยกต่างหากออกมาได้ โดยไม่จำเป็นต้องเปลี่ยนแปลงแหล่งข้อมูลเดิม จะมีเพียงแผนการดำเนินงานที่ยังไม่ได้เริ่มต้นการดำเนินการเท่านั้นที่สามารถแก้ไขได้

เมื่อพบปัญหา: บันทึกโครงการไว้ในคอมพิวเตอร์ และรีเฟอร์แผนการต่างๆ หากมีข้อผิดพลาดเกิดขึ้น หากมีข้อบกพริด ให้ตรวจสอบข้อมูลเกี่ยวกับตัวแทนที่ใช้ในการดำเนินโครงการ ระยะเวลา และการอนุมัติการส่งผลงานต่างๆ บนเดสก์ท็อป จากนั้นรีเฟอร์การตั้งค่าของโครงการบนเดสก์ท็อปอีกครั้ง อย่าได้ถือว่าโครงการที่กำลังดำเนินอยู่นั้นสามารถแก้ไขได้

18.2 แก้พารามิเตอร์และกู้ฉบับร่างบนเครื่อง

  1. แผนด็อกกิงอาจมีช่องให้ตั้งจำนวนเธรด CPU ต่อลิแกนด์ จำนวนลิแกนด์ที่รันพร้อมกัน ความละเอียดในการค้นหา (exhaustiveness) จำนวนท่าจับสูงสุด ฟังก์ชันให้คะแนน และค่า seed ตั้งช่วงพลังงาน (kcal/mol) เฉพาะเมื่อมีช่องนี้ในแบบฟอร์ม หากใช้กล่องเดียว ให้ระบุศูนย์กลางและขนาด XYZ ในหน่วย Å
  2. GNINA รันด้วย CPU เท่านั้นหรืออนุญาตให้ใช้ GPU ได้เมื่อรองรับ โหมดให้คะแนน CNN ที่แสดงคือค่าปัจจุบันและแก้ในหน้านี้ไม่ได้ ให้แก้กล่องค้นหาของตัวรับแต่ละตัวบนคอมพิวเตอร์
  3. การตั้งค่าต่างๆ ของ MD อาจรวมถึงจำนวนเธรดต่อราน, รานของ MPI, เครื่องประมวลผลกราฟิก, ปริมาณหน่วยความจำ (ในหน่วย GiB), เวลาการรอคอย, การแบ่งส่วนข้อมูล, บัญชีที่ใช้, คุณภาพการทำงาน, ช่วงเวลาการทำงานสูงสุด (ในชั่วโมง) และรูปแบบการประมวลผลต่างๆ เหล่านี้ไม่มีผลต่อการตั้งค่าทางวิทยาศาสตร์ใน TPR ที่มีอยู่แล้ว
  4. ตรวจสอบให้แน่ใจว่าที่แก้ไขไว้ยังคงอยู่ในระบบลูกค้าทั้งในรูปแบบไฟล์และข้อมูลที่ส่งไปยังระบบออนไลน์ หากจำเป็น ให้เปิดไฟล์ร่างในระบบลูกค้าอีกครั้ง ตรวจสอบค่าต่างๆ ในไฟล์ร่างนั้น และอัปเดตข้อมูลจากแหล่งข้อมูลออนไลน์ก่อนที่จะทำการดูตัวอย่างผลลัพธ์.

ตรวจสอบ: กรุณาปฏิบัติตามหน่วยและช่วงค่าที่แสดงออกมาให้ถูกต้อง การป้อนข้อมูลแบบท้องถิ่นนั้นเป็นเพียงการป้อนข้อมูลผ่านโทรศัพท์เท่านั้น ไม่ใช่แผนการใช้งานบนเดสก์ และไม่มีการคำนวณใดๆ เกิดขึ้นเลย กรุณาใช้เครื่องหมายจุลภาคเพื่อแบ่งช่วงค่าต่างๆ และใช้รูปแบบการแสดงผลตามตารางที่กำหนดไว้.

เมื่อพบปัญหา: กรุณาแก้ไขค่าที่เลือกไว้ให้ถูกต้อง หากแหล่งข้อมูลของเดสก์เปลี่ยนไป ให้ตรวจสอบร่างแรกก่อนที่จะทิ้งมันไป และทำการปรับเปลี่ยนข้อมูลตามแหล่งข้อมูลล่าสุด อย่าไปลบโปรเจกต์ที่มีการปรับเปลี่ยนไปด้วยร่างแรกไป หากการบันทึกข้อมูลในระบบลูกค้าของคุณไม่สำเร็จ ให้คอยตรวจสอบการบันทึกข้อมูลต่อไป.

18.3 ตรวจการเปลี่ยนแปลงและบันทึกแผน

  1. แก้ไขให้เสร็จแล้วเปิดดูตัวอย่างการเปลี่ยนแปลง
  2. เปรียบเทียบค่าก่อนและหลังแก้ หากสร้างแผนใหม่จากโปรเจกต์บนคอมพิวเตอร์ ให้ตรวจสรุปทรัพยากรด้วย
  3. ยืนยันและบันทึกแผนในสถานะรอส่ง
  4. ตรวจผลการบันทึกและรายการแผนที่บันทึกไว้ หากแอปแสดงหลักฐานตอบรับที่ยืนยันแล้วจากคอมพิวเตอร์ ให้ตรวจด้วย

ตรวจสอบ: แอปพลิเคชันรายงานว่ามีแผนที่อยู่ในระหว่างการดำเนินการ แต่ยังไม่มีการประมวลผลใดๆ เกิดขึ้น หรืออาจเป็นแผนที่แยกต่างหากจากแผนหลัก และโครงการต้นทางก็ยังคงไม่เปลี่ยนแปลงอยู่ การบันทึกข้อมูลไม่ได้เริ่มต้นการประมวลผลใดๆ เลย

เมื่อพบปัญหา: แผนที่มีอยู่ในปัจจุบันจำเป็นต้องมีการปรับเปลี่ยนก่อนที่จะนำไปใช้งานได้ หากต้องการใช้แผนใหม่ ก็สามารถใช้การตั้งค่าเดิมได้เช่นกัน หากมีการเปลี่ยนแปลงในส่วนของแหล่งข้อมูลหรือวิธีการนำเสนอข้อมูล ก็จำเป็นต้องรีเฟอร์และทดลองใช้แผนใหม่อีกครั้ง หากผลลัพธ์ของการบันทึกข้อมูลยังไม่แน่นอน ก็ควรลองทำการบันทึกข้อมูลอีกครั้ง แทนที่จะสร้างแผนใหม่ขึ้นมา

18.4 ตรวจทรัพยากร ส่งงาน และกู้สถานะเมื่อผลยังไม่ทราบ

  1. ให้สิทธิ์ส่งงานแบบจำกัดเวลาบนคอมพิวเตอร์ แล้วรีเฟรชสิทธิ์บนโทรศัพท์ บันทึกการแก้ไขในเครื่องไปยังคอมพิวเตอร์ก่อน หรือเลือกทิ้งฉบับร่างที่ไม่ต้องการ
  2. เปิดแผนที่บันทึกไว้แล้ว และตรวจสอบเนื้อหาที่แนบมาด้วย.
  3. ตรวจโฮสต์ โปรแกรม จำนวนงาน และจำนวนงาน CPU ที่รันพร้อมกัน สำหรับ MD ให้ตรวจเธรด แรงก์ GPU หน่วยความจำ และเวลารันสูงสุดของระบบคิว
  4. เมื่อทบทวนแผนแล้ว ให้ทำเครื่องหมายยืนยันและเริ่มการคำนวณ ขั้นตอนนี้จะส่งงานจริงไปยังโฮสต์คำนวณ
  5. สถานะของแผนการปรับปรุง: เมื่อมีการแสดงผลการดำเนินการที่เกี่ยวข้อง ให้เปิดข้อมูลเกี่ยวกับความคืบหน้า ผลลัพธ์ บันทึกของผู้ปฏิบัติงาน หรือบันทึกของตัวจัดการเวลาไว้ดูก่อน.

ตรวจสอบ: การส่งผลลัพธ์เข้ามานั้น เกิดขึ้นก่อนที่ผลลัพธ์จะถูกแสดงออกมา การส่งผลลัพธ์เข้ามาและการรอคอยนั้น ไม่ถือเป็นการเสร็จสมบูรณ์ของกระบวนการเลย โปรดตรวจสอบข้อมูลที่เกี่ยวข้องด้วย.

เมื่อพบปัญหา: หากปุ่มเริ่มใช้งานไม่ได้ ให้ตรวจการยืนยัน สิทธิ์ และการแก้ไขที่ยังไม่บันทึก หากการเชื่อมต่อขาด ให้กู้การส่งครั้งเดิมหรือรีเฟรชแผน แทนการเริ่มแผนใหม่ กลับไปใช้บัญชี บริการ และโฮสต์เดิมเพื่อจัดการหลักฐานตอบรับที่เก็บไว้ หากเก็บหลักฐานไม่สำเร็จ ให้กู้พื้นที่จัดเก็บบนเครื่องและรักษารายการเดิมไว้ อย่าล้างข้อมูลเพื่อข้ามขั้นตอนกู้คืน
