MolloM 完整使用手冊

從桌面專案準備到手機端查看任務、結果與日誌，按章節查閱 MolloM 的操作流程。

初次試用只需一個配體。載入公開範例並儲存專案，在三維口袋中找出受體、參考配體與搜尋盒。用 Vina 試跑一個配體，能開啟分數與姿態後，再換成自己的分子庫。手上已有軌跡，可直接讀軌跡分析。

桌面步驟依 0.301.0 開發版核對，圖片保留較早版本的畫面。請在設定中查看版本，再到下載頁核對。使用自己的 AI 用戶端時，先看連線步驟，再交給它 Agent 操作指南（Markdown）。

1. 從哪裡開始

1.1 先選一條要完成的路線

第一次使用，建議先完成一個規模很小、自己熟悉的任務。準備一個受體和少量配體，走通導入、準備、設置搜索盒、試跑和查看結果，再擴大到整批分子。

已有 GROMACS 體系的讀者可以直接從第 10 章開始；已有波函數檔案，可以讀第 12 章。手機的連接、查看和計劃操作從第 13 章開始。對接與 MD 都有各自的入口，無需為了使用其中一項先完成另一項。

1.2 分清操作位置和計算位置

桌面端用於準備結構、配置程序、安排計算和檢查結果。執行位置可以是當前電腦，也可以是通過 SSH 連接的服務器。程序、輸入路徑和計算資源都要按所選機器填寫：服務器上的路徑由服務器讀取，本機路徑由本機讀取。

手機連接監控服務後，可以查看所綁定設備提供的運行、結果和日誌，也可以在授權有效期內編輯待提交計劃。離開電腦前，應確認計算機器不會休眠，監控服務能夠繼續運行。

1.3 找到專案與設置

打開“專案與模板”，可以“新建專案”“打開專案 JSON”，也可以“載入公開示例”熟悉介面。在“設置”選擇介面語言；手冊中的中文名稱對應繁體中文介面。

初次試用公開示例時，先檢查示例檔案、計算環境和搜索範圍，再啓動小規模試跑。模板中的數值是起點，需要根據自己的結構和研究目的調整。

透過自己的 AI 用戶端讀取任務。 在執行 MolloM 的電腦上使用支援 MCP stdio 的用戶端，並讓它可執行 Node.js 18 或以上版本。在設定的「AI Agent · MCP」選擇唯讀並套用權限。服務啟動後，複製接入 JSON，加入用戶端現有的 MCP 設定。保留原本的服務與產生的路徑，請勿將連線檔內容貼進對話。保持 MolloM 開啟，重新連線後，將 Agent 指南交給它，要求「列出最多五筆對接任務，等我選定再讀狀態」。空清單也可能表示已連線，但尚無登記的任務。需要寫入時再啟用任務控制、套用並重連。

2. 連接計算環境並準備軟體

2.1 在本機運行

  1. 打開“計算環境與軟體中心”，執行位置選擇“本機運行”。
  2. 點擊“重新探測”，查看程序和環境的探測結果。
  3. 已有對接程序時，用“指定 Vina 可執行檔案”或相應引擎的程序選擇入口指定實際檔案。
  4. 檢查工作目錄是否可寫、磁盤空間是否足夠。

路徑檢查完成後，再做一次小規模真實試跑。啓動程序時缺少動態庫、模型檔案或設備驅動的問題，通常會在這一步暴露出來。

2.2 連接 SSH 服務器

  1. 添加服務器，填寫“主機 / SSH Config 別名”。已有系統 SSH 配置時可以使用別名。
  2. 根據配置填寫用戶名、端口，選擇系統認證或密鑰檔案。不要把私鑰正文粘進普通輸入框。
  3. 填寫服務器工作目錄、遠端程序路徑；需要指定 Python 時，填寫服務器上的 Python 路徑。
  4. “保存服務器”後，點擊“測試連接並探測環境”。

首次連接需要核對服務器主機指紋。遇到未知主機或認證失敗，應先完成系統 SSH 認證，再回到 MolloM 測試。路徑存在但程序無法啓動時，查看探測信息，檢查權限、依賴和運行環境。

在叢集上依任務頁提供的排程方式填寫分區或佇列、帳戶、時限及資源。

未知的主機指紋要向管理員核對；認證失敗則檢查使用者名稱及金鑰。SSH 已連線但執行環境檢查失敗時，查遠端 Python。Slurm 的 PENDING / Priority 表示正在排隊；QOSMinGRES 則要核對分區最低資源要求，連 CPU 分析也可能需要申請 GPU 配額。

2.3 用軟體中心安裝或接入已有程序

進入“軟體中心”，先選擇本機或目標服務器，點擊“刷新”查看該環境的軟體記錄。需要安裝時選擇版本，點擊“安裝”，閱讀“安裝與驗證方案”，確認安裝位置、許可和依賴後再“開始執行”。

已有安裝可以“重新驗證”，通過後選擇“使用此版本”。部分軟體提供的是官方安裝說明或已有程序接入入口，應按對應頁面完成準備。遇到驗證失敗，先閱讀該條記錄的輸出；不要僅因目錄已經生成就開始整批任務。

3. 新建專案與導入結構

3.1 建立一個便於回看的專案

在“專案與模板”點擊“新建專案”，填寫能辨認研究對象與用途的專案名稱，再“進入專案”。一個專案中可以保留多次任務和篩選輪次，沒必要為每次小調整都複製整套檔案。

修改重要配置後點擊“保存專案”。“導出 JSON”適合保存專案設置；需要把輸入與結果一起搬到另一台電腦，使用第 9 章的專案包。

3.2 添加受體與配體

  1. 進入“受體與配體”，點擊“添加受體”，選擇 PDB 或 PDBQT 檔案。
  2. 配體可以“選擇檔案”“選擇資料夾”，也可以從服務器瀏覽檔案。
  3. 當前輸入入口支持 PDBQT、SDF/SD、MOL2、MOL 和 SMILES；按來源選擇正確格式。
  4. 點擊“重新檢查輸入”，核對識別記錄數、引擎格式輸入和解析問題。

一個 SDF 檔案可能包含多條記錄，因此檔案數與分子記錄數可能不同。先查看有問題的記錄，再決定修正、排除或重新準備。不要在未弄清缺失記錄的情況下直接擴大計算。

3.3 保存清楚的來源

保留原始檔案及可追溯的分子標識。後續準備可能產生不同工作態，篩選時要能找回它們共同的母體。給受體起易辨認的名稱，尤其是在同一專案里比較多個結構或構象時。

原始輸入不需要手工改成程序輸出格式後再覆蓋。結構準備會輸出工作副本，下一章介紹如何核對這些變化。

4. 準備受體與配體

4.1 確認受體中保留甚麼

在“結構準備”填寫需要的鏈；留空時保留全部。根據體系決定是否移除普通水分子，以及是否保留 HETATM 輔因子或金屬。結合口袋中有功能水、金屬或輔因子時，先依據結構和文獻判斷其作用。

檢查缺失殘基、非標準殘基和質子化狀態。當前準備流程遇到不支持的結構會報告問題，缺失環和目標 pH 下的質子化需要另行處理。

4.2 處理配體工作態

根據輸入選擇是否取最大母體、是否枚舉互變異構工作態，以及每條來源記錄允許的工作態數量。未定義手性默認會被隔離；只有明確知道如何處理該批輸入時，才使用允許未定義手性的選項。

沒有三維坐標的輸入需要生成三維結構。無論輸入來自數據庫還是自己繪制，都應檢查電荷、手性和成鍵關係，再用於後續對接。

4.3 檢查準備前後的變化

點擊“準備輸入並檢查”，結束後查看成功和問題記錄，使用“打開準備目錄”查看產物。在“結構準備前後對比”選擇結構，點擊“查看變化”，核對重原子、形式電荷、片段和坐標。

對準備失敗的記錄按具體原因修正。重試時保留原檔案，重新生成工作副本，避免覆蓋後無法判斷變化來自哪裡。

5. 在三維視圖中設置搜索範圍

5.1 找到目標口袋

進入“三維口袋”，選擇“對應受體”。用蛋白、配體和表面顯示開關查看局部環境，拖動旋轉、滾輪縮放，必要時“重置視角”。

有參考配體時，可以使用“選擇參考配體定位”幫助確定位置。參考配體必須與當前受體處在同一坐標系；來自另一個結構的坐標，需要先完成合適的結構對齊。

5.2 核對搜索盒

在“搜索盒設置”填寫中心 XYZ 和邊長 XYZ，單位為 Å。逐個檢查盒子是否覆蓋希望搜索的區域、是否容納配體，以及是否大到把大量無關空間也包括進去。

多個受體需要分別核對搜索盒。不要只複製同一組數字就開始批量運行。設置完成後保存專案，並在試跑結果中確認輸出姿態位於預期區域。

6. 配置對接引擎與資源

6.1 選擇並檢查引擎

在“對接引擎庫”按名稱或類別找到程序，查看“官方資料”，點擊“用於本輪”。在“任務方案”指定目標機器上的可執行程序，並“檢查程序路徑”。

優先使用已配置的內置接入。自定義原生協議適合熟悉目標程序命令和輸出格式的使用者，應先用小任務檢查輸入、命令與結果解析，再擴大規模。

6.2 設置 Vina 參數與獨立 seed

選擇 Vina 後，填寫搜索強度、輸出 pose 上限、能量窗口和評分函數。增加搜索強度會增加計算開銷，應結合試跑判斷，而不是一開始就把所有數值調到最高。

填寫獨立 seed 列表，每個 seed 對應一次獨立搜索。輸入數量、啓用的受體數量和 seed 數量共同決定任務規模。提交前再次核對本輪名稱和任務總數，避免多選受體或重復 seed 帶來額外計算。

6.3 使用 GNINA

選擇 GNINA 後，按任務目的設置 CNN 使用方式，例如重評分或參與精修，再選擇模型；留空時使用引擎默認模型。需要純 CPU 運行時使用“僅使用 CPU（禁用 GPU）”。

GPU 路徑需要同時核對軟體、驅動和資源分配，試跑後查看日誌中的實際執行情況。結果中的能量、CNNscore 和 CNNaffinity 各有含義與排序方向，篩選時分別設置條件。

6.4 分配併發與 CPU、GPU

“每任務 CPU 配額”控制單項任務使用的 CPU，“併發任務數”控制同時運行的任務數量。兩者相乘應與分配到的 CPU 資源相協調，還要為系統和數據讀寫留出空間。

集群任務還需核對隊列、時間、記憶體和 GPU 申請。填寫後先試跑，觀察運行速度和記憶體佔用，再決定整批資源。多開併發不一定更快，磁盤、顯存或 CPU 爭用都可能拖慢整批任務。

7. 小樣本試跑與批量任務

7.1 先確認能正確完成一小批

進入“試跑與估時”，設置抽樣配體數，點擊“開始真實試跑”，再“查看試跑任務”。這一步會實際運行程序並使用所選機器的資源。

試跑完成後檢查輸出姿態、結果解析和日誌。估時根據當前樣本與配置計算，不包含排隊、準備、傳輸及導出時間。換引擎、模型、搜索強度或機器後，應重新試跑。

打開一筆成功結果，確認姿態落在口袋內；有失敗記錄時，先讀一筆原始日誌。若只試了一個小配體，而整庫含許多大分子，耗時只能粗估。記下樣本數與並行數，另留排隊、傳輸及匯出時間。

7.2 提交整批計算

進入“任務與進度”，核對準備輸入、受體、seed 和資源配置，點擊“提交新對接任務”。用“查看參數”確認這次運行實際保存的配置。

觀察完成、失敗和待處理數量。需要定位異常時打開“運行事件與原始日誌”或“打開運行目錄”。修改專案中的下一輪參數後，應新建運行，以免混淆不同條件下得到的結果。

7.3 暫停、取消和恢復

“暫停領取”會停止領取新任務，已經開始的任務繼續執行；準備好後點擊“繼續”。“取消剩餘任務”用於停止剩餘工作，已生成的結果仍保留。

失敗後使用“選擇失敗項重試”，只處理需要重試的項，並保留成功結果和嘗試記錄。網絡中斷或狀態未知時，先恢復連接並刷新原任務，不要立即重復提交。關閉桌面窗口後，獨立執行器可以繼續工作；計算機器休眠、關機或任務被調度器終止，則需要另外處理。

8. 篩選結果並建立下一輪

8.1 找到值得繼續看的記錄

在“結果與篩選”選擇運行，通過名稱搜索、主閾值或高級多指標條件篩選，然後“應用篩選”。查看每條記錄的姿態、來源和指標，而不只盯著第一列分數。

同一條 pose 需要滿足所設置的條件。來自不同評分方法的數值應按各自含義解釋，不要直接平均。對接結果用於挑選下一步要檢查的結構和候選，活性及結合方式仍要結合獨立證據判斷。

8.2 控制重復並保留多樣性

需要壓縮候選數量時，可按母體保留一個代表，或按 RDKit 骨架限制代表數。先確認這是否符合研究目的：如果正在比較工作態，過早合併可能丟掉想觀察的差異。

檢查篩選後數量，再逐項勾選希望繼續處理的記錄。對異常高分、明顯碰撞或不合理構象，先查輸入與準備過程。

8.3 創建下一輪

打開“篩選輪次”，選擇已結束的運行，設置條件後點擊“統計候選數”。填寫下一輪名稱和引擎，選擇複製原始準備輸入，或使用本輪評分最優的達標 pose。

點擊“選擇目錄·創建下一輪”，檢查生成的輸入和配置，再進入任務頁面試跑或提交。創建輪次後可以繼續修改方案，不會立刻開始計算。

練習時可在 Vina affinity 設 ≤ −7.0 kcal/mol，先查看符合條件的數量。下一輪若改用 GNINA，重新選評分欄位及方向，例如 CNNscore 越高越優。建立後檢查受體、配體數與引擎，再決定是否提交。

9. 導出結果與搬遷專案

9.1 導出要交給合作者的內容

進入“結構與結果導出”，選擇當前篩選結果，或勾選“僅導出勾選記錄”。按需要導出 CSV、結構、受體、配置和報告；需要多個姿態時選擇所有達標 pose。

檢查導出報告中的成功與失敗記錄。缺少可靠原子映射時，SDF 轉換可能失敗，保留的 PDBQT 與報告可用於繼續排查。不要把缺失的結構檔案當作已成功交付。較大的導出任務可暫停，並從檢查點恢復。

匯出途中離開後，重開原專案，從同一筆匯出記錄核對目的地並繼續。發現衝突先查看檔案並保留既有內容。最後對照成功與失敗記錄；每個配體保留多個姿態時，表格列數、配體數與檔案數可能不同。

9.2 建立可攜帶專案包

在“可攜帶專案包”預覽要帶走的內容。需要服務器上的輸入時，選擇包含遠端輸入；需要結果時，選擇已結束任務的結果，再“選擇目錄並導出”。

在另一台電腦點擊“導入專案包”，選擇包中的 Project.htvs.json，檢查預覽後“確認導入為獨立專案”。隨後重新配置目標機器的軟體、認證和路徑。歷史結果供查看與比較，新計算應從導入後的專案重新建立任務。

9.3 管理磁盤空間

在“專案與空間”使用“掃描空間與引用”，先看清檔案用途和引用關係，再處理緩存。“清理預覽中的安全緩存”只應用於預覽列出的可清理項。

對原始輸入、正式結果和準備過程記錄，應按照自己的備份計劃保留。移動專案時優先使用專案包，避免只搬了配置檔案卻遺漏實際輸入。

10. 準備分子動力學體系

10.1 選擇合適的入口

打開“分子動力學 · GROMACS”。標準蛋白 PDB 可以從“體系構建”開始；已有坐標、拓撲或 TPR，可以通過“導入或連接體系”檢查並接入。

從對接結果繼續研究時，使用“對接→MD 交接”中的“生成交接 SDF”，檢查原子身份和坐標，再進入配體參數化。先明確力場、質子化、配體電荷和體系組成，再開始構建。

10.2 準備配體與復合物

在“配體參數”選擇已配置的 ACPYPE / AmberTools、GAFF 或 GAFF2，填寫整數淨電荷和電荷方法。依次“檢查輸入與環境”“準備隔離任務”，確認後“提交計算”，完成後“查看拓撲交接”。

“復合物組裝”當前面向 AMBER 乾蛋白與 GAFF/GAFF2 單配體。選擇蛋白 GRO/TOP、配體 ITP 和結合 pose GRO，核對坐標系、原子順序及力場兼容性，然後“檢查原子對應與輸入”。通過後創建隔離復合物，交給體系構建處理溶劑、離子與驗證。

10.3 構建溶劑與離子環境

  1. 在“體系構建”選擇起點：標準蛋白 PDB、保留拓撲的乾體系，或已有完整體系。
  2. 填寫計算位置、體系目錄和輸入檔案，點擊“檢查結構與安裝的力場”。
  3. 選擇實際可用的力場及匹配水模型，設置盒形、溶質到邊界的距離、鹽濃度、離子和電中和。
  4. 檢查末端及質子化處理，點擊“保存構建方案並預覽命令”。
  5. 確認後“提交構建”，檢查輸出，再交給多階段模擬或 MD 導入。

這裡的盒子距離使用 nm，與對接搜索盒的 Å 不同。膜蛋白、特殊殘基和複雜輔因子應使用合適的專門準備流程，再導入已準備的體系。構建完成後仍要進行能量最小化與平衡。

10.4 接入已有體系

在“導入或連接體系”選擇已有 TPR，或坐標、拓撲與 MDP 的組合。填寫目標機器上的體系目錄和目錄內相對路徑，根據需要加入索引、位置限制參考坐標和檢查點。

依次“檢查 GROMACS 環境”“檢查體系”“導入為可提交任務”。檢查輸入與預處理輸出後，再“提交任務”。只需要觀察已有計算時選擇“僅監控已有目錄”。

11. 配置和運行多階段模擬

11.1 建立流程與獨立重復

進入“模擬流程”，選擇“創建流程與獨立重復”，填寫體系與資源，按需要設置獨立重複數和起始隨機 seed。逐階段檢查 EM、NVT、NPT 和 Production 的輸入、MDP 和資源。

內置短流程用於走通工程流程，不能直接當作自己體系的平衡與生產方案。特別檢查時間長度、溫壓耦合、位置限制和約束。確認後“保存流程；不提交計算”。

11.2 編輯 MDP 並核對預處理

點擊“瀏覽 GROMACS 參數”或參數工作台，按原生參數名搜索，查看說明並編輯。核對 integrator、dt、nsteps、輸出頻率、耦合與約束；模擬總時間由步長和步數共同決定。

導入 MDP 時檢查重復鍵和保留的注釋。預處理報錯或警告時閱讀原文，回到輸入和參數修正原因，不靠提高 maxwarn 跳過未弄清的問題。

11.3 啓動階段與分配運行資源

選擇“啓動當前／下一階段”，核對運行位置、調度資源和 mdrun 參數。執行緒、PME、GPU 與隊列申請需要相互匹配；先查看短運行的實際日誌，再決定長任務資源。

上一階段結束後檢查輸出和體系狀態，再啓動下一階段。失敗或主動停止的階段先恢復處理，避免跳過必要步驟。

11.4 停止、續跑與檢查日誌

需要有序停止時點擊“保存檢查點並停止”。恢復時使用“從檢查點續跑”，核對原任務及檢查點，再查看日誌中的續跑位置。總步數終點表示最終要達到的步數，填寫時不要誤當作額外追加步數。

用“讀取日誌”“刷新”查看進展。發現約束錯誤、能量異常或結構不合理時，先檢查體系與參數，必要時回到準備或平衡階段。跨階段傳遞狀態與同一階段斷點續跑，應按各自入口處理。

12. 檢查軌跡與波函數分析

12.1 添加軌跡並確定分析方法

軌跡停止寫入後，在“任務與分析”添加只讀分析源，選擇 TPR 與 XTC/TRR，按需要加入 EDR 和日誌。點擊“檢查軌跡、原子組與能量項”。

選擇時間窗口、抽幀間隔、PBC 處理、參考結構、擬合組與測量組，再選擇指標。可以從 RMSD、RMSF、回轉半徑、SASA、氫鍵、距離接觸與能量開始；PCA、聚類、密度等分析按研究問題和環境中可用工具選擇。

自定義原子選擇應先“檢查實際選擇並預覽”。例如在蛋白擬合後測量配體 RMSD，與配體自身擬合後的 RMSD 回答的是不同問題，應在分析記錄中寫清。

0 至 20 ns 每 10 ps 儲存一幀，含首尾共 2,001 幀；每 100 ps 取樣一次則有 201 個曲線點。點選時間後核對實際幀。若排程器顯示 FAILED，先對照模擬最後一步、末幀時間與外層指令稿的錯誤，再決定是否續跑。

12.2 查看、比較和導出分析

分析完成後打開“分析方法與來源”，核對時間段、選擇與參數，再查看曲線或“加載軌跡預覽”。曲線中的異常點可以回到對應實際幀檢查，避免僅憑平滑或波動幅度判斷體系。

需要比較時，在比較區“加載 MD 任務”“加載此任務的分析”“加入比較”，可比較 2–8 條記錄。先核對時間窗口、擬合與選擇是否一致，再“比較曲線與方法”，按需“導出比較 JSON”。獨立重復之間的差異也應保留。

12.3 檢查 Multiwfn 輸入

打開“Multiwfn · 輸入檢查”，選擇本機或 SSH 環境中的波函數檔案，點擊“檢查輸入”。當前入口可檢查 FCH/FCHK、單幀 MWFN，以及受支持的非磁性 GTO WFN/WFX。

查看原子、電子、基組、軌道和密度等輸入信息，先解決缺失或不匹配項。需要準備程序時進入“管理 Multiwfn 安裝”，安裝或驗證目標環境中的程序。對接 pose 或 MD 幀可以保存為後續量化計算的幾何來源；波函數檔案需由相應量化計算生成，再導回檢查。

12.4 建立分析任務與查看三維密度

在“波函數分析”填寫 Multiwfn 程序路徑、方法、CPU 執行緒和超時，點擊“預覽任務”。確認輸入電子態、方法和許可後“保存任務（不計算）”，再單獨“提交計算”。

密度任務需填寫網格起點、間距和點數，長度單位為 Bohr。檢查網格是否覆蓋目標區域及總點數是否合理。完成後“加載三維密度”，設置等值面閾值並“更新等值面”。

依輸入檢查選取檔案支援的方法。Mulliken 或 Löwdin 電荷需要相應的基組資料，變更副檔名無法補齊。

12.5 導出與保留分析檔案

通過“導出檔案”保存 cube、日誌、方法結果及任務設置。需要搬遷時進入“任務檔案”，預覽後“選擇目錄並建立檔案”；大批複製可暫停與繼續。

“導入任務檔案”用於離線查閱已有結果。列表可以設置別名、隱藏或移除記錄；誤移除時在“已移除記錄”中“還原記錄”。記錄管理與原始計算數據分開處理，清理磁盤前仍應核對檔案用途。

13. 連接自己的電腦或服務器

離開電腦以後，可以從手機查看計算進展、記錄想法，並繼續處理待提交計劃。先完成服務連接與設備配對，再進入後面的操作。

13.1 連接服務並登錄

先在電腦端準備好監控服務，並確認手機可以訪問該服務。服務地址由自己的部署或管理者提供；不要把服務器的 SSH 地址填進賬號服務地址欄。

  1. 點擊底部“我的”，進入“賬號與設備”。也可以從“設置”進入“賬號、設備與通知”。
  2. 在“服務地址”中填寫已配置的地址，點擊“連接服務”。
  3. 填寫“郵箱”和“密碼”，點擊“登錄”。
  4. 如使用的服務已開放注冊，點擊“創建新賬號”，填寫“顯示名稱”、郵箱和密碼後點擊“注冊”。若頁面要求驗證郵箱，完成郵件驗證後點擊“返回登錄”，再登錄。

檢查結果： 登錄表單收起，頁面顯示當前賬號和“我的監控設備”。沒有已綁定設備時，繼續完成配對。

常見失敗與恢復： 連接失敗時先核對服務地址和電腦端服務是否運行。登錄失效時重新登錄；提示需要驗證郵箱時，可點擊“重新發送驗證郵件”，再檢查收件箱和垃圾郵件。服務尚未配置郵件時，應先由管理者完成配置，反復點擊不會解決問題。“本機只讀連接”用於當前設備上的本地服務，不是連接另一台電腦的快捷方式。

13.2 用一次性配對碼綁定設備

  1. 在電腦端監控 Agent 生成新的配對碼，確認電腦與手機使用同一個服務地址。
  2. 回到手機“賬號與設備”，在“一次性配對碼”中輸入該碼，點擊“綁定設備”。
  3. 手機提示等待電腦確認後，回到電腦端核對並確認申請綁定的賬號。
  4. 在手機點擊“刷新設備”。

檢查結果： 電腦出現在“我的監控設備”中。手機確認只是配對的第一步，電腦端確認完成後才能正常選擇設備。

常見失敗與恢復： 配對碼無效、已使用或已過期時，在電腦端重新生成，不要繼續重復使用舊碼。一直停在等待確認時，核對電腦端是否已確認正確賬號，以及兩端服務地址是否相同。

13.3 選擇要查看的設備

  1. 在“我的監控設備”找到目標電腦，檢查設備名稱、最近聯繫時間和狀態報告時間。
  2. 點擊“查看此設備”，返回“進展”。
  3. 如需切換電腦，重新打開“我的”，在另一台電腦的卡片上點擊“查看此設備”。

檢查結果： 已選設備有選中標記；首頁按當前連接顯示運行。計算可能在所選電腦本機，也可能由它連接的服務器執行，查看運行時還要核對“本機計算”或“遠程計算”。

常見失敗與恢復： 設備列表尚未確認時先點“刷新設備”。設備斷連時檢查電腦是否休眠、監控 Agent 是否運行以及網絡是否可用；斷連本身不表示計算已經失敗。不要把一條運行的連接異常當成全部設備都已離線。

13.4 查看訪問權限與解除綁定

  1. 打開“我的”，點擊“刷新設備”，查看設備卡片上的權限說明和授權有效期。
  2. 只查看運行時，使用當前查看權限即可。需要修改計劃或提交計算時，在電腦端為該設備開啓相應限時授權，再回手機刷新。計劃操作見第 18 章。
  3. 不再使用某台設備時，先導出需要保留的研究記錄，再點擊該設備的“解除綁定”，閱讀提示後確認。

檢查結果： 刷新後權限說明與電腦端授權相符。解綁後，該設備不再向此賬號繼續提供監控內容；已有計算仍在原電腦或服務器上運行。

常見失敗與恢復： 權限未確認或已到期時，回電腦端檢查授權，再點“刷新設備”，不要反復嘗試不可用的編輯按鈕。解綁、退出賬號或切換連接前，應先處理需要保留的本機記錄；相關本機副本會按頁面提示清理。

14. 找到運行並讀懂進展

14.1 從進展首頁找到需要處理的運行

  1. 點擊底部“進展”。
  2. 查看“任務概覽”中的“全部運行”“進行中”和“需關注”；點擊相應統計進入對應運行列表。
  3. 在“最近運行”中找到目標，點擊“查看詳情”。需要更多記錄時，點擊“查看全部運行與專案”。
  4. 在詳情中同時查看“計算端更新”和“成功讀取”時間：前者表示計算端數據的更新時間，後者表示手機成功取得數據的時間。

檢查結果： 運行名稱、專案、計算類型和計算位置符合要查看的對象。看到“上次進度”或“狀態未知”時，按最後一次讀取的信息理解，不當作實時進度。

常見失敗與恢復： 首頁沒有預期運行時，先核對所選設備，再進入“研究”搜索。讀取尚未完成或連接中斷時，檢查連接後點擊刷新圖標“刷新任務”，不需要重新提交計算。

14.2 按專案、類型和狀態查找運行

  1. 點擊底部“研究”，在“搜索名稱、專案或編號”中輸入要找的名稱或關鍵詞。
  2. 用“全部專案”和“全部計算類型”選擇專案及 Docking、MD 等類型。
  3. 根據需要選擇“全部”“進行中”“需關注”或“已完成”。展開“引擎與計算位置”，繼續按引擎、本機或遠程計算篩選。
  4. 用“上一頁”“下一頁”瀏覽結果；重新開始查找時，點擊“清空篩選”。

檢查結果： 列表上方顯示搜索範圍。當前目錄搜索覆蓋全部分頁；賬號連接搜索覆蓋當前設備已同步的記錄，而不是僅搜索屏幕上這一頁。

常見失敗與恢復： 找不到記錄時，先清空篩選再搜索，並確認專案和類型沒有選錯。如果頁面提示只同步了部分記錄，範圍之外的歷史應回電腦端查找。離線時搜索僅覆蓋本機保存的副本。

14.3 設置刷新頻率與恢復讀取

  1. 開啟「設定」，在「語言」選擇「繁體中文」，以便對照本手冊。
  2. 在“刷新頻率”選擇需要的讀取間隔，或選擇“手動刷新”。當前提供 5 秒、10 秒、15 秒、30 秒、1 分鐘、2 分鐘和 5 分鐘，以及手動刷新。
  3. 回到首頁，點擊刷新圖標“刷新任務”立即讀取。結果或日誌讀取失敗時，在詳情頁點擊“重新讀取”。

檢查結果： 最近成功讀取時間更新；選擇手動刷新後，不再按固定間隔主動讀取。更改刷新頻率、關閉頁面或鎖屏不會暫停計算端的任務。

常見失敗與恢復： 時間沒有更新時，先查看連接提示。恢復網絡後仍無法讀取，回“我的”刷新並確認設備，再重新讀取；保留下來的舊頁面只供參考。

14.4 在消息中心篩選通知並打開對應運行

  1. 登錄並配對電腦後，點擊底部“消息”，打開“消息中心”；點擊“刷新消息”讀取最新列表。
  2. 在“閱讀狀態”選擇“全部”“未讀”或“已讀”；在“事件類型”選擇“全部事件”“失敗”“完成”或“連接變化”。用“上一頁”“下一頁”查看較早消息。
  3. 點擊消息上的“標為已讀”或“標為未讀”整理閱讀狀態。需要處理消息時，點擊“查看異常日誌”“查看運行”或“查看設備”：App 會切換到通知對應的設備，打開異常日誌、運行結果或設備進展首頁。成功打開目標後，該消息自動標為已讀。
  4. 從失敗通知進入任務日誌時，核對通知時間和嘗試次數。如果頁面提示通知對應的嘗試與當前嘗試不同，下方展示的是當前嘗試的日誌；舊嘗試請回電腦端查看。

檢查結果： 消息卡片顯示“未讀”或“已讀”，頂部顯示未讀數量，篩選後列表隨之變化。“已讀”只表示消息的閱讀狀態，不表示故障已經解決。通知描述歷史事件，判斷當前運行狀態仍需查看打開後的進展和讀取時間。

常見失敗與恢復： 出現登錄提示時點擊“前往登錄”；消息更新失敗時檢查連接後點“刷新消息”，已加載內容仍保留。沒有符合篩選的消息時，先將兩個篩選恢復為“全部”和“全部事件”。設備已撤銷綁定的通知只保留為歷史記錄，不能繼續跳轉；通知或運行不可訪問時，核對賬號及綁定設備，並回電腦端查找原記錄。看到舊嘗試提示時，不要用當前日誌解釋舊通知中的失敗。

15. 查看結果與排查日誌

15.1 查看 Docking 結果

  1. 在“研究”選擇 Docking 運行，點擊“查看詳情”，打開“結果摘要”。
  2. 對照每項結果的配體、受體、隨機種子和嘗試次數，確認正在查看哪一次計算。
  3. 查看構象的評分名稱、評分數值、“越高越優”或“越低越優”提示，以及已有 QC 記錄。
  4. 用“上一頁”“下一頁”瀏覽更多結果。想留待比較的構象，可點擊“候選記錄”，按第 16 章保存。

檢查結果： 結果有讀取時間，並按任務分頁；每項最多展示五個構象。缺失評分或 QC 時按頁面的缺失提示處理，不補成零分或“通過”。

常見失敗與恢復： 顯示“尚無任務結果”時，先檢查運行是否仍在排隊或計算，再查看日誌。讀取失敗可“重新讀取”。不同引擎的分數保留各自含義，不跨引擎平均，也不把分數直接當成結合或活性的實驗結論。

15.2 查看 MD 進度、檢查點和已有分析

  1. 在“研究”的“全部計算類型”中選擇 MD，再打開目標運行的“查看詳情”。
  2. 在“結果摘要”查看模擬時間與目標時間、運行速度、步數和檢查點情況。
  3. 核對是否從檢查點續跑，以及當前顯示的嘗試和來源嘗試。
  4. 如果運行已有分析結果或獨立分析記錄，查看頁面展示的分析摘要；需要繼續配置或運行分析時，回到電腦端處理。

檢查結果： 頁面展示已讀取的模擬進度和檢查點信息；沒有提供的數據保持缺失。檢查點“有”表示發現了檢查點，不表示手機已經執行續跑。

常見失敗與恢復： 沒有分析區時，先在電腦端確認是否已生成可讀取的分析結果。頁面顯示可續跑提示時，在電腦端核對並繼續；不要把時間達到目標或程序結束寫成軌跡已收斂、機制已確認。

15.3 選擇正確的日誌

  1. 從運行詳情切換到“錯誤與日誌”，或點擊運行卡片上的同名入口。
  2. 選擇“Worker”查看執行端輸出，選擇“調度器”查看調度相關輸出。
  3. 要追查某條 Docking 結果，在該結果下面點擊“查看任務日誌”。打開後，任務日誌標籤對應這條結果。
  4. 點擊“更早日誌”向前查看，點擊“最新日誌”回到最新可讀取內容。

檢查結果： 日誌區標明讀取時間、當前字節範圍和總大小。先確認日誌類型及嘗試次數，再解釋具體報錯。

常見失敗與恢復： “日誌尚未生成”不等於日誌被清空，可稍後點“最新日誌”。從歷史消息進入日誌時，如頁面提示嘗試次數不一致，應回對應運行核對，不能把當前日誌直接當作那次歷史失敗的輸出。

15.4 搜索、跟隨和複製日誌

  1. 在“搜索當前日誌頁”輸入關鍵詞，用箭頭按鈕“上一個匹配”“下一個匹配”定位。
  2. 點擊“只看錯誤關鍵詞”篩選包含相關關鍵詞的行；需要完整上下文時再次點擊關閉篩選。
  3. 在連接可用且設置了自動刷新間隔時，點擊“跟隨最新”。搜索、向上閱讀或打開舊日誌頁會暫停跟隨；讀完後再次點擊“跟隨最新”恢復。
  4. 需要複製當前頁時，點擊“複製本頁”。

檢查結果： 頁面顯示匹配數量，跟隨開啓時按鈕顯示“正在跟隨”。搜索和錯誤篩選只覆蓋當前頁，每頁最多 16 KiB；行號也是本頁行號。“複製本頁”複製當前頁，不是下載完整日誌。

常見失敗與恢復： 搜索無匹配時可以翻到更早日誌繼續找。跟隨按鈕不可用時，檢查是否處於離線副本或“手動刷新”；手動模式可直接點“最新日誌”。複製失敗時長按選擇日誌文字。錯誤關鍵詞只是閱讀輔助，還需要結合退出碼和前後文判斷原因。

16. 寫筆記、收藏與對照候選

16.1 為一次運行保存筆記和收藏

  1. 打開運行“查看詳情”，點擊“運行筆記”。
  2. 需要經常回看的運行，勾選“收藏運行”。
  3. 在“研究處理狀態”選擇“待查看”“已查看”或“待討論”，在“備注”寫下判斷、問題或下一步安排。
  4. 點擊“保存記錄”。以後從“研究”打開“研究記錄”，在“運行筆記”中找到它；點擊“編輯記錄”可繼續修改。

檢查結果： 列表顯示收藏標記、處理狀態、備注和記錄更新時間。這裡的“已查看”只是研究筆記狀態，不會把計算運行改為“已完成”。記錄先保存在本機。

常見失敗與恢復： 保存失敗時保持編輯頁，檢查本機存儲後重試。看不到以前的記錄時，先確認當前賬號和所選設備。關閉未保存的編輯時會詢問是否放棄修改；想保留內容應返回並點“保存記錄”。

16.2 將構象加入候選清單

  1. 在 Docking“結果摘要”中找到要記錄的構象，點擊其“候選記錄”。
  2. 核對記錄中的來源和評分，再選擇“研究處理狀態”、填寫“備注”。
  3. 點擊“保存記錄”，從“研究記錄”切換到“候選清單”查看。
  4. 點擊“查看來源運行”返回原運行；需要更多來源字段時，在記錄中展開“查看完整來源”。

檢查結果： 候選清單保留所選構象的來源、評分及讀取時間，不只是複製一個分數。對同一候選繼續使用“編輯記錄”，可以更新筆記。

常見失敗與恢復： 沒有穩定構象標識時，“候選記錄”按鈕不可用，應先在電腦端核對結果。來源暫時無法打開時，已保存的來源信息仍可查看；恢復對應連接後再點“查看來源運行”。“刪除記錄”刪除的是研究記錄，原始計算結果不受影響；如記錄已關聯同步，應先閱讀實際確認提示。

16.3 對照兩到四條記錄

  1. 打開“研究記錄”，選擇“運行筆記”或“候選清單”。
  2. 勾選要比較的記錄上的“選擇用於對照/導出”，選擇兩到四條。
  3. 點擊“對照已選”，進入“結果對照”。
  4. 橫向滑動查看不同記錄，核對來源、引擎、評分名稱、已有參數、讀取時間和備注；淺色區域標出不同值。

檢查結果： 對照頁並列展示已保存信息，缺失項顯示為“—”。頁面會提示記錄上下文是否相同；即便相同，也需要核對具體科學條件。

常見失敗與恢復： 少於兩條或多於四條時，“對照已選”不可用，調整勾選數量即可。來自不同受體、運行或評分上下文的記錄可以並列查看，但不能據此混排或合併評分。若記錄過舊，先回來源運行讀取並更新需要保存的內容。

16.4 導出摘要並確認保存

  1. 在“研究記錄”勾選條目後點擊“導出已選”；需要當前類別全部記錄時點擊“導出此列表”。對照頁也可以展開“導出摘要”。
  2. 在“檔案格式”選擇“Markdown (.md)”或“JSON (.json)”，檢查“導出預覽”。
  3. Android 介面提供“保存檔案”和“分享檔案”；iOS 提供“保存或分享檔案”；瀏覽器介面提供“下載檔案”。按當前平台顯示的按鈕繼續，並在系統介面選擇目的位置或接收應用。
  4. 不需要檔案時，也可以點“複製文本”。分享前先檢查備注和來源信息，移除不準備對外發送的內容。

檢查結果： 在所選保存位置打開檔案，或到接收應用確認內容。導出包含已保存記錄、備注和來源摘要，不是完整分子庫、軌跡或全部計算檔案。

常見失敗與恢復： 取消系統保存或分享不會刪除原記錄。導出未完成時可返回重新操作，或用“複製文本”。“已打開系統分享介面”僅表示介面已打開，不能代替目標應用已收到的確認。

17. 保留頁面並離線查看

17.1 保存運行摘要和需要的頁面

  1. 在連接可用時打開目標運行的“查看詳情”，等待讀取完成。
  2. 點擊“保存運行摘要”。需要結果或日誌時，先打開對應頁，再點擊“保留當前已讀取頁”。
  3. 翻到其他需要的結果或日誌頁，逐頁讀取並保留。
  4. 展開“已保存的結果與日誌頁”，檢查哪些內容標為“已主動保留”，並核對頁範圍、讀取時間和保存時間。

檢查結果： 操作成功後顯示已保留提示。摘要和每個選定頁面分開保存；保存摘要不會自動下載整次運行。後續在線讀取會更新對應副本，因此它保存的是最近讀過的內容，不是凍結不變的備份。

常見失敗與恢復： “保留當前已讀取頁”不可用時，先等待當前頁成功讀取。容量已滿時，按 17.3 取消不需要的保留後重試；提示本次未保存時，不要把屏幕上的內容當作已經可靠保存。

17.2 離線重開與檢查缺頁

  1. 保持原賬號和原連接，重新打開 App。查看頁面上的“離線副本”和原讀取時間。
  2. 進入“設置”里的“離線記錄”，展開“主動保留的運行”，點擊目標運行的“打開已保留資料”。
  3. 在運行詳情展開“已保存的結果與日誌頁”，點擊需要的頁。
  4. 連接恢復後，回首頁點擊“刷新任務”；需要更新某頁時再重新讀取該頁。

檢查結果： 離線時展示已讀副本，保留原始讀取時間，不顯示為新的實時進展。普通讀取也會自動緩存最近內容，主動保留則用於留下明確選擇的摘要和頁面。

常見失敗與恢復： “此頁尚未保存”時，從已保存頁面列表選擇已有頁；要取得缺頁，需恢復連接後讀取。離線列表沒有運行時，檢查是否切換了賬號或設備。退出賬號或解除綁定會清理相應本機記錄，不能用重新登錄保證恢復未導出的內容。

17.3 管理容量和取消保留

  1. 打開“設置 → 離線記錄”，查看當前連接、全 App 和主動保留內容的用量。
  2. 在“主動保留的運行”點擊“取消保留”，可取消整次運行的主動保留；在運行詳情的已保存頁面列表中，也可以對單頁點擊“取消保留”。
  3. 如需取消該運行全部保留，可在詳情點擊“取消此運行全部保留”，確認後再查看用量。
  4. 只有確定不再需要當前連接的本機副本時，才點擊“清除當前連接的離線記錄”，閱讀確認提示後繼續。

檢查結果： 當前全 App 上限為 40 個運行、每運行 12 頁結果或日誌、總計 20 MiB。主動保留佔用同一額度，但不會被自動淘汰；取消保留後內容回到可淘汰的自動緩存。清理本機副本不刪除服務器上的原始結果。

常見失敗與恢復： 取消保留不一定立即讓用量變為零，因為自動緩存可能仍在。無法保存或清理時先檢查本機存儲，保留仍可讀取的內容，不用退出賬號來代替正常的容量管理。

18. 編輯待提交計劃並確認計算

18.1 打開桌面專案或已有計劃

  1. 在桌面端保存準備好的專案；手機讀取的是已保存內容，不包含桌面尚未保存的修改。
  2. 在桌面端打開“設置 → 手機專案與任務授權”，選擇已綁定監控 Agent 的 Device.json，設置授權時長。默認僅允許編輯計劃；需要從手機提交計算時，在同一授權頁另外勾選“允許手機確認後提交真實計算任務”。勾選授權本身不會啓動計算，仍需完成 18.4 的手機確認。
  3. 回手機“我的”，確認已選擇正確設備並刷新權限。從“研究”里的“專案與計算計劃”點擊“打開計劃”；也可從登錄後的賬號頁點擊“專案與計劃”。
  4. 點擊“桌面專案”，在目標專案上選擇“配置新計劃”；或者點擊“已保存計劃”，對已有計劃選擇“查看計劃”。
  5. 核對專案名稱、計算主機、引擎和任務數量，再進入參數設置。

檢查結果： 從桌面專案創建的是獨立待提交計劃，原專案保持不變。已有計劃只有處於待提交且尚未開始執行時，才可進入支持的編輯操作。

常見失敗與恢復： 沒有專案或計劃時，先在電腦端確認已保存，再點“刷新計劃”。權限失效或與預期不符時，回桌面“設置 → 手機專案與任務授權”核對所選 Device.json 是否屬於已綁定的 Agent、授權時長及提交勾選狀態，重新授權後回手機刷新。專案提示不能創建移動計劃時，回電腦端檢查；不要把運行中的任務當成可編輯計劃。

18.2 修改參數並恢復本機草稿

Docking 與 MD 在手機上的參數表不同，按當前計劃實際顯示的字段操作。

  1. Docking 計劃可調整“每個配體 CPU 執行緒”“並行配體數”“搜索強度”“最大 pose 數”“評分函數”和“隨機種子”；顯示“能量範圍（kcal/mol）”時再按需要調整。單個 Box 的表單提供“Box 中心（Å）”“Box 尺寸（Å）”及 X、Y、Z 輸入。
  2. GNINA 計劃顯示“執行模式”，可在“僅 CPU（禁用 GPU）”與“允許使用 GPU（取決於主機）”之間選擇；“CNN 評分模式”是當前配置說明，不是此頁的編輯控件。專案有多個受體各自的 Box 時，在電腦端修改 Box。
  3. MD 計劃可調整“每個 rank 的執行緒”“MPI rank 數”“GPU 數”“記憶體（GiB）”“隊列時限”“分區”“計算賬號”“QoS”“最長運行時間（小時）”和“計算模式”。這裡調整執行資源，不修改已有 TPR 中的科學設置。
  4. 編輯後檢查“修改已保存在本機，尚未發送到桌面”的提示。重開後可從“本機未保存修改”選擇“恢復本機草稿”，用“查看草稿輸入”核對原值；聯網刷新來源後再繼續預覽。

檢查結果： 輸入符合字段標出的單位和範圍。本機草稿只是手機保存的輸入，尚未保存成電腦端計劃，更沒有開始計算。隨機種子按表單說明用逗號分隔；隊列時限按輸入框顯示的時間格式填寫。

常見失敗與恢復： 字段標紅時修改對應值。桌面來源已改變時，先用“查看草稿輸入”保留核對依據，再“刪除本機草稿”，按最新來源重新編輯。不要用舊草稿覆蓋已變化的專案。出現本機保存失敗提示時保持當前頁，檢查存儲後再繼續。

18.3 預覽差異並保存待提交計劃

  1. 在參數表中完成修改後，點擊“預覽修改”。
  2. 在“確認修改差異”逐項核對“修改前”和“修改後”。從桌面專案創建新計劃時，還要核對展示的資源摘要。
  3. 確認修改正確後，點擊“確認 · 保存為待提交計劃”。
  4. 查看保存提示；有操作回執時，展開“桌面回執已核實”檢查此次操作，再回“已保存計劃”核對。

檢查結果： 頁面明確提示“已保存為待提交計劃，未提交任何計算”，或提示已保存獨立計劃、原專案不變。完成這一步只是保存，計算尚未啓動。

常見失敗與恢復： 修改已有計劃時，沒有參數變化會提示先修改再預覽；從桌面專案配置新計劃則可以沿用原參數。預覽過期、計劃或輸入已改變時，返回列表“刷新計劃”，重新核對並預覽。若顯示保存結果未知，保留原操作，使用“查詢 / 重試同一次保存”恢復結果，不另建替代計劃。

18.4 核對資源、提交並恢復未知結果

  1. 在電腦端為當前設備開啓限時“允許提交”，回手機刷新計劃。先將本機修改保存到桌面，或明確刪除不再需要的本機草稿。
  2. 打開已保存的待提交計劃，點擊“核對計算提交”。
  3. 在“計算提交確認”檢查主機、引擎、任務數量、CPU 與並行數，或 MD 的執行緒、rank、GPU、記憶體和隊列時限。確認這些資源與自己的使用安排相符。
  4. 勾選“已核對主機、引擎、任務數量及資源，確認啓動此次計算。”，再點擊“開始計算”。這一步會向計算端提交真實計算，應只對準備執行的計劃操作。
  5. 點擊“刷新計劃狀態”。出現關聯運行後，用“進度與結果”“報錯與 Worker 日誌”或“調度器日誌”繼續查看。

檢查結果： 頁面先記錄提交，再顯示計劃的當前狀態。已提交或排隊中不等於計算完成；以刷新後的狀態和關聯運行信息為準。

常見失敗與恢復： “開始計算”不可用時，檢查是否已勾選確認、提交授權是否有效，以及是否還有未處理的本機修改。連接中斷後出現提交結果未知，使用“恢復同一次提交”或“刷新計劃狀態”，不要另建計劃重復提交。重開 App 後也應回到原賬號、原服務和原電腦處理保留的回執。若提示回執存儲異常，先恢復本機存儲並保留原操作，不通過清空數據繞過它。
