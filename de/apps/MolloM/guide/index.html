MolloM – Benutzerhandbuch

Vom Einrichten eines Desktopprojekts bis zum Prüfen von Läufen und Ergebnissen auf dem Smartphone: die Arbeitsabläufe in MolloM.

Für den ersten Versuch genügt ein Ligand. Laden Sie das öffentliche Beispiel, speichern Sie das Projekt und suchen Sie Rezeptor, Referenzligand und Suchbox in der 3D-Ansicht. Öffnen Sie nach einem kleinen Vina-Lauf die Pose und den Score. Mit einer vorhandenen Trajektorie beginnen Sie bei der Analyse.

Die Desktop-Anleitung wurde für die Entwicklungsversion 0.301.0 geprüft. Die Abbildungen zeigen einen früheren Stand. Ihre Version steht in den Einstellungen; verfügbare Builds unter Downloads. Für einen eigenen KI-Client gibt es die Einrichtung und den Leitfaden für den Agenten (Markdown).

1. Erste Schritte

1.1 Einen ersten Auftrag auswählen

Verwenden Sie einen vertrauten Rezeptor sowie einige Liganden. Führen Sie die Vorgehensweise durch: Importieren, Vorbereitung, Verwendung des Suchfelds, kleine Tests sowie die Überprüfung der Ergebnisse. Anschließend können Sie eine große Bibliothek verwenden.

Falls Sie bereits ein GROMACS-System haben, beginnen Sie mit Kapitel 10. Falls Sie eine Datei mit der Wellenfunktion haben, beginnen Sie mit Kapitel 12. Für den Betrieb von mobilen Geräten sowie für Planungseingaben sollten Sie Kapitel 13 auswählen. Die Bereitstellung von Daten für die Docking-Operationen sowie die Berechnung der Molekülstrukturen erfordern getrennte Eingabepunkte. Keines dieser Konzepte ist Voraussetzung für das andere.

1.2 Arbeitsplatz und Rechenrechner wählen

Verwenden Sie die Desktop-Anwendung, um die Strukturen vorzubereiten, Programme zu konfigurieren, Berechnungen zu planen und die Ergebnisse zu überprüfen. Wählen Sie einen loklichen Computer oder einen SSH-Server als Ausführungshost. Geben Sie die Pfade der Programme, die Pfade für die Eingabedaten sowie die Ressourcen für diesen Host ein: Die Remote-Pfade werden auf dem Server angezeigt, die lokalen Pfade auf Ihrem Computer.

Nachdem Sie das Telefon mit dem Überwachungsdienst verbunden haben, können Sie die Ausgaben, Ergebnisse und Protokolle des verbundenen Geräts überprüfen. Zudem können Sie die noch auszuführenden Planungen bearbeiten – solange die entsprechenden Berechtigungen noch gültig sind. Bevor Sie den Desktop verlassen, stellen Sie sicher, dass der Rechner weiterhin aktiv bleibt und der Überwachungsdienst weiterhin läuft.

1.3 Projekte und Einstellungen öffnen

Unter „Projekte und Vorlagen“ erstellen Sie ein neues Projekt, öffnen Sie die JSON-Datei des Projekts oder laden Sie die öffentliche Beispieldatei. Wählen Sie die Sprache Ihrer Benutzeroberfläche in den Einstellungen aus.

Bevor Sie das Beispiel ausführen, überprüfen Sie zuerst die Eingabedateien, den ausgeführten Computer- und die Suchbereich. Führen Sie zunächst einen kleinen Test durch. Verwenden Sie die Wertvorstellungen der Vorlagen als Ausgangspunkt und passen Sie diese an die Ihren Strukturen sowie der Forschungsfragen an.

Erste Abfrage per MCP. Öffnen Sie auf dem MolloM-Rechner einen Client mit MCP über stdio und Zugriff auf Node.js ab Version 18. Wählen Sie unter Einstellungen → AI Agent · MCP den Lesezugriff und übernehmen Sie die Berechtigung. Sobald der Dienst läuft, kopieren Sie das Verbindungs-JSON und ergänzen damit die vorhandene MCP-Konfiguration des Clients. Verwenden Sie die erzeugten Pfade; der Inhalt der Verbindungsdatei gehört nicht in den Chat. Lassen Sie MolloM geöffnet, verbinden Sie den Client erneut und geben Sie ihm den Agentenleitfaden. Erste Anfrage: „Liste höchstens fünf Docking-Läufe auf. Ich wähle einen aus, bevor du seinen Status liest.“ Auch eine leere Liste kann eine erfolgreiche Antwort sein. Für Schreibzugriffe die Aufgabensteuerung ausdrücklich aktivieren, übernehmen und neu verbinden.

2. Rechenumgebung einrichten

2.1 Lokal ausführen

  1. Open Compute Environment and Software Center – Wählen Sie die lokale Ausführung aus.
  2. Erkennen Sie erneut die Umgebung und überprüfen Sie die von ihr identifizierten Programme.
  3. Wenn bereits ein Docking-Engine installiert ist, wählen Sie das eigentliche ausführende Programm aus – beispielsweise das Vina-Binary.
  4. Prüfen Sie, ob das Arbeitsverzeichnis beschreibbar ist und genügend freier Speicherplatz vorhanden ist.

Nach der Überprüfung der möglichen Pfade sollten Sie einen kleinen, realen Test durchführen. Hier werden die fehlenden Bibliotheken, Modelldaten oder Geräte-Treiber am ehesten auftauchen.

2.2 Per SSH verbinden

  1. Fügen Sie einen Server hinzu, wobei Sie entweder den Hostnamen des Servers verwenden oder einen SSH-Konfigurationsalias verwenden können.
  2. Geben Sie Benutzername und Port an und wählen Sie die Systemauthentifizierung oder eine Schlüsseldatei. Fügen Sie nie einen privaten Schlüssel in ein gewöhnliches Textfeld ein.
  3. Geben Sie den Arbeitsverzeichnis des Servers sowie die Pfade für die Fernausführung von Befehlen ein. Falls eine Python-Pfade erforderlich sind, verwenden Sie den auf dem Server vorhandenen Pfad.
  4. Speichern Sie den Server, testen Sie anschließend die Verbindung und überprüfen Sie die Umgebungsbedingungen.

Prüfen Sie bei der ersten Verbindung den Fingerabdruck des Hosts. Bei einem unbekannten Host oder Anmeldefehler testen Sie die Verbindung zuerst im SSH-Client des Systems, dann in MolloM. Startet ein vorhandenes Programm nicht, prüfen Sie die Diagnoseausgabe, Berechtigungen, Abhängigkeiten und Umgebung.

Auf einem Cluster den für diese Aufgabe angebotenen Scheduler wählen und Partition oder Warteschlange, Konto, Zeitlimit und Ressourcen angeben.

Einen unbekannten Host-Fingerabdruck mit der Administration abgleichen. Bei einem Anmeldefehler Benutzername und Schlüssel prüfen, nach erfolgreicher SSH-Anmeldung bei einem Laufzeitfehler das entfernte Python. Unter Slurm bedeutet PENDING / Priority Warten auf Ressourcen; bei QOSMinGRES die Mindestanforderungen der Partition prüfen.

2.3 Programme installieren oder registrieren

Im Software Center wählen Sie das lokale Computer oder das Zielserver aus und aktualisieren die Liste der verfügbaren Software. Um eine bestimmte Version zu installieren, lesen Sie zunächst den Installations- und Verifizierungsplan durch – dabei sollten auch die Angaben zur Lizenz und zu den Abhängigkeiten berücksichtigt werden.

Für eine bereits vorhandene Installation sollten Sie diese noch einmal überprüfen, bevor Sie sich für diese Version entscheiden. Einige Einträge in der Liste enthalten Anweisungen zur Installation von der Quelle her. Zudem können Sie auch die von Ihnen separat installierte Software registrieren lassen. Lesen Sie den Ausgangstext der fehlgeschlagenen Überprüfung, bevor Sie weitermachen. Das Vorhandensein eines Verzeichnisses bedeutet nicht unbedingt, dass die Software funktioniert.

3. Projekt anlegen und Strukturen importieren

3.1 Ein Projekt sinnvoll benennen

Erstellen Sie ein neues Projekt unter „Projekte und Vorlagen“. Geben Sie diesem Projekt einen Namen, der die Thematik und den Zweck des Projekts beschreibt. Ein Projekt kann mehrere Iterationen oder Screening-Rounds enthalten. Eine geringfügige Anpassung erfordert keine Kopie aller Dateien.

Speichern nach dem Ändern der wichtigen Einstellungen. Exportieren Sie die JSON-Datei ausschließlich für die Projektübergaben; verwenden Sie außerdem das „Portable Package“ aus Kapitel 9, um auch die Eingabedaten sowie die Ergebnisse zu übernehmen.

3.2 Rezeptoren und Liganden hinzufügen

  1. Unter „Receptoren und Liganden“ fügen Sie einen Receptor aus einer PDB- oder PDBQT-Datei hinzu.
  2. Wählen Sie die entsprechenden Liganden-Dateien aus, oder geben Sie den Ordner an, in dem sich die Dateien befinden. Alternativ können Sie auch die Dateien auf dem Server durchsuchen.
  3. Wählen Sie den gewünschten Eingabeformat aus: PDBQT, SDF/SD, MOL2, MOL oder SMILES.
  4. Überprüfen Sie erneut die eingegebenen Daten. Stellen Sie außerdem sicher, dass die Anzahl der Daten sowie die Probleme bei der Parsing der Daten korrekt sind.

Eine SDF-Datei kann mehrere molekulare Daten enthalten. Daher können die Anzahl der Dateien sowie der Anzahl der Daten variieren. Überprüfen Sie die problematischen Daten und entscheiden Sie, ob sie korrigiert, ausgeschlossen oder wieder bereitgestellt werden sollen, bevor Sie mit der Weiterverarbeitung des Datensatzes fortfahren.

3.3 Herkunft nachvollziehbar halten

Bewahren Sie die ursprünglichen Dateien sowie die identifizierbaren Molekül-Identifikatoren auf. Die vorbereiteten Arbeitsunterlagen sollten weiterhin mit einem gemeinsamen „Vater“ verknüpft bleiben können. Nennen Sie die Rezeptoren klar, wenn Sie Strukturen oder Konformationen in einem Projekt vergleichen.

Verwenden Sie die von der ursprünglichen Datei erstellten Arbeitskopien nicht, um die ursprünglichen Dateien zu überschreiben. Die Vorbereitungsstufe erzeugt Arbeitskopien, die Sie separat überprüfen können.

4. Rezeptoren und Liganden vorbereiten

4.1 Bestandteile des Rezeptors auswählen

Bei der Strukturvorbereitung sollten Sie angegebenen Ketten oder den Feldeingaben „leer“ lassen, um alle Ketten beizulegen. Bestimmen Sie außerdem, ob die übliche Wasserstoffverbindungen entfernt werden sollen oder ob die HETATM-Kofaktoren sowie Metalle weiterhin erhalten bleiben sollen. Überprüfen Sie zudem die strukturellen und literarischen Erkenntnisse, bevor Sie funktionelle Wasserstoffverbindungen, Metallionen oder Kofaktoren aus dem „Pocket“ entfernen.

Es müssen die fehlenden oder nicht standardmäßigen Residuen sowie die Protonation berücksichtigt werden. Der aktuelle Arbeitsablauf berücksichtigt Strukturen, die nicht unterstützt werden. Fehlende Loops sowie die Protonation bei der Ziel-Härte müssen separat bearbeitet werden.

4.2 Ligandenzustände vorbereiten

Wählen Sie aus, ob der größte „Parent“-Wert beibehalten werden soll, die möglichen tautomerischen Zustände auflisten sollen oder die Anzahl der Zustände pro Quelldatensatz begrenzt werden soll. Ungeschriebene Stereochemie werden standardmäßig ausgeschlossen. Aktivieren Sie diese Funktion nur dann, wenn Sie wissen, wie mit diesen spezifischen Eingaben umgegangen werden soll.

Erstellen Sie 3D-Koordinaten für die Eingaben, die diese Koordinaten nicht haben. Anschließend prüfen Sie die Anzahl der Elektronen, die Stereochemie sowie die Bindungen, bevor der Docking-Vorgang durchgeführt wird.

4.3 Änderungen nach der Vorbereitung prüfen

Prüfen Sie die Eingabedaten und die bereits fertiggestellten sowie problematischen Datensätze. Anschließend öffnen Sie den Ordner mit den Vorbereitungsdateien, um die Dateien zu überprüfen. Im Vergleich zwischen dem vorherigen und dem nachfolgenden Zustand sollten Sie die Anzahl der „schweren Atome“, die Formelchargen, die Fragmente sowie die Koordinaten überprüfen.

Bei Fehlern sollte man die Ursachen ermitteln. Speichern Sie die ursprünglichen Dateien und erstellen Sie neue, funktionierende Kopien. So können Sie die Änderungen nachvollziehen.

5. Suchbereich festlegen

5.1 Bindungstasche finden

In der 3D-Perspektive wählen Sie den Rezeptor aus. Sie können zwischen der Anzeige von Proteinen, Liganden und Oberflächen wählen. Um die Ansicht zu drehen, können Sie die Elemente bewegen. Für den Zoomvorgang können Sie scrollen. Falls nötig, können Sie die Ansicht auch wieder zurücksetzen.

Verwenden Sie einen Referenzliganden, um die Lage des Pockets zu bestimmen – sofern ein solcher Referenzliganden vorhanden ist. Der Referenzliganden muss die gleiche Koordinatensysteme verwenden wie der aktuelle Rezeptor. Ziehen Sie die Strukturen zuerst in die richtige Position, falls die Koordinaten aus einer anderen Struktur stammen.

5.2 Suchbox prüfen

Geben Sie Mittelpunkt und Kantenlängen (jeweils XYZ) in Ångström (Å) ein. Die Box soll den Zielbereich und den Liganden aufnehmen, ohne unnötig viel umliegenden Raum einzuschließen.

Überprüfen Sie jeweils die Kästchen der einzelnen Rezeptoren. Speichern Sie das Projekt anschließend und überprüfen Sie anschließend in den Ergebnissen, ob die erwarteten Ergebnisse tatsächlich angezeigt werden.

6. Docking-Programm und Ressourcen einrichten

6.1 Programm auswählen und prüfen

Finden Sie das Programm nach Namen oder Kategorie. Besuchen Sie dazu die Dokumentation des Programms und wählen Sie es für diese Runde aus. Stellen Sie sicher, dass das ausführende Programm auf dem Zielhost installiert ist und der Pfad korrekt ist.

Es ist besser, eine eingebettete Integration zu verwenden. Für eine benutzerdefinierte native Integration sollten Sie zunächst die Testbefehle sowie die Verarbeitung von Eingaben und Ausgaben an einer kleinen Menge an Daten ausprobieren.

6.2 Vina-Parameter und unabhängige Seeds festlegen

Wählen Sie „Vina“. Stellen Sie anschließend die Anforderungen bezüglich der Ausführungsgeschwindigkeit, des maximalen Ausgangswerts, des Energieverbrauchs sowie der Erfassungsfunktion fest. Je höher die Anforderungen sind, desto mehr Rechenressourcen werden benötigt. Verwenden Sie dazu einen Test, um zu entscheiden, was wirklich wichtig ist – anstatt alles zu maximieren.

Geben Sie eine Liste der unabhängigen Samen ein – je eine Suche pro Samenträger. Die Eingabe der Daten, der aktivierten Rezeptoren sowie der Samen zusammen bestimmen die Anzahl der Aufgaben. Überprüfen Sie den Namen der Runde sowie die Anzahl der Aufgaben vor der Eingabe, um unerwünschte Rezeptoren oder wiederholte Samen zu vermeiden.

6.3 Mit GNINA arbeiten

Wählen Sie aus, wie der CNN verwendet werden soll – beispielsweise ob er noch einmal ausgewertet oder weiter weiterverarbeitet werden soll. Sie können auch ein Modell auswählen oder den Feldeinstellungen entsprechend die Standardwerte verwenden. Wenn GPUs nicht verwendet werden sollen, wählen Sie bitte die Option „Nur auf der CPU ausführen“.

Prüfen Sie für GPU-Läufe Software, Treiber und zugewiesene Ressourcen. Lesen Sie im Testprotokoll nach, welcher Modus tatsächlich lief. Energie, CNNscore und CNNaffinity messen Unterschiedliches und haben jeweils eine eigene Sortierrichtung. Legen Sie die Filter getrennt fest.

6.4 Parallelität, CPUs und GPUs zuweisen

Die CPUs pro Auftrag bestimmen dessen Ressourcen; die Parallelität bestimmt die Zahl gleichzeitiger Aufträge. Ihr Produkt darf die zugewiesenen CPU-Ressourcen nicht ausschöpfen: Lassen Sie Spielraum für das Betriebssystem und Ein-/Ausgaben.

Überprüfen Sie die Warteschlangen, die Zeit, den Speicherverbrauch sowie die Anfragen an der GPU in einem Cluster. Überprüfen Sie auch den Durchsatz und den Speicherverbrauch vor der Skalierung. Eine höhere Konkurrenz auf der CPU kann dazu führen, dass ein Batch-Job langsamer abläuft, insbesondere wenn es um Speicher, GPU-Auslastung oder CPUs geht.

7. Kleinen Testlauf und Gesamtlauf starten

7.1 Eine kleine Stichprobe testen

Im Ansichtenbereich für Test und Timing können Sie die Größe des Liganden-Beispielobjekts festlegen. Anschließend können Sie den eigentlichen Test starten und seine Aufgaben öffnen. Dadurch wird das ausgewählte Programm ausgeführt und die verfügbaren Ressourcen auf dem ausgewählten Host werden genutzt.

Die Überprüfung der Ausgabe, die Erfassung der Ergebnisse sowie die Protokolle zeigen dies deutlich. Die Schätzungen berücksichtigen dabei dieses Beispiel sowie die Konfiguration – nicht jedoch das Warten, die Vorbereitung, die Übertragungen oder die Exportaktivitäten. Führen Sie eine weitere Testrunde durch, nachdem Sie den Motor, das Modell, die Ausführlichkeit oder den Host geändert haben.

Kontrollieren Sie für einen erfolgreichen Liganden die Pose in der Tasche, für einen fehlgeschlagenen das Originalprotokoll. Ein kleiner Ligand liefert für eine Bibliothek mit vielen großen Molekülen nur eine grobe Schätzung. Stichprobengröße und Parallelität festhalten; Wartezeit, Übertragung und Export zusätzlich einplanen.

7.2 Den Gesamtlauf einreichen

In den Bereichen „Aufgaben und Fortschritt“ sollten Sie die vorbereiteten Einstellungen, Rezeptoren, Samen sowie Ressourcen überprüfen. Anschließend sollten Sie eine neue Ausführung des Prozesses starten. Öffnen Sie außerdem die gespeicherten Parameter, um die tatsächliche Konfiguration zu überprüfen.

Die ausgeführten Aktionen, die fehlgeschlagen sind sowie die noch auszuführenden Aktionen können überwacht werden. Es ist auch möglich, die Protokolle oder die Verzeichnisse der ausgeführten Aktionen zu betrachten, um ein Problem zu identifizieren. Wenn die Einstellungen für eine neue Runde geändert werden, sollten die Ergebnisse unter den verschiedenen Bedingungen getrennt werden.

7.3 Lauf pausieren, abbrechen oder wiederaufnehmen

Beim Pausieren nimmt der Executor keine neuen Aufgaben an; laufende Aufgaben werden fortgesetzt. Heben Sie die Pause auf, wenn Sie bereit sind. Beim Abbrechen der verbleibenden Aufgaben bleiben bereits geschriebene Ergebnisse erhalten.

Wiederholen Sie nur fehlgeschlagene Aufgaben, bei denen ein neuer Versuch nötig ist. Erfolgreiche Ergebnisse und der Verlauf bleiben erhalten. Nach einem Verbindungsabbruch oder bei unbekanntem Status verbinden Sie sich erneut und aktualisieren den ursprünglichen Lauf, statt ihn erneut einzureichen. Ein unabhängiger Executor kann bei geschlossenem Fenster weiterlaufen; Ruhezustand, Herunterfahren und Abbruch durch den Scheduler müssen gesondert behandelt werden.

8. Ergebnisse filtern und die nächste Runde anlegen

8.1 Einträge zur Prüfung auswählen

Wählen Sie eine Veranstaltung aus der Kategorie „Results“ und „Screening“. Verwenden Sie dabei Filter für Namen, primäre Schwellenwerte oder fortgeschrittene Multimetrische Filter. Überprüfen Sie die Positionsangaben, Herkunft sowie die Metriken – nicht nur den ersten Wert.

Alle Bedingungen sollten für dieselbe Pose gelten. Die unabhängigen Bewertungsmethoden sollten nicht verwendet werden. Die Priorisierung der Strukturen erfolgt auf der Grundlage der Ergebnisse der Untersuchungen. Für die Bindung und die Aktivität der Strukturen sind unabhängige Beweise erforderlich.

8.2 Duplikate begrenzen, Vielfalt erhalten

Verwenden Sie jeweils nur einen Vertreter pro Elternteil – oder begrenzen Sie die Anzahl der Vertreter pro RDKit-Skaffo, wenn das erforderlich ist. Vermeiden Sie das Zusammenführen von Elementen, wenn es Unterschiede zwischen den verschiedenen Zuständen gibt, die mit der Abwärtarmung vergleichen werden.

Prüfen Sie die gefilterte Anzahl der Datensätze und wählen Sie die Datensätze aus, die weiterverwendet werden sollen. Bei ungewöhnlich hohen Punktzahlen, Konflikten oder unlogischen Angaben sollten Sie zunächst die Eingabedaten sowie die Geschichte der Vorbereitung überprüfen.

8.3 Eine neue Runde anlegen

Für die Offenen Sitzungen sollten Sie eine ausgearbeitete Version des Projekts auswählen, die Bedingungen festlegen und die Kandidaten überprüfen. Nennen Sie die nächste Runde und wählen Sie dafür das passende Engine. Verwenden Sie den ursprünglich vorbereiteten Input oder wählen Sie die beste Eigenschaft der Kandidaten für diesen Runde aus.

Wählen Sie einen Ausgabepfad aus und erstellen Sie die neue Runde. Überprüfen Sie zuerst die Eingaben und die Konfigurationen, bevor Sie die Runde testen oder einreichen. Die Erstellung der Runde bedeutet nicht, dass der Berechnungsvorgang beginnt.

  3. Lesen Sie den Namen des Posenwerts, den Wert, die Richtung der Rangierung sowie die verfügbaren Qualitätskriterien.
  4. Schauen Sie sich die Ergebnisse an. Öffnen Sie die Einträge der Kandidaten, die Sie vergleichen möchten. Weitere Informationen finden Sie im Kapitel 16.

Kontrolle: Die Zusammenfassung zeigt die Dauer der Lesung. Die Ergebnisse werden nach Aufgaben geordnet und pro Aufgabe können bis zu fünf Ergebnisse angezeigt werden. Fehlende Punktzahlen oder QC-Informationen bleiben unberücksichtigt. Diese sollten nicht als null oder „gut“ betrachtet werden.

Bei Problemen: Wenn keine Ergebnisse vorhanden sind, prüfen Sie, ob die Aktion in der Warteschlange oder aktiv ist. Anschließend können Sie die Protokolle prüfen. Versuchen Sie erneut die Aktion – falls sie fehlschlägt. Die Punktzahlen können nicht zwischen den verschiedenen Maschinen verglichen werden. Zudem stellen die Punktzahlen keine Aussage über die Aktivität oder die Leistung der Maschinen dar.

15.2 MD-Fortschritt, Checkpoints und Analysen prüfen

  1. Filtern Sie die Forschungsergebnisse für das MD-Format aus und öffnen Sie die entsprechende Datei.
  2. In seiner Zusammenfassung sollte der verstrichene Simulationszeitpunkt mit den Zielen, der Leistung, der Anzahl der Schritte sowie dem Zustand der Checkpoints verglichen werden.
  3. Prüfen Sie, ob dieser Versuch von einem Punkt der Übertragung wieder aufgenommen wurde. Identifizieren Sie außerdem die ursprüngliche Version des Versuchs.
  4. Überprüfen Sie die bestehenden Analysen im Zusammenfassung. Verwenden Sie die Desktop-Anwendung, um weitere Analysen durchzuführen.

Kontrolle: Unverfügbare Daten bleiben unberücksichtigt. Das Finden eines Punktes der Kontrolle bedeutet nicht, dass das Handy seine Arbeit wieder aufgenommen hat.

Bei Problemen: Wenn keine Analyse vorgenommen wird, prüfen Sie, ob auf dem Computer lesbare Ausgaben vorhanden sind. Wenn die Ausführung der Anweisungen wieder möglich ist, bestätigen Sie dies und setzen die Ausführung der Anweisungen fort. Die Erreichung eines bestimmten Zeitpunkts oder das Erledigen aller Anweisungen bedeutet noch nicht, dass die Anweisungen erfolgreich ausgeführt wurden.

15.3 Das passende Protokoll auswählen

  1. Offene Fehler und Protokolle aus der Ausführung oder der entsprechenden Karte.
  2. Wählen Sie den „Worker“ für die Ausgabe der Ausführungsdaten oder den „Scheduler“ für die Planung der Arbeitsabläufe.
  3. Aus dem Ergebnis der Docking-Aktion können Sie den „Task-Log“ öffnen, um dieses spezielle Ergebnis zu überprüfen.
  4. Wechseln Sie zu den früheren Protokolldaten oder kehren Sie zum aktuellsten verfügbaren Ausgabe-Text zurück.

Kontrolle: Die Datei zeigt die Lesetime, den Bytebereich sowie die Gesamtgröße an. Überprüfen Sie die Quelle und versuchen Sie es erneut – bevor Sie einen Fehler feststellen.

Bei Problemen: Eine noch nicht vorhandene Log-Eintragung kann später auftauchen. Versuchen Sie es erneut mit der aktuellen Seite. Wenn der Log-Eintrag aus einer historischen Nachricht stammt, prüfen Sie, ob der Eintrag sich von dem aktuellen unterscheidet.

15.4 Protokolle durchsuchen, verfolgen und kopieren

  1. Suchen Sie die aktuelle Seite aus und nutzen Sie die Funktionen zur Suche nach vorherigen und nächsten Einträgen.
  2. Filtern Sie die Wörter, die zu Fehlern führen könnten aus. Schalten Sie den Filter anschließend aus, wenn Sie den vollständigen Kontext benötigen.
  3. Mit einer Live-Verbindung und einem automatischen Intervall kann man die Funktion „Follow-Latest“ aktivieren. Das Suchen, Scrollen nach oben oder das Lesen einer älteren Seite verzögert die Anzeige der Nachrichten. Diese Funktion kann wieder aktiviert werden, sobald die Suche oder das Lesen der Seiten beendet sind.
  4. Verwenden Sie die Funktion „Kopieren der aktuellen Seite“, um diese Seite zu kopieren.

Kontrolle: Trefferzahl und Statusanzeige zeigen den aktuellen Stand. Suche und Filter gelten nur für die offene Seite mit bis zu 16 KiB. Die Zeilennummern beziehen sich auf diese Seite. Das Kopieren der Seite lädt nicht das gesamte Protokoll herunter.

Bei Problemen: Wenn nötig, sollten Sie nach älteren Seiten suchen. Die folgende Information ist nicht verfügbar – oder befindet sich in manueller Modus. Bitte öffnen Sie die aktuelle Seite manuell. Falls die Kopieierung fehlschlägt, drücken Sie lange auf den Text, um ihn auszuwählen. Die Ergebnisse der Suchvorgänge werden mit Hilfe von Schlüsselwörtern und Kontext interpretiert.

16. Notizen, Favoriten und Kandidatenvergleich

16.1 Eine Notiz speichern und einen Lauf markieren

  1. Bitte geben Sie die Details des Laufes ein und wählen Sie „Laufnotizen“.
  2. Die Lieblingsläufe werden immer wieder besucht.
  3. Setzen Sie den Zustand der Forschungsübersicht fest und fassen Sie die beobachteten Ergebnisse, Fragen oder nächsten Schritte zusammen.
  4. Speichern. Kehren Sie zu den Forschungsunterlagen zurück und öffnen Sie die Funktion „Run Notes“, um es zu finden oder zu bearbeiten.

Kontrolle: Die Lieblingsstücke, der Zustand der Bewertungen, Notizen sowie die Zeitpunkte der Bearbeitung werden in der Liste angezeigt. Das Markieren eines Notizpunkts bedeutet nicht, dass die Berechnung abgeschlossen ist. Der Datensatz wird zunächst lokal gespeichert.

Bei Problemen: Sollte ein Fehler auftreten, bleiben Sie im Editor und überprüfen Sie den Speicher. Falls ein Eintrag fehlt, bestätigen Sie die Konten- und Geräteinformationen. Wenn Sie aufgefordert werden, ungespeicherte Änderungen zu löschen, gehen Sie zurück und speichern Sie diese Änderungen, um sie zu bewahren.

16.2 Eine Pose zur Kandidatenliste hinzufügen

  1. Öffnen Sie die Einträge der Kandidaten für eine bestimmte Pose aus dem Zusammenfassung des Docking-Verfahrens.
  2. Überprüfen Sie die Herkunft und die Punktzahl des Produkts. Stellen Sie außerdem einen Status der Bewertung fest und fügen Sie dazu Anmerkungen hinzu.
  3. Speichern Sie und finden Sie den Eintrag in der Liste der Kandidaten unter „Forschungsunterlagen“.
  4. Öffnen Sie den Quellcode oder erweitern Sie die vollständige Herkunft der Daten für weitere Felder.

Kontrolle: Der Kandidat behält die ursprüngliche Form, die Punktzahl sowie die Dauer der Veröffentlichung bei. Bitte bearbeiten Sie die ursprüngliche Aufzeichnung, um den entsprechenden Hinweisen aktuell zu halten.

Bei Problemen: Eine Pose ohne festen Identifikationsnummer kann nicht gespeichert werden. Überprüfen Sie den Ergebnistext auf dem Desktop. Wenn die Quelle nicht verfügbar ist, bleibt der gespeicherte Inhalt weiterhin lesbar, bis Sie erneut eine Verbindung herstellen. Das Löschen eines Forschungsprotokolls bedeutet nicht, dass die ausgewerteten Daten gelöscht werden. Lesen Sie den Bestätigungstext sorgfältig durch, bevor Sie mit der Synchronisierung des Datenverkehrs beginnen.

16.3 Zwei bis vier Einträge vergleichen

  1. Wählen Sie „Run Notes“ oder die Liste der Kandidaten in den Forschungsunterlagen aus.
  2. Mark die beiden bis vier Einträge für den Vergleich oder die Auswahl.
  3. Öffnen Sie den Vergleich der ausgewählten Einträge.
  4. Scrollen Sie horizontal entlang, um die Quellen, Engine, Metriken, Parameter sowie die Anzahl der Lesungen und Anmerkungen zu sehen. Die hervorgehobenen Felder unterscheiden sich von den übrigen.

Kontrolle: Fehlende Werte werden durch einen Strich dargestellt. Ein passendes Kontextfeld ist zwar eine Hinweisquelle, doch es ersetzt nicht die Notwendigkeit, die wissenschaftlichen Bedingungen genau zu überprüfen.

Bei Problemen: Passen Sie Ihre Auswahl an, wenn es weniger als zwei oder mehr als vier Ergebnisse gibt. Sie können die Daten aus verschiedenen Rezepturen, Abläufen oder Zählungskontexten nebeneinander betrachten. Verwenden Sie jedoch keine nicht kompatiblen Ergebnisse für die Rangvergabe. Erneuern Sie außerdem die veralteten Daten aus ihren ursprünglichen Quellen.

16.4 Zusammenfassung exportieren und Empfang prüfen

  1. Exporte die ausgewählten Datensätze oder die aktuelle Liste in „Research Records“. Oder exportieren Sie eine Zusammenfassung aus der Vergleichsdatei.
  2. Wählen Sie Markdown (.md) oder JSON (.json) als Dateiformat aus. Anschließend können Sie den Vorschlag ansehen.
  3. Speichern oder teilen Sie das Dokument auf dem Android- oder iOS-Gerät. Oder laden Sie es direkt aus dem Browser herunter. Anschließend wählen Sie einen Speicherort in der Systemoberfläche aus.
  4. Führen Sie den Text nur dann auf, wenn es nicht notwendig ist. Überprüfen Sie den Inhalt sowie die Herkunft des Textes vor der Weitergabe. Entfernen Sie alles, was Sie nicht offenbaren wollen.

Kontrolle: Öffnen Sie die gespeicherte Datei oder bestätigen Sie die Annahme in der entsprechenden Anwendung. Es werden nur Zusammenfassungen der gespeicherten Daten, Notizen und Informationen über die Herkunft der Daten angezeigt – nicht jedoch die vollständige molekulare Bibliothek, die Datenströme oder die Berechnungsdaten.

Bei Problemen: Das Ablehnen der Funktionen „Speichern“ oder „Teilen“ führt nicht dazu, dass die Quelldatei gelöscht wird. Falls die Exportation fehlschlägt, sollte man den Text erneut versuchen oder die Datei kopieren. Das Öffnen einer „Teilliste“ beweist nicht, dass die Datei tatsächlich übertragen wurde.

17. Seiten offline bereithalten

17.1 Laufübersicht und ausgewählte Seiten speichern

  1. Bitte geben Sie die Details des offenen Datensatzes bei der Verbindung an, und warten Sie darauf, dass die Lesung erfolgreich ist.
  2. Speichern Sie den Zusammenfassungsbericht. Um eine Ergebnis- oder Protokollseite zu speichern, öffnen Sie diese und bewahren Sie die aktuell geladenen Informationen auf.
  3. Bitte laden und speichern Sie jede zusätzliche Seite separat.
  4. Überprüfen Sie die gespeicherten Ergebnisse sowie die Protokolldaten – einschließlich der Daten zu den Zeitschritten, an denen die Daten gelesen oder gespeichert wurden.

Kontrolle: Die Seite berichtet von erfolgreicher Datensicherung. Eine Zusammenfassung laden nicht den gesamten Inhalt der Datei. Neue Online-Readings können eine gespeicherte Kopie ersetzen – daher handelt es sich dabei nicht um eine unveränderliche Sicherungskopie.

Bei Problemen: Wenn die Speicherung deaktiviert ist, warten Sie bis die Seite vollständig geladen ist. Wenn der Speicher voll ist, entfernen Sie die Materialien, die Sie nicht mehr benötigen. Dies wird in Abschnitt 17.3 beschrieben. Eine sichtbare Seite ist keine gespeicherte Kopie, es sei denn, die App bestätigt dies.

17.2 Offline öffnen und fehlende Seiten erkennen

  1. Öffnen Sie die App mit dem ursprünglichen Konto und der ursprünglichen Verbindung. Achten Sie auf das Etikett „Offline-Version“ sowie die ursprüngliche Lesezeit.
  2. In den Einstellungen unter „Offline Records“ können Sie Material aus einer explizit aufbewahrten Runde öffnen.
  3. Erweitern Sie den gespeicherten Ausdruck und die Protokolldatenseiten. Wählen Sie die Seite aus, die Sie benötigen.
  4. Nach der erneuten Verbindung sollten die Aufgaben aktualisiert werden und alle Seiten, die aktualisiert werden müssen, sollten erneut gelesen werden.

Kontrolle: Die Offline-Versionen zeigen die ursprüngliche Lesezeit an. Die normale Lesevorgang speichert aktuelle Inhalte; die explizite Speicherung bewahrt die Zusammenfassungen sowie die ausgewählten Seiten bei.

Bei Problemen: Wählen Sie eine bereits gespeicherte Seite aus – falls keine solche vorhanden ist, müssen Sie die Seite erneut herunterladen. Falls eine Offline-Ausführung fehlt, überprüfen Sie die Konten- und Gerätekonfigurationen. Das Ausloggen oder Entfernen der Verbindung kann dazu führen, dass lokale Kopien gelöscht werden. Eine erneute Verbindung ist jedoch keine Alternative zur Exportierung der Daten.

17.3 Speicher verwalten und Seiten zur Bereinigung freigeben

  1. Öffnen Sie die Einstellungen → Offline Records, um die Nutzung durch Verbindungen, Apps sowie die gespeicherten Inhalte zu verfolgen.
  2. Hören Sie auf, eine ganze Seite oder einzelne Seiten aus der Liste der gespeicherten Seiten zu behalten.
  3. Um alle noch gespeicherten Seiten zu löschen, verwenden Sie die entsprechende Funktion. Stellen Sie außerdem sicher, dass die Nutzung der Seiten korrekt ist.
  4. Löschen Sie die Offline-Daten der aktuellen Verbindung nur dann, wenn Sie sicherstellen können, dass Sie diese nicht mehr benötigen.

Kontrolle: Die App speichert insgesamt bis zu 40 Läufe, 12 Ergebnis- oder Protokollseiten je Lauf und 20 MiB. Fest gespeicherte Kopien zählen mit, werden aber nicht automatisch entfernt. Heben Sie die Aufbewahrung auf, kann der Cache sie wieder bereinigen. Lokales Löschen ändert keine Serverergebnisse.

Bei Problemen: Das Freigeben einer gespeicherten Kopie muss nicht dazu führen, dass der Dienst sofort weniger genutzt wird – schließlich kann diese Kopie weiterhin im Cache verbleiben. Überprüfen Sie außerdem den Speicherplatz des Geräts, falls das Speichern oder Löschen der Daten fehlschlägt. Verlassen Sie den Dienst nicht, um den Speicherplatz zu verwalten.

18. Einen ausstehenden Plan bearbeiten und einreichen

18.1 Desktopprojekt oder gespeicherten Plan öffnen

  1. Speichern Sie das Desktop-Projekt – das Telefon kann die nicht gespeicherten Änderungen am Desktop nicht anzeigen.
  2. Wählen Sie auf dem Computer unter Einstellungen → Berechtigungen für mobile Projekte und Aufgaben die Device.json des gekoppelten Monitoring-Agenten und setzen Sie eine Gültigkeitsdauer. Standardmäßig ist nur das Bearbeiten von Plänen erlaubt. Für einen echten Rechenlauf ist eine separate Freigabe zum Einreichen nötig. Die Freigabe allein startet nichts; bestätigen Sie auf dem Smartphone.
  3. Im Telefonbereich wählen Sie das richtige Gerät aus und aktualisieren die erforderlichen Rechte. Öffnen Sie die Seite „Pläne“ – entweder über „Forschung“ oder über den Ansichtselement für angemeldete Konten.
  4. Öffnen Sie das Desktop-Projekt, um einen neuen Plan zu konfigurieren – oder um einen bereits gespeicherten Plan anzusehen.
  5. Überprüfen Sie den Projektplan, die Anzahl der Hosts, des Engines sowie der Anzahl der Aufgaben, bevor Sie den Text bearbeiten.

Kontrolle: Ein Desktop-Projekt erstellt einen unabhängigen Plan, der noch nicht ausgeführt wird. Nur solche Pläne, die noch nicht ausgeführt werden, können bearbeitet werden – sofern dies erlaubt ist.

Bei Problemen: Speichern Sie das Projekt auf dem Computer und aktualisieren Sie die Pläne, falls diese fehlen. Bei Fehlern bezüglich der Genehmigungen sollten Sie die zugehörigen Informationen auf dem Desktop überprüfen. Auch sollte man die Genehmigungen für die Verwendung des Projekts auf dem Computer überprüfen. Achten Sie auf mögliche unzulässige Konfigurationen des Projekts auf dem Desktop – verwenden Sie solche Konfigurationen nicht als bearbeitbare Informationen.

18.2 Parameter bearbeiten und lokale Entwürfe wiederherstellen

  1. Die Docking-Pläne können Angaben zu den CPU-Threads pro Ligand, den parallelen Liganden, der Ausführungszeit, der maximalen Anzahl der Operationen, der Punktzahl sowie der „Seed“-Wert enthalten. Die Energiebereich (in kcal/mol) sollten nur dann angegeben werden, wenn dies in der Formulierung angegeben wird. Für eine einzelne Box sollten die Mittelwerte sowie die Größe der Box in Ångströmen angegeben werden.
  2. GNINA kann nur die CPU oder, sofern unterstützt, auch eine GPU nutzen. Der angezeigte CNN-Bewertungsmodus ist hier nicht veränderbar. Bearbeiten Sie rezeptorspezifische Suchboxen am Computer.
  3. Die Einstellungen bezüglich der Ressourcen können folgende Werte enthalten: Anzahl der Threads pro Rang, MPI-Ränge, GPUs, Speicherverfügbarkeit (in GiB), Wartezeiten, Partitionierung, Kontoinformationen, Qualitätsstandards, maximale Ausführungszeit (in Stunden) sowie der Ausführungsmodus. Diese Einstellungen ändern die wissenschaftlichen Parameter eines bestehenden TPR nicht.
  4. Stellen Sie sicher, dass die Änderungen lokal gespeichert wurden, aber nicht übermittelt wurden. Falls nötig, öffnen Sie den lokalen Entwurf erneut. Überprüfen Sie die Werte des Entwurfs und aktualisieren Sie die Online-Quelle, bevor Sie den Entwurf vor dem ersten Anzeigen ausprobieren.

Kontrolle: Folgen Sie den angezeigten Einheiten und Bereichen. Die lokale Vorstellung ist nur eine Telefonabfrage – es handelt sich dabei nicht um einen Desktop-Plan. Zudem wurde keine Berechnung durchgeführt. Verwenden Sie die durch Kommas getrennten Werte sowie die Zeitformatvorlage des Formulars.

Bei Problemen: Bitte korrigieren Sie die hervorgehobenen Werte. Falls sich die Desktop-Quelle ändert hat, überprüfen Sie zuerst den alten Entwurf, bevor Sie ihn wegwerfen und die Änderungen an der neuen Quelle vornehmen. Übernehmen Sie nicht die alten Daten des Projekts. Falls die lokale Speicherung fehlschlägt, halten Sie die Seite weiterhin offen und überprüfen Sie den Speicherplatz.

18.3 Änderungen prüfen und den Plan speichern

  1. Schließen Sie die Bearbeitung ab und öffnen Sie die Vorschau der Änderungen.
  2. Vergleichen Sie den Stand vor und nach der Änderung. Prüfen Sie bei einem neuen Plan aus einem Desktopprojekt auch dessen Ressourcenübersicht.
  3. Bestätigen Sie und speichern Sie den Plan als ausstehend.
  4. Prüfen Sie das Speicherergebnis und die Liste der gespeicherten Pläne. Falls die App eine bestätigte Rückmeldung vom Computer anzeigt, prüfen Sie diese ebenfalls.

Kontrolle: Die App berichtet von einem geplanten Plan, bei dem keine Berechnungen vorgenommen wurden. Zudem wird bestätigt, dass es sich um einen eigenständigen Plan handelt – allerdings mit unverändertem Quellprojekt. Das Speichern des Plans führt jedoch zu keiner Ausführung des Plans.

Bei Problemen: Ein bereits vorhandener Plan muss vor der Vorstellung angepasst werden. Ein neuer Plan kann die ursprünglichen Einstellungen beibehalten. Wenn die Quelle oder die Vorlage sich ändert, sollte man die Vorlage erneut aktualisieren. Wenn das Ergebnis der Speicherung unbekannt ist, sollte man die gleiche Aktion wiederholen – anstatt einen neuen Plan zu erstellen.

18.4 Ressourcen prüfen und einen unklaren Auftragsstatus klären

  1. Aktivieren Sie am Computer die zeitlich begrenzte Freigabe zum Einreichen und aktualisieren Sie die Berechtigungen auf dem Telefon. Speichern Sie zuerst lokale Änderungen am Desktop oder verwerfen Sie ausdrücklich einen nicht mehr benötigten Entwurf.
  2. Öffnen Sie den gespeicherten, noch nicht veröffentlichten Plan und überprüfen Sie die Ergebnisse der Präsentation.
  3. Prüfen Sie Host, Programm, Anzahl der Aufgaben und CPU-Parallelität bzw. MD-Threads, Ranks, GPUs, Speicher und Laufzeitlimit der Warteschlange.
  4. Setzen Sie das Bestätigungshäkchen und starten Sie erst dann, wenn der Plan geprüft ist. Dadurch geht ein echter Auftrag an den Rechenhost.
  5. Stellen Sie den Zustand des Plans sicher. Sobald eine verbindete Aktion angezeigt wird, öffnen Sie die Funktionen für den Fortschritt, die Ergebnisse, die Arbeitsprotokolle oder die Protokolle des Planers.

Kontrolle: Die Eingabe wird vor der Anzeige des aktuellen Zustands aufgezeichnet. Die Eingabe und das Warten in der Warteschlange bedeutet noch nicht, dass die Arbeit abgeschlossen ist. Bitte überprüfen Sie den zugehörigen Ausführungsprozess.

Bei Problemen: Ist der Start gesperrt, prüfen Sie Bestätigung, Freigabe und ungespeicherte Änderungen. Stellen Sie nach einer Unterbrechung dieselbe Einreichung wieder her oder aktualisieren Sie den Plan, statt einen neuen zu starten. Rufen Sie mit dem ursprünglichen Konto, Dienst und Host den gespeicherten Beleg ab. Bei einem Speicherfehler stellen Sie den lokalen Speicher wieder her und behalten den ursprünglichen Vorgang bei. Löschen Sie keine Daten, um die Wiederherstellung zu umgehen.
